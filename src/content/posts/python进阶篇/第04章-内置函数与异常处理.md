> 本章内容：掌握 Python 常用内置函数（enumerate、zip、eval、exec 等）及其安全风险，学习异常处理机制增强程序健壮性。（对应课程第 81~94 集）

## 4.1 枚举与拉链

Python 有 60 多个内置函数（Built-in Functions），很多已经学过，如 `print`、`input`、`sum`、`min`、`max`、各种数据类型、`len`、`sorted`、`next`、`range`、`map` 等。本节介绍两个重要的序列处理函数。

### 4.1.1 enumerate（枚举）

**需求**：遍历列表时，同时获取索引和值。

未学 `enumerate` 前只能借助列表的 `index` 方法：

```python
li = ["a", "b", "c", "d"]
for value in li:
    print(li.index(value), value)   # 通过 index 查找索引
# 输出: 0 a / 1 b / 2 c / 3 d
```

**`enumerate(可迭代对象, 起始数字=0)`** 返回一个迭代器，每次产出 `(索引, 值)` 元组，可用解压赋值直接拆开：

```python
li = ["a", "b", "c", "d"]
res = enumerate(li)
print(hasattr(res, "__iter__"), hasattr(res, "__next__"))   # 输出: True True

for index, value in enumerate(li):
    print(index, value)
# 输出: 0 a / 1 b / 2 c / 3 d

for index, value in enumerate(li, 1):    # 第二个参数指定起始数字
    print(index, value)
# 输出: 1 a / 2 b / 3 c / 4 d
```

### 4.1.2 zip（拉链）

**`zip(*可迭代对象)`** 把多个可迭代对象一一配对，返回迭代器，每次产出一个元组，**长度以最短的为准**：

```python
li = ["a", "b", "c", "d"]
nums = [1, 2, 3, 4]
t = ("x", "y", "z")          # 只有 3 个元素

for i in zip(li, nums):
    print(i)
# 输出: ('a', 1) ('b', 2) ('c', 3) ('d', 4)

for i in zip(li, nums, t):   # 长度以最短的为准
    print(i)
# 输出: ('a', 1, 'x') ('b', 2, 'y') ('c', 3, 'z')
```

常见用法：

```python
# 组合字典
keys = ["name", "age"]
values = ["张大仙", 73]
print(dict(zip(keys, values)))   # 输出: {'name': '张大仙', 'age': 73}
```


:::warning[注意]
`enumerate` 和 `zip` 返回的迭代器只能遍历一次：
```python
it = zip(li, nums)
print(list(it))   # 输出: [('a', 1), ('b', 2), ('c', 3), ('d', 4)]
print(list(it))   # 输出: []  已经耗尽
```
Python 3.10+ 中 `zip(..., strict=True)` 会在长度不一致时抛出 `ValueError`，避免数据被悄悄截断。
:::


## 4.2 简单内置函数

快速掌握几个用法简单的内置函数：

**进制转换与字符编码**：

```python
print(bin(10), oct(10), hex(10))   # 输出: 0b1010 0o12 0xa
print(ord("a"), chr(97))           # 输出: 97 a
```

- `bin` / `oct` / `hex`：十进制转二进制 / 八进制 / 十六进制
- `ord` / `chr`：字符与 Unicode 码位互转

**类型判断**：

```python
class Animal:
    pass

class Dog(Animal):
    pass

d = Dog()
print(callable(Dog), callable(d))      # 输出: True False
print(isinstance(d, Animal))           # 输出: True
print(issubclass(Dog, Animal))         # 输出: True
```

- `callable(对象)`：判断对象能否加括号调用
- `isinstance(对象, 类)`：判断对象是否属于某个类（包括父类）
- `issubclass(类1, 类2)`：判断类1是否是类2的子类

**`super`、`property`、`classmethod`、`staticmethod`**：已在面向对象章节学过。

**`hasattr`、`getattr`、`setattr`、`delattr`**：已在反射章节学过。

## 4.3 vars 与 frozenset

### 4.3.1 vars

**`vars(对象)`** 返回对象的属性字典，等同于 `对象.__dict__`；不传参数时等同于 `locals()`：

```python
class Human:
    star = "earth"              # 类属性

    def __init__(self, name, age):
        self.name = name
        self.age = age

obj = Human("张大仙", 73)

print(vars(obj))                        # 输出: {'name': '张大仙', 'age': 73}
print(vars(obj) == obj.__dict__)        # 输出: True
print("star" in vars(obj), "star" in dir(obj))   # 输出: False True
print(vars(Human)["star"])              # 输出: earth
print(vars() == locals())               # 输出: True
```

**`vars` 与 `dir` 的区别**：

- `dir(对象)`：查看对象能"点"出来的所有属性，包括继承的
- `vars(对象)`：只查看对象自己的属性（`__dict__` 里的）

### 4.3.2 frozenset

**`frozenset(可迭代对象)`** 创建不可变集合，没有 `add`、`remove`、`clear` 等修改方法，因此可以作为字典的键或放进另一个集合：

```python
s = {1, 2, 3}
s.remove(1)
print(s)                                         # 输出: {2, 3}

fs = frozenset({1, 2, 3})
print(hasattr(fs, "remove"), hasattr(fs, "update"))   # 输出: False False
print({fs: "ok"}[frozenset({3, 2, 1})])          # 输出: ok  可作为字典的键
```


:::tip[技巧]
其他常用内置函数：`abs` 绝对值、`divmod(a, b)` 返回 `(商, 余数)`、`round` 四舍五入、`all` / `any` 判断全部为真 / 任一为真、`reversed` 反向迭代、`filter` 过滤。全部内置函数可通过 `dir(__builtins__)` 或官方文档 "Built-in Functions" 查看。
:::


## 4.4 __import__ 与动态导入

`import` 关键字后面不能跟字符串。如果模块名是字符串（比如从文件或配置文件读取），就用 **`__import__(模块名字符串)`**，返回模块对象：

```python
name = "time"                # 可能来自配置
time = __import__(name)      # 以字符串方式导入模块
print(time.time())           # 输出: 当前时间戳，如 1700000000.123
```

## 4.5 globals 与 locals

- **`globals()`**：返回全局名称空间的字典，包括我们定义的变量、`__file__`、`__name__`，以及 `__builtins__`（内置名称空间）
- **`locals()`**：返回当前局部名称空间的字典。在全局位置调用时结果与 `globals()` 相同；在函数内调用只返回函数内的变量

```python
b = 3
print("b" in globals(), "__builtins__" in globals())   # 输出: True True

def func():
    a = 1
    print(locals())

func()                       # 输出: {'a': 1}
```

**关键区别**：

```python
g = globals()
g["age"] = 18                # 往 globals() 字典里加值
print(age)                   # 输出: 18   globals() 字典与全局名称空间绑定

def func():
    l = locals()
    l["age2"] = 18           # 往 locals() 字典里加值
    try:
        print(age2)
    except NameError as e:
        print(e)             # 输出: name 'age2' is not defined

func()
```

- **`globals()` 返回的字典与全局名称空间绑定**，修改字典会影响全局变量
- **在函数内，`locals()` 返回的字典没有绑定**，只是一份拷贝

## 4.6 eval 执行表达式

**`eval(表达式字符串, globals=None, locals=None)`** 把字符串作为代码执行，用于**表达式**，返回表达式的结果：

```python
b = 3
res = eval("1 + 2 + b")
print(res)                   # 输出: 6
```

### 4.6.1 控制名称空间

第二个参数 `g` 是全局名称空间，第三个参数 `l` 是局部名称空间：

```python
b = 3
g = {}
l = {}

try:
    eval("1 + 2 + b", g, l)
except NameError as e:
    print(e)                 # 输出: name 'b' is not defined

print(list(g.keys()))        # 输出: ['__builtins__']  空字典里被自动加入内置名称空间

g = {"b": 3}
print(eval("1 + 2 + b", g, l))   # 输出: 6

l = {"b": 4}
print(eval("1 + 2 + b", g, l))   # 输出: 7   局部有 b，优先使用
```

**要点**：

- 传的全局名称空间即使是空字典，也会自动加入 `__builtins__`，能访问所有内置函数
- 不传第二个参数时，默认使用 `globals()`；不传第三个参数时，默认使用 `locals()`
- 这两个参数用来控制代码能访问的变量

### 4.6.2 只能执行表达式

表达式必须有返回值。赋值语句（如 `a = 1`）没有返回值，会报语法错误：

```python
try:
    eval("a = 1 + 2 + 3")
except SyntaxError as e:
    print("SyntaxError:", e)     # 输出: SyntaxError: invalid syntax (<string>, line 1)
```


:::tip[技巧]
如果只是想把字符串转成字面量（列表、字典等），更安全的做法是 **`ast.literal_eval`**；如果是 JSON 格式，用 **`json.loads`**：
```python
import ast
print(ast.literal_eval("[1, 2, {'a': 3}]"))    # 输出: [1, 2, {'a': 3}]
try:
    ast.literal_eval("__import__('os').system('dir')")
except (ValueError, SyntaxError):
    print("拒绝执行")                            # 输出: 拒绝执行
```
:::


## 4.7 exec 执行代码块

**`exec(代码块字符串, globals=None, locals=None)`** 执行字符串形式的代码块，**没有返回值**（永远返回 `None`），产生的变量存入局部名称空间（第三个参数）：

```python
g = {"b": 3}
l = {"b": 4}

res = exec("1 + 2 + b", g, l)
print(res)                   # 输出: None

exec("a = 1 + 2 + b", g, l)  # 赋值语句 exec 可以执行
print(l)                     # 输出: {'b': 4, 'a': 7}

l = {}
exec("a = 1 + 2 + b", g, l)  # 局部没有 b，用全局的 b=3
print(l)                     # 输出: {'a': 6}
```

### 4.7.1 在函数内使用 exec

不传名称空间参数时，默认使用 `globals()` 和 `locals()`。在全局位置，`locals()` 就是 `globals()`，所以全局可以直接访问：

```python
b = 3
exec("a = 1 + 2 + b")
print(a)                     # 输出: 6
```

但在函数内不传参数时访问不到：

```python
def func():
    g = {"b": 3}
    l = {}
    exec("a = 1 + 2 + b", g, l)
    print(l["a"])            # 输出: 6  通过 l 字典访问

func()
```

原因前面已讲：在函数内，`locals()` 返回的字典没有绑定，`exec` 产生的变量存到了拷贝字典中，直接访问变量名访问不到。

| | `eval` | `exec` |
|---|---|---|
| 执行内容 | 表达式（必须有返回值） | 代码块（可以有赋值等语句） |
| 返回值 | 表达式的结果 | 永远 `None` |
| 产生的名字 | — | 存入局部名称空间（第三个参数） |


:::note[补充]
`exec` 正是第 09 章模拟 `class` 关键字时，用来"执行类体代码得到名称空间"的工具。
:::


## 4.8 安全风险与防范

`eval` 和 `exec` 经常被黑客利用，成为**执行系统级命令的入口**进而实施攻击。

### 4.8.1 危险案例

有人把 `input` 套在 `eval` 里，用户输入什么类型就得到什么类型：

```python
res = eval(input(">>> "))
# 输入 123        -> 123 <class 'int'>
# 输入 [1, 2, 3]  -> [1, 2, 3] <class 'list'>
```

看起来很好用，但攻击者可以这样输入：

```text
__import__('os').system('dir')
```

- `__import__('os')` 导入 `os` 模块，`os.system` 可以执行系统命令
- `dir` 查看当前路径下所有内容（Linux 下用 `ls`），当前路径下的所有文件和文件夹都暴露了
- 读取文件：`open('settings.py', 'rt', encoding='utf-8').read()`，重要文件的内容就被拿到了
- **删除文件**：`__import__('os').system('del settings.py /q')`（`/q` 表示不做二次确认）；在 Linux 下执行 `rm -rf /` 甚至会删除系统里所有文件

**水能载舟，亦能覆舟**。

### 4.8.2 防范措施

如果确实要用 `eval` 执行 `input` 输入的内容，可以控制全局名称空间，把 `__builtins__` 改成 `None`：

```python
g = {"__builtins__": None}       # 禁用内置名称空间

print(eval("[1, 2, 3]", g))      # 输出: [1, 2, 3]  普通数据仍可解析

try:
    eval("__import__('os').system('dir')", g)
except TypeError as e:
    print("TypeError:", e)       # 输出: TypeError: 'NoneType' object is not subscriptable
```

访问不到任何内置函数（`print`、`open`、`__import__` 等），安全多了。


:::warning[注意]
清空 `__builtins__` 只能挡住直接调用内置函数，仍可能通过 `().__class__.__base__.__subclasses__()` 等方式绕过，并非真正的沙箱。**永远不要对不可信输入直接使用 `eval` / `exec`**。只需把字符串转成字面量时，应使用 `ast.literal_eval`；交换数据用 `json.loads`。
:::


## 4.9 异常的基本概念

**异常（Exception）是程序发生错误的信号**。程序一旦出错就会抛出异常，然后**立即终止运行**：

```python
print(11)
l = [1, 2, 3]
l[6]            # IndexError: list index out of range，程序在这里终止
print(22)       # 不会执行
# 输出: 11  然后打印报错信息
```

但实际程序不能轻易崩溃——用微信时不可能用着用着就报错退出。为增强程序的**健壮性**，就要在程序抛出异常时对异常进行**捕捉并处理**。

### 4.9.1 异常的三部分

异常由三部分组成：

```text
Traceback (most recent call last):
  File "demo.py", line 7, in <module>
    print(name)
NameError: name 'name' is not defined
```

1. **Traceback**：异常的追踪信息，定位到哪个文件、哪一行抛的异常
2. **异常类型**：如 `NameError`、`IndexError`、`KeyError` 等
3. **异常信息**：冒号后面的提示信息

### 4.9.2 语法错误与逻辑错误

异常总的来说分两大类：

**语法错误（Syntax Error）**：对于语法错误，我们没办法做任何处理，必须在程序运行之前就把代码改正。语法错误是不允许存在的，一般是初学者才会犯的错误。我们真正要处理的是**逻辑错误**。

```python
# 语法错误示例
try:
    compile("if 1 > 2\n    print('hello')", "<demo>", "exec")   # 缺少冒号
except SyntaxError as e:
    print("语法错误:", e.msg)    # 输出: 语法错误: expected ':'
```


:::note[补充]
语法错误在解释器检查语法阶段就被发现，一行代码都不会执行，所以无法用 `try` 处理同一文件中的语法错误。Python 3.10+ 错误提示大幅改进，如直接提示 `expected ':'`、`'(' was never closed`。缩进错误 `IndentationError` 也是 `SyntaxError` 的子类。
:::


**逻辑错误**：只要不是语法错误，其他的都叫逻辑错误。逻辑错误是允许出现的——程序复杂到一定程度时，逻辑不可能一次做到十全十美。

常见的逻辑错误类型：

```python
# TypeError: 'NoneType' object is not iterable
for i in None:
    pass

# NameError: name 'name' is not defined
print(name)

# IndexError: list index out of range
[1, 2, 3][6]

# KeyError: 'age'
{"name": "张大仙"}["age"]

# ValueError: invalid literal for int() with base 10: 'abc'
int("abc")

# AttributeError: type object 'Test' has no attribute 'xxx'
class Test:
    pass
Test.xxx

# TypeError: object of type 'type' has no len()
len(Test)
```

看到异常类型就能立刻判断问题：看到 `KeyError` 就知道一定是字典取了不存在的 key；`len(Test)` 报 `TypeError: object of type 'type' has no len()`，说明 `type` 的对象没有 `len`，而 `Test` 正是 `type` 的对象。


:::note[补充]
还有一种逻辑错误是程序不报错但结果不对（如把 `+` 写成 `-`），这类 bug 只能靠测试和调试发现。所有异常都是类，大部分继承自 `Exception`，顶层是 `BaseException`。
:::


## 4.10 异常处理：可预知与不可预知

逻辑错误又分两类：**错误发生的条件可预知**，和**错误发生的条件不可预知**。

### 4.10.1 可预知的错误用 if 规避

写一个猜数字程序，让用户输入数字：

```python
while True:
    num = input("请输入数字: ")
    num = int(num)            # 用户输入 abc 就会报 ValueError
    if num > 666:
        print("猜大了")
    elif num < 666:
        print("猜小了")
    else:
        print("猜对了")
        break
```

用户输入 `abc`，代码就会出现逻辑错误。这个错误发生的条件是**可以预知**的——输入的内容必须是数字，不是数字就会报错。对于可预知的错误，用**逻辑判断**规避：

```python
while True:
    num = input("请输入数字: ")
    if not num.isdigit():     # 可预知的错误：提前用 if 判断规避
        print("必须是数字")
        continue
    num = int(num)
    if num > 666:
        print("猜大了")
    elif num < 666:
        print("猜小了")
    else:
        print("猜对了")
        break
```

### 4.10.2 不可预知的错误用 try 处理

后面学到套接字（socket）时会遇到不可预知的错误。比如服务端和客户端基于网络通信，通信前要建立双向连接。假设服务端发数据的过程中连接被中断了（客户端软件被关掉、停电或断网），服务端发到一半发现"桥塌了"，直接就崩溃了。站在服务端角度，无法判断客户端什么时候会断开，也没办法控制，用 `if` 写不出这个判断条件——这就是**错误发生的条件不可预知**。

**基本语法**：

```python
try:
    子代码块            # 可能会抛出异常的代码
except 异常类型 as e:
    子代码块            # 捕捉到该类型的异常后执行
```

- `except` 后面跟异常类型，一旦捕捉到这个类型，就执行它下面的子代码块
- `as e` 中的 `e` 拿到的是异常的提示信息，可以打印或记录到日志文件

```python
try:
    num = int("abc")
except ValueError as e:
    print("出错了:", e)     # 输出: 出错了: invalid literal for int() with base 10: 'abc'
```


:::warning[注意]
**`try...except` 能不用就尽量不用**，只在错误发生的条件**不可预知**时才用；可预知时，虽然 `try` 也能解决，但能用判断解决就最好不要用 `try`。`try` 会降低代码可读性。
:::


## 4.11 try 的完整语法

```python
try:
    子代码块1
    子代码块2
    子代码块3
    子代码块4
except 异常类型1 as e:
    ...
except 异常类型2 as e:
    ...
except Exception as e:     # 万能异常，可以捕捉所有异常
    ...
else:
    ...                    # try 的子代码块没有异常时执行
finally:
    ...                    # 无论前面有没有发生异常，最后都会执行
```

- 可以跟很多个 `except`；不需要错误信息时，`as e` 可以不写
- `else`：被检测的代码（`try` 下的子代码块）**没有异常**时执行
- `finally`：**不管有没有发生异常**，最后都会执行

### 4.11.1 执行流程

1. 先执行 `try` 下的子代码块。如果执行到子代码块 3 出现异常，后面的 4 就不再执行，直接进入异常捕捉环节
2. 先判断异常是不是异常类型 1：是，就执行它的子代码块，后面的 `except` 都不再执行，`else` 也不执行，但 `finally` 无论如何都会执行；不是，就进入下一个 `except` 判断
3. 如果所有 `except` 都走完仍没有对应的异常，程序还是会立马报错崩溃。为防止这种情况，可以最后写一个 `except Exception as e`，它能捕捉所有异常
4. 如果 1~4 都正常执行没有异常，就直接跳到 `else` 执行，最后执行 `finally`
5. `try` 整体执行完后，接着执行后续代码。只要异常被捕捉到，就不会影响后续代码

**注意**：子代码块 3 报错后，4 就不会执行。如果 4 做的是**回收系统资源**，不执行就麻烦了。所以应该把回收系统资源的代码放到 `finally` 下面，保证资源一定会被回收。

```python
def demo(n):
    try:
        print("子代码块1")
        if n == 1:
            int("abc")                    # 抛 ValueError
        elif n == 2:
            {"name": "张大仙"}["age"]      # 抛 KeyError
        print("子代码块4")
    except ValueError as e:
        print("捕捉到 ValueError:", e)
    except Exception as e:
        print("万能异常捕捉到:", type(e).__name__, e)
    else:
        print("没有异常")
    finally:
        print("finally 都会执行")
    print("后续代码")

demo(0)
# 输出: 子代码块1 / 子代码块4 / 没有异常 / finally 都会执行 / 后续代码
demo(1)
# 输出: 子代码块1 / 捕捉到 ValueError: ... / finally 都会执行 / 后续代码
demo(2)
# 输出: 子代码块1 / 万能异常捕捉到: KeyError 'age' / finally 都会执行 / 后续代码
```

**合法的组合**：

- `try` + `except`
- `try` + 多个 `except`
- `try` + `finally`（没有 `except` 也行）
- **`try` 不能单独和 `else` 连用**
- 全都要用时，顺序是 `try` → `except` → `else` → `finally`

### 4.11.2 捕捉多个异常

如果**多种异常的处理代码一样**，就没必要写多个 `except`，把它们放在一个**元组**里：

```python
try:
    d = {"name": "张大仙"}
    d["age"]                          # KeyError
except (ValueError, NameError) as e:  # 处理方式相同的异常写进元组
    print(e)
except KeyError as e:
    print("key不存在", e)             # 输出: key不存在 'age'
```

### 4.11.3 万能异常

**`Exception`** 可以捕捉任意错误类型：

```python
def run(n):
    try:
        if n == 0:
            int("abc")               # ValueError
        elif n == 1:
            print(name)              # NameError
        else:
            {"name": "张大仙"}["age"]  # KeyError
    except Exception as e:           # 不管抛什么异常都能捕捉到
        print("捕捉任意错误类型", type(e).__name__, e)

for n in range(3):
    run(n)
# 输出:
# 捕捉任意错误类型 ValueError invalid literal for int() with base 10: 'abc'
# 捕捉任意错误类型 NameError name 'name' is not defined
# 捕捉任意错误类型 KeyError 'age'
```

不需要 `e` 的话，甚至可以连 `Exception as e` 都不写，直接 `except:`，同样能捕捉任何异常。


:::warning[注意]
不要滥用万能异常把所有错误"吞掉"（如 `except Exception: pass`），这会让 bug 难以排查；能明确的异常写具体类型，万能异常放在最后兜底并记录日志。另外，`KeyboardInterrupt`（Ctrl+C）和 `SystemExit` 直接继承自 `BaseException`，`except Exception` 不会捕获它们；而裸 `except:` 会连它们一起捕获，因此更推荐写 `except Exception`。
:::


## 4.12 else 与 finally

### 4.12.1 else

**`else`** 在没有异常的条件下执行，前面必须搭配 `except`：

```python
try:
    print(1)
except Exception as e:
    print(e)
else:
    print("没有异常")
finally:
    print("都会执行")
# 输出: 1 / 没有异常 / 都会执行
```

### 4.12.2 finally

**`finally`** 无论有没有异常都会执行。`try` 可以单独和 `finally` 连用，但要注意：`finally` 不处理异常。

```python
print("开始")
try:
    int("abc")
finally:
    print("都会执行")
print("结束")
# 输出:
# 开始
# 都会执行
# 然后报错: ValueError: invalid literal for int() with base 10: 'abc'
# "结束" 不会打印
```

程序执行到出错的那一行，`try` 下后续代码不再执行，但有了 `finally`，Python 会**先把 `finally` 下的代码执行完，然后再报错**，后续代码不会执行。

**`finally` 下面一般写回收系统资源的代码**：在 `try` 里用到的系统资源，回收代码一定要写在 `finally` 下，因为它无论如何都会执行，即便报错也会先执行完它再报错。网上有人把 `finally` 下的代码形象地比喻成"**生前遗书**"。


:::tip[技巧]
打开文件更推荐 `with open(...) as f:`，它内部相当于帮你做了 `finally: f.close()`：
```python
f = open("demo.txt", "w", encoding="utf-8")
try:
    f.write("hello")
finally:
    f.close()            # 无论 write 是否出错，文件都会被关闭
```
:::


## 4.13 实战预览：教务管理系统

面向对象讲完之后趁热打铁，基于面向对象的知识开发一个实际项目——**教务管理系统**。项目除了面向对象，还会用到 **GUI 编程**（Graphical User Interface，图形用户界面）：用户以图形界面的方式与程序交互，像平时用的软件一样用鼠标点击选择各种功能，从此不再只用命令行与用户交互。

软件以安装包形式提供，需要实现的功能如下：

**登录界面**：可选择**学生、老师、管理员**三种角色登录，还可以注册学生用户。

**管理员**：

- 首页关键指标：付费人次、今日营收、累计营收、累计注册学员、课程数量、老师人数
- 学校：点击学校名出现下拉框，可切换学校或添加学校
- 学员管理：查看所有学员信息，冻结 / 取消冻结学员，筛选买了课的学员，按名字查询
- 课程管理：当前学校的所有课程，可创建课程、编辑课程（编辑时可选择授课老师）
- 老师管理：添加、编辑老师，编辑时可选择是否冻结老师账号
- 财务中心：查看流水（所有支出和收入），给老师发工资，每发一次工资流水中就多一条记录
- 设置：设置欢迎语和虚拟学习人数

**老师**：

- 首页热销课程数据（包含管理员设置的虚拟人数）
- 查看课程：当前学校中该老师能教授的课程，可给买了课的学员排班、管理学员
- 设置：设置联系方式

**学生**：选择学校、购买课程、联系老师。


:::note[补充]
项目的完整开发在后续课程中进行。下面是一个不含界面的简化模型，演示如何用本册知识（继承抽取公共父类、组合关联对象、`__str__`、`raise` 与 `try/except`）表达学校、课程、老师、学生之间的关系：

```python
class People:
    """老师和学生的公共父类"""
    def __init__(self, name):
        self.name = name

class Course:
    def __init__(self, name, price, teacher=None):
        self.name = name
        self.price = price
        self.teacher = teacher        # 组合：课程关联授课老师

    def __str__(self):
        return f"<课程 {self.name} 价格:{self.price}>"

class School:
    def __init__(self, name):
        self.name = name
        self.courses = []             # 组合：学校"有"多门课程

    def add_course(self, course):
        self.courses.append(course)

class Teacher(People):
    pass

class Student(People):
    def __init__(self, name):
        super().__init__(name)
        self.courses = []

    def buy_course(self, school, course):
        if course not in school.courses:
            raise ValueError(f"{school.name} 没有开设 {course.name}")
        self.courses.append(course)
        print(f"{self.name} 购买了 {course.name}，授课老师: {course.teacher.name}")

school = School("南翔技校")
t = Teacher("张大仙")
dig = Course("挖掘机", 9800, t)
school.add_course(dig)
print(dig)                                 # 输出: <课程 挖掘机 价格:9800>

stu = Student("小明")
stu.buy_course(school, dig)                # 输出: 小明 购买了 挖掘机，授课老师: 张大仙
try:
    stu.buy_course(school, Course("烹饪", 6800))
except ValueError as e:
    print("购买失败:", e)                   # 输出: 购买失败: 南翔技校 没有开设 烹饪
```
:::


## 本章小结

- Python 有 60 多个内置函数，`enumerate` 同时拿到索引和值，`zip` 把多个可迭代对象一一配对、以最短为准，二者都返回迭代器
- `bin`/`oct`/`hex` 进制转换，`ord`/`chr` 字符与码位互转，`callable`/`isinstance`/`issubclass` 类型判断
- `__import__` 以字符串导入模块；`globals()` 是全局名称空间（与全局绑定），`locals()` 是当前局部名称空间（函数内只是拷贝）
- `eval` 执行表达式并返回结果，表达式必须有返回值；可通过全局、局部名称空间参数控制可访问的名字
- `exec` 执行代码块，无返回值，产生的名字存入局部名称空间；在函数内不传参数时访问不到产生的名字
- **`eval`/`exec` 可被利用执行系统命令（读文件、删文件），必须谨慎**；可将 `__builtins__` 置为 `None` 限制，更稳妥的是 `ast.literal_eval`
- `vars` 等同于 `__dict__`（不传参等同 `locals()`），`frozenset` 是不可变集合
- 异常是程序发生错误的信号，未处理时程序立即终止；异常由追踪信息、异常类型、提示信息三部分组成
- 语法错误必须在运行前改正；除此之外的都是逻辑错误（`TypeError`、`NameError`、`IndexError`、`KeyError`、`ValueError`、`AttributeError` 等）
- **错误条件可预知用 `if` 规避；不可预知（如网络连接中断）才用 `try`**。`try` 会降低可读性，能不用就不用
- 执行流程：`try` 出错后其后续代码不执行，`except` 自上而下匹配；都不匹配仍会崩溃；处理方式相同的异常可写成元组；`Exception` 是万能异常
- `else` 在无异常时执行，不能脱离 `except` 单独与 `try` 连用；`finally` 无论如何都执行（即使未捕获也先执行再报错），用于回收系统资源
- 实战项目：带 GUI 的教务管理系统，分学生、老师、管理员三种角色
