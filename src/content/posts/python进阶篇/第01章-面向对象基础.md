## 1.1 面向对象思想

### 1.1.1 什么是对象

面向对象是一种**编程思想**。在此之前我们用的都是**面向过程**的思想：第一步做什么、第二步做什么、第三步做什么，核心是把程序**流程化**。

**对象其实就是容器。** 程序里能存进容器的东西有两类：

- **变量**：不管什么类型，说到底就是**数据**
- **函数**：就是**功能**

从学编程第一天到现在，代码都在做两件事：把数据存起来，围绕这些数据写一堆功能。所以**程序就是由数据和功能组成的**；而对象就是用来存放数据和功能的，可以把**对象看作数据和功能的集合体**。

```python
# 字典就是一种容器：既能存数据（变量），也能存功能（函数）
def say_hi():
    print("hi")

box = {
    "name": "容器",     # 数据
    "say_hi": say_hi,   # 功能（存的是函数的内存地址，不加括号）
}
print(box["name"])
box["say_hi"]()
# 输出:
# 容器
# hi
```

**用面向对象的思想编程不一定比面向过程好**，二者没有高低之分，只是应用场景不同。


:::note[补充]
面向过程适合流程固定、扩展性要求低的程序（如一次性脚本）；面向对象适合需求经常变化、需要良好扩展性的程序（如游戏、业务系统）。对象内部的功能本身依然是"过程式"的代码。
:::


### 1.1.2 为什么需要对象

假设要写"王者荣耀"的程序：游戏里有英雄的数据和英雄功能，还有玩家的数据和玩家功能。

**还没学函数时的写法**：

```python
# ---- 英雄的数据 ----
hero_name = "鲁班七号"
hero_speed = 450      # 移速
hero_hp = 3000        # 生命值
hero_atk = 100        # 攻击力

# ---- 英雄的功能（不用函数）----
print(f"英雄属性：名字：{hero_name} 移速：{hero_speed} 生命值：{hero_hp} 攻击力：{hero_atk}")
hero_speed += 60      # 增加移速：比如游戏中买了一双鞋

# ---- 玩家的数据 ----
user_name = "张大仙"
user_gender = "male"
user_team = "XYG"
user_rank = "荣耀王者"

# ---- 玩家的功能（不用函数）----
print(f"玩家属性：名字：{user_name} 性别：{user_gender} 战队：{user_team} 段位：{user_rank}")
user_name = "月下无限连"
```

所有代码都堆在一起，不好管理。学了函数后可以用函数整理功能：

```python
hero_name = "鲁班七号"
hero_speed = 450
hero_hp = 3000
hero_atk = 100

def get_hero_info():
    print(f"英雄属性：名字：{hero_name} 移速：{hero_speed} 生命值：{hero_hp} 攻击力：{hero_atk}")

def set_hero_speed():
    global hero_speed   # 局部中修改全局变量需要 global 声明
    hero_speed += 60

user_name = "张大仙"
user_gender = "male"
user_team = "XYG"
user_rank = "荣耀王者"

def get_user_info():
    print(f"玩家属性：名字：{user_name} 性别：{user_gender} 战队：{user_team} 段位：{user_rank}")

def set_user_name():
    global user_name
    user_name = "月下无限连"

set_hero_speed()
get_hero_info()
set_user_name()
get_user_info()
# 输出:
# 英雄属性：名字：鲁班七号 移速：510 生命值：3000 攻击力：100
# 玩家属性：名字：月下无限连 性别：male 战队：XYG 段位：荣耀王者
```

这样改完，程序结构比原来清晰多了。但问题在于：

- 英雄的两个功能只操作英雄那块数据，玩家的两个功能只操作玩家那块数据——**某些数据和某些功能之间是有关联的**
- 现在却把所有数据和功能都写在一起，显得很乱

**解决思路：整合 → 解耦合**

把相关的数据和功能装到同一个容器里：

- **英雄的容器**：英雄的数据 + 英雄的功能
- **玩家的容器**：玩家的数据 + 玩家的功能

这样程序对外暴露的只有"英雄的容器"和"玩家的容器"，更加清晰。整合的另一个好处是**解耦合**：英雄数据和玩家数据并没有隔开，都堆在一起，这就叫**耦合**到一起了。耦合的程序代码看起来很乱，维护、升级迭代都很麻烦。把不同的数据和功能放到不同的容器后就**解开了耦合**。

**生活中的例子**：假设家里的床坏了要修，需要钉子、螺丝、油漆等材料（数据），还需要锤子、电钻、刷子等工具（功能）。又比如裤子崩开了要缝，需要线、拉链等材料，以及针、剪刀、顶针等工具。

如果不按相关性整理，所有东西混在一起，用的时候很麻烦。生活中的解决办法是两个容器：

- **针线包**：所有缝衣服相关的材料和工具都放在里面
- **工具箱**：所有修理相关的材料和工具都放在里面

遇到缝衣服就拿出针线包，遇到修家具就拿出工具箱，要什么有什么。写代码也一样：把相关的数据和功能放进同一个容器，有需求时直接拿出这个容器，**要数据有数据，要功能有功能**。这就是整合的好处，也是面向对象的核心思想。

### 1.1.3 手工造对象：模块与字典

**用什么方式把相关联的数据和功能整合到一起**？只要能把数据和功能整合到一起，造出来的东西就可以称为对象。

**方案一：用模块**

把英雄的数据和功能剪切出来，新建一个 `hero.py` 文件放进去。这个模块就是一个存放数据和功能的容器，所以**这个模块就可以称为对象**。

```python
# hero.py —— 一个模块就是一个对象：里面有数据也有功能
hero_name = "鲁班七号"
hero_speed = 450
hero_hp = 3000
hero_atk = 100

def get_hero_info():
    print(f"英雄属性：名字：{hero_name} 移速：{hero_speed} 生命值：{hero_hp} 攻击力：{hero_atk}")

def set_hero_speed():
    global hero_speed
    hero_speed += 60
```

```python
# main.py —— 使用时导入这个"英雄对象"
import hero

hero.set_hero_speed()
hero.get_hero_info()
# 输出: 英雄属性：名字：鲁班七号 移速：510 生命值：3000 攻击力：100
```

**对象的本质就是存放数据和功能的容器**：只要造出来的东西能存放数据和功能，它就能称为对象。用这种方式写程序，就是在用面向对象的思想写程序。面向对象是一种**编程思想**，而不是某一种具体技术。

不过实际中，如果每涉及一类数据和功能就新建一个文件，项目里的文件会非常多，所以**用文件整合并不是最好的方式**。

**方案二：用字典**

还有什么容器能把数据和功能整合到一起？基本数据类型里的列表、字典、元组都是容器类型。**字典的 key 有提示作用**，更好用。

```python
def get_hero_info(hero_obj):
    """拿到整个对象，要什么数据自己取"""
    print(f"英雄属性：名字：{hero_obj['hero_name']} 移速：{hero_obj['hero_speed']} "
          f"生命值：{hero_obj['hero_hp']} 攻击力：{hero_obj['hero_atk']}")

def set_hero_speed(hero_obj, speed):
    """修改移速：不需要 global，直接改容器里的数据"""
    hero_obj["hero_speed"] = speed

hero_obj = {
    "hero_name": "鲁班七号",
    "hero_speed": 450,
    "hero_hp": 3000,
    "hero_atk": 100,
    "get_hero_info": get_hero_info,   # 存函数名，即函数的内存地址
    "set_hero_speed": set_hero_speed,
}

hero_obj["set_hero_speed"](hero_obj, 510)
hero_obj["get_hero_info"](hero_obj)
# 输出: 英雄属性：名字：鲁班七号 移速：510 生命值：3000 攻击力：100
```

经过这样整合，整个程序被组织成一个个容器，清晰度、整洁度和扩展性都比原来好得多。

**还存在的瑕疵**：

- 这两个函数仍然**暴露在外面**。最理想的对象是功能也不露在外面，而是直接定义、存放在容器里面，整个容器完全独立
- 字典能造出对象，但造得不够好，所以需要另寻他法

Python 提供了一种新语法，能很方便地把数据和功能整合到一起。Go、C 等语言没有 `class` 语法，但同样可以用面向对象的思想写程序（如 Go 用结构体 + 方法、C 用结构体 + 函数指针），只是 Python 提供了更方便的语法支持。只要懂了"**整合**"这两个字，就懂了面向对象的思想，学其他语言时也通用。不过在学这种语法之前，还需要先了解一个概念——**类（class）**。


:::note[补充]
Python 中通过类创建的对象，底层也是用字典存属性的——每个对象都有一个 `__dict__` 字典。
:::


## 1.2 类与对象

### 1.2.1 类的概念

对象是存放数据和功能的容器，那**类**是什么？从字面理解，就是**种类、分类**的意思。

回到上一节用字典造的英雄对象，再造一个"后羿"：

```python
def get_hero_info(hero_obj):
    print(hero_obj["hero_name"], hero_obj["hero_speed"])

hero1_obj = {
    "hero_work": "射手",          # 职业
    "hero_name": "鲁班七号",
    "hero_speed": 450,
    "hero_hp": 3000,
    "hero_atk": 100,
    "get_hero_info": get_hero_info,
}
hero2_obj = {
    "hero_work": "射手",
    "hero_name": "后羿",
    "hero_speed": 460,
    "hero_hp": 3100,
    "hero_atk": 110,
    "get_hero_info": get_hero_info,
}
print(hero1_obj.keys() == hero2_obj.keys())   # 两个对象的 key（属性）完全一样
# 输出: True
```

观察这两个英雄对象：

- 它们所有的 key 都一样——把 key 换个词描述，叫**属性**。**属性一样的对象就可以归为一类**。玩家的属性和英雄不同，所以玩家和英雄不属于同一类。这是"分类"的含义
- 它们只有名字、移速、生命值、攻击力不同，职业和功能完全相同。每个对象都把相同的内容存一份，**太浪费计算机资源**了，按理只应单独存各自不同的部分

所以类有两方面作用：

1. 给对象做区分、做归类
2. 解决不同对象重复存储相同数据的问题

Python 为此提供了造类的语法，**类就是专门用来存放同类对象所共有的数据和功能的**。因此不仅对象是容器，**类也是容器**。也有人反过来说"类也是对象"：类同样存放数据和功能，这么说没有问题。

**面向对象最终用的是对象，而不是类。**

类里存放共有的职业和功能，每个对象里只存各自的名字、移速、生命值、攻击力。关于类与对象的关系，有两点要注意：

- 提取到类里的共有数据，**本质上仍属于各个对象自己**。这样做只是为了分类和节省空间，并不是把对象私有的数据变成了公有的。通过对象依然能找到它的职业
- 现在涉及两个空间：**对象自己的空间**和**类的空间**。通过对象找职业时，一定是**先找对象自己独有的数据，自己没有，再顺着关联去对应的类里找**


:::note[补充]
在 Python 3 中，类和类型（type）是同一个概念，`int`、`str`、`list` 本质上都是类。
:::


### 1.2.2 类的定义

讲解时我们是先讲对象、再对对象分类引出类；但**用具体语法写程序时顺序是反过来的**：一定要**先定义类**（先想好对象共有的数据和功能，用语法定义出来），**再调用类产生对象**。

第一步：把两个英雄对象共有的数据和功能提取出来——职业都是射手，原来放在字典里，现在拿出来写成**变量**；两个功能也是共有的，同样提取出来。

第二步：用 `class` 语法定义一个容器把它们存起来：

```python
class Hero:
    hero_work = "射手"             # 共有的数据：变量

    def get_hero_info(hero_obj):   # 共有的功能：函数（函数体暂沿用字典写法）
        print(f"英雄属性：名字：{hero_obj['hero_name']} 移速：{hero_obj['hero_speed']}")

    def set_hero_speed(hero_obj, speed_plus):
        hero_obj["hero_speed"] += speed_plus

    print("类体代码执行了")         # 类体中其实可以写任意代码

# 没有调用 Hero，直接运行也会打印
# 输出: 类体代码执行了
```

要点：

1. **类名命名规范：驼峰体**，每个单词首字母大写，如 `Hero`、`HeroInfo`。这和变量不同——变量名全小写，多个单词用下划线连接。类名后面跟冒号
2. 类的作用是存放对象共有的数据和功能，所以类里**应该只定义变量和函数**；但语法上类里可以写任意代码，比如 `print`
3. 类的定义方式很像函数：都以关键字开头（`def` / `class`），都有名字（函数名 / 类名），后面都有冒号和子代码；区别是类名后面没有括号
4. **最大的不同：函数要"函数名加括号"调用，子代码才执行；而类的子代码在定义阶段就直接运行了**

既然类体代码运行了，就会产生 `hero_work`、`get_hero_info`、`set_hero_speed` 三个名字；只要涉及名字，就会产生名称空间来存放——这就是**类的名称空间**。所以**类的名称空间在定义阶段就产生了**。


:::warning[注意]
"类体代码在定义阶段执行"是 Python 的特点，其他语言不一定如此。别和函数混淆：函数体在调用时才执行。
:::


### 1.2.3 类的属性访问

定义不是关键，关键是定义完怎么用、怎么拿到类里的名字。类里存的数据和功能主要是给对象用的，但类本身也是容器，通过类当然也能访问。

**方式一：`类名.__dict__`**，得到一个字典，里面就是类名称空间中的名字。其中以双下划线开头的是 Python 自动添加的，暂时不用管。

```python
class Hero:
    hero_work = "射手"

    def get_hero_info(hero_obj):
        print("查看英雄信息")

    def set_hero_speed(hero_obj, speed_plus):
        pass

print(Hero.__dict__)                    # 类名称空间里的名字
print(Hero.__dict__["hero_work"])       # 通过字典的 key 取数据
print(Hero.__dict__["get_hero_info"])   # 取到函数的内存地址
Hero.__dict__["get_hero_info"](None)    # 加括号即可调用
# 输出:
# {'__module__': '__main__', 'hero_work': '射手', 'get_hero_info': <function ...>, ...}
# 射手
# <function Hero.get_hero_info at 0x...>
# 查看英雄信息
```

**方式二：点语法**。用 `__dict__` 再按 key 取值太麻烦，Python 提供了更简单的取值语法 `类名.属性名`。它只是为了方便使用，**本质还是通过字典取值**。

```python
class Hero:
    hero_work = "射手"

    def get_hero_info(hero_obj):
        print("查看英雄信息")

print(Hero.hero_work)          # 等价于 Hero.__dict__["hero_work"]
print(Hero.get_hero_info)      # 点函数名拿到函数
Hero.get_hero_info(None)       # 加括号调用
# 输出:
# 射手
# <function Hero.get_hero_info at 0x...>
# 查看英雄信息
```

这种访问类里数据和功能的方式叫**属性访问**。类的属性分为两种：

- **数据属性**：类里定义的变量
- **函数属性**：类里定义的函数


:::warning[注意]
`Hero.__dict__` 返回的是只读的 `mappingproxy`，不能通过 `Hero.__dict__["x"] = 1` 修改类属性，要用点语法（如 `Hero.x = 1`）。而对象的 `__dict__` 是普通字典，可以直接修改。
:::


### 1.2.4 调用类产生对象

类里存的东西只是为了减少资源浪费，本质上仍属于具体的对象。所以提取到类之后还要**建立对象与类的关联**，让对象顺着关联访问到原本属于它的那部分数据和功能。

做法：**调用类——类名后面加括号**。调用后 Python 会基于这个类造一个对象，并建好对象与类的关联，返回值就是一个英雄对象。

- 调用类**不会**再次执行类的子代码（子代码在定义阶段已执行过），只负责造对象、建关联
- 调用一次造一个对象，调用多少次就造多少个

对象和类一样也有 `__dict__`。刚造出来的对象 `__dict__` 是**空字典**，因为还没往里放东西；但这不代表对象访问不到内容——`hero_work`、`get_hero_info`、`set_hero_speed` 被提取到类里了，对象一定能访问到。

```python
class Hero:
    hero_work = "射手"

    def get_hero_info(hero_obj):
        pass

    def set_hero_speed(hero_obj, speed_plus):
        pass

hero1_obj = Hero()   # 调用类，造对象
hero2_obj = Hero()
hero3_obj = Hero()

print(hero1_obj.__dict__, hero2_obj.__dict__, hero3_obj.__dict__)
print(hero1_obj.hero_work)    # 对象自己没有，但能访问到类里的
# 输出:
# {} {} {}
# 射手
```

接下来给对象添加**独有的数据**（名字、移速、生命值、攻击力）。对象的 `__dict__` 是字典，可以直接往里加；但更简单的是用**点语法**增加属性：

```python
class Hero:
    hero_work = "射手"

hero1_obj = Hero()

# 方式一：直接操作 __dict__
hero1_obj.__dict__["name"] = "鲁班七号"
hero1_obj.__dict__["speed"] = 450

# 方式二：点语法（更简单，本质仍是操作 __dict__）
hero1_obj.hp = 3000
hero1_obj.atk = 100
print(hero1_obj.__dict__)

hero2_obj = Hero()
hero2_obj.name = "后羿"
hero2_obj.speed = 460
hero2_obj.hp = 3100
hero2_obj.atk = 110
print(hero2_obj.__dict__)
# 输出:
# {'name': '鲁班七号', 'speed': 450, 'hp': 3000, 'atk': 100}
# {'name': '后羿', 'speed': 460, 'hp': 3100, 'atk': 110}
```

通过"对象.属性"的方式**访问、修改、增加**属性，本质都是在操作对象的 `__dict__`，Python 只是提供了更简洁的语法。每个对象就有了各自独有的数据。

问题：每造一个对象都要写好几行赋值，代码重复。

### 1.2.5 `__init__` 初始化方法

**第一步：用函数消除重复**

解决代码重复，讲函数时就说过：把重复代码缩进到一个函数里。再看函数里哪里"写死"了：

- 要赋的值不能写死 → 定义成参数 `name`、`speed`、`hp`、`atk`
- 对象本身也不能写死 → 也通过参数 `hero_obj` 传进来

注意 `hero_obj.name = name` 里有两个 `name`：右边是参数传进来的值，左边是对象的 `name` 属性。

这个函数的作用是在对象刚造出来时立即给它**初始化独有属性**，所以取名 `init`：

```python
class Hero:
    hero_work = "射手"

def init(hero_obj, name, speed, hp, atk):
    """给对象初始化独有的属性"""
    hero_obj.name = name      # 左边是对象的属性，右边是传进来的参数
    hero_obj.speed = speed
    hero_obj.hp = hp
    hero_obj.atk = atk

hero1_obj = Hero()
hero2_obj = Hero()
hero3_obj = Hero()
init(hero1_obj, "鲁班七号", 450, 3000, 100)
init(hero2_obj, "后羿", 460, 3100, 110)
init(hero3_obj, "虞姬", 470, 3200, 120)
print(hero1_obj.__dict__)
print(hero3_obj.__dict__)
# 输出:
# {'name': '鲁班七号', 'speed': 450, 'hp': 3000, 'atk': 100}
# {'name': '虞姬', 'speed': 470, 'hp': 3200, 'atk': 120}
```

**第二步：放进类里，改名 `__init__`**

能否把 `init` 和类进一步整合，**调用类产生对象时就自动调用它**、拿到的直接就是带独有属性的对象？

只把 `init` 剪切进类里，调用类时并不会自动执行。必须把名字改成 **`__init__`**（前后各两个下划线），这个名字是固定的。只要类里定义了 `__init__`，**调用类时它就会自动执行**——这是 Python 提供的语法支持。

于是外面手动调用 `init` 的代码都不需要了。先直接 `Hero()` 运行一下：

```python
class Hero:
    hero_work = "射手"

    def __init__(hero_obj, name, speed, hp, atk):
        hero_obj.name = name
        hero_obj.speed = speed
        hero_obj.hp = hp
        hero_obj.atk = atk

try:
    hero1_obj = Hero()
except TypeError as e:
    print(e)
# 输出: Hero.__init__() missing 4 required positional arguments: 'name', 'speed', 'hp', and 'atk'
```

报错说明 `__init__` 确实被调用了。但它明明有 5 个参数，报错却只说少了后 4 个——说明 **Python 自动传了第一个参数**：调用类时，Python 自动调用类里的 `__init__`，并把**刚创建的（还是空的）对象**传进去。我们只需传后面 4 个参数，**在调用类的括号里传**，Python 会把它们传递给 `__init__`：

```python
class Hero:
    hero_work = "射手"

    def __init__(hero_obj, name, speed, hp, atk):
        hero_obj.name = name
        hero_obj.speed = speed
        hero_obj.hp = hp
        hero_obj.atk = atk

# 一行代码，既造了对象，又初始化了对象的属性
hero1_obj = Hero("鲁班七号", 450, 3000, 100)
hero2_obj = Hero("后羿", 460, 3100, 110)
hero3_obj = Hero("虞姬", 470, 3200, 120)
print(hero1_obj.__dict__)
print(hero2_obj.__dict__)
print(hero3_obj.__dict__)
# 输出:
# {'name': '鲁班七号', 'speed': 450, 'hp': 3000, 'atk': 100}
# {'name': '后羿', 'speed': 460, 'hp': 3100, 'atk': 110}
# {'name': '虞姬', 'speed': 470, 'hp': 3200, 'atk': 120}
```

调用类造对象的过程，也有人称为**实例化（Instantiation）**：类是抽象的概念（如人类、植物类），具体到某个人时，这个人才是人类实际的一个案例，即人类的**实例**。

**调用类时发生的三件事**：

1. 创建一个**空对象**（没有任何独有属性）
2. 调用类里的 `__init__` 方法，把刚创建的空对象以及调用类时括号里的参数**一同传给** `__init__`
3. **返回初始化好的对象**

**`__init__` 的注意点**：

- **返回的对象并不是 `__init__` 返回的**。`__init__` 里写 `return None` 没问题，不写默认也返回 `None`；而且一开始没定义 `__init__` 时，调用类同样能返回对象——返回对象是类在底层做的事情
- **`__init__` 只能返回 `None`**，返回其他值会报错，所以里面没必要写 `return`
- `__init__` 里除了初始化属性，也可以写其他代码，如 `print`、各种判断、调用其他方法——凡是需要在调用类时自动执行的代码，都可以放在 `__init__` 里

```python
class Hero:
    def __init__(hero_obj, name):
        print("调用类时自动执行")   # 可以写任意代码
        hero_obj.name = name
        # return 1   # 返回非 None 会报错

h = Hero("鲁班七号")
print(h.name)
# 输出:
# 调用类时自动执行
# 鲁班七号
```


:::note[补充]
严格来说，"创建空对象"这一步由 `__new__` 方法完成，`__init__` 只负责初始化，所以它是**初始化方法**而非构造方法。`__new__` 将在后续章节讲解。另外，`__init__` 的第一个参数按规范应写作 `self`，下一节会讲到。
:::


## 1.3 属性查找与绑定方法

### 1.3.1 属性查找顺序

调用类产生对象后，对象有自己的名称空间，存放独有的属性；类的名称空间存放对象共有的属性。

对象查找属性时，**一定是先在对象自己的名称空间里找，自己没有，才去它所属的类的名称空间里找**。

```python
class Hero:
    hero_work = "射手"

    def __init__(self, name, speed, hp, atk):
        self.name = name
        self.speed = speed
        self.hp = hp
        self.atk = atk

hero1_obj = Hero("鲁班七号", 450, 3000, 100)
hero2_obj = Hero("后羿", 460, 3100, 110)
hero3_obj = Hero("虞姬", 470, 3200, 120)

print(hero1_obj.name)        # 对象自己有
print(hero1_obj.hero_work)   # 对象没有，去类里找
# 输出:
# 鲁班七号
# 射手

# 三个对象和类访问到的是同一个内存地址
print(id(hero1_obj.hero_work) == id(hero2_obj.hero_work) == id(hero3_obj.hero_work) == id(Hero.hero_work))
# 输出: True

# 1. 修改类的数据属性：所有对象都跟着变
Hero.hero_work = "法师"
print(hero1_obj.hero_work, hero2_obj.hero_work, hero3_obj.hero_work)
# 输出: 法师 法师 法师

# 2. 通过对象赋值：只在对象自己的名称空间新增属性，不会改类
Hero.hero_work = "射手"
hero3_obj.hero_work = "法师"
print(hero1_obj.hero_work, hero2_obj.hero_work, hero3_obj.hero_work, Hero.hero_work)
print(hero3_obj.__dict__)
# 输出:
# 射手 射手 法师 射手
# {'name': '虞姬', 'speed': 470, 'hp': 3200, 'atk': 120, 'hero_work': '法师'}
```

要点：

- 所有对象的职业都指向类里的 `hero_work`，所以只要类改了，所有对象都跟着变
- "先自己后类"说的是**查找**。**赋值操作**不管自己有没有这个属性：有就覆盖，没有就在**自己这里新增**，绝不会去改类里的值——否则其他对象岂不是也跟着变了
- `hero3_obj` 自己有了 `hero_work` 之后，再查找就不会去类里找了


:::note[补充]
类不会反过来到对象中找属性，`Hero.name` 会直接报 `AttributeError`。学完继承后，查找链会延长为：对象 → 类 → 父类 → … → `object`。
:::


### 1.3.2 类属性的共享特性

只要改了类的数据属性，通过这个类实例化的**所有对象都能感知到变化**。利用这个特点做一个小需求：**每实例化一个对象就统计一次对象数量**，不管通过哪个英雄对象访问 `count` 属性，都能查到当前的英雄数量。

分析：

- 所有对象都要能访问 `count`，所以它应该放在**类**里（放在某个对象里就只有这个对象能访问），初始值为 0
- 每造一个对象就加 1。注意**一定不能写 `hero1_obj.count += 1`**，那样改的是对象自己的属性（会在对象的名称空间里新增一个 `count`）；要让所有对象都看到变化，必须**通过类去改**：`Hero.count += 1`

每造一个对象都在外面写一次 `Hero.count += 1` 太麻烦了。造对象时会自动执行 `__init__`，所以把这句放进 `__init__`，外面的代码就不需要了：

```python
class Hero:
    hero_work = "射手"
    count = 0                 # 放在类里，所有对象共享

    def __init__(self, name, speed, hp, atk):
        self.name = name
        self.speed = speed
        self.hp = hp
        self.atk = atk
        Hero.count += 1       # 必须通过类修改；写 self.count += 1 就成了给对象新增属性

hero1_obj = Hero("鲁班七号", 450, 3000, 100)
hero2_obj = Hero("后羿", 460, 3100, 110)
hero3_obj = Hero("虞姬", 470, 3200, 120)
print(Hero.count, hero1_obj.count, hero2_obj.count, hero3_obj.count)
# 输出: 3 3 3 3
```

所以修改数据属性时一定要清楚：**改的是类的数据属性，还是对象的数据属性**。


:::warning[注意]
如果类属性是**可变类型**（如列表），通过对象调用 `obj.items.append()` 并不是赋值，而是修改类中共享的那个列表，会影响所有对象。因此对象独有的可变数据应在 `__init__` 中用 `self.items = []` 创建。
:::


### 1.3.3 绑定方法

类的数据属性是共享给对象用的，那类的**函数属性**又是如何给对象使用的？

**类调用函数：就是普通函数**

类自己当然可以用函数属性。`Hero.get_hero_info` 拿到的是函数内存地址，加括号就能运行，但要严格按函数的用法，**有几个参数就传几个参数**。

- 不传参数直接调用 → 报错缺少参数 `hero_obj`
- 函数体若还沿用字典写法 `hero_obj["name"]`，传入对象后会报 `TypeError: 'Hero' object is not subscriptable`（对象不支持下标）。改成 `hero_obj.__dict__["name"]` 可以，但更简单的是直接用**点语法** `hero_obj.name`

```python
class Hero:
    hero_work = "射手"

    def __init__(hero_obj, name, speed, hp, atk):
        hero_obj.name = name
        hero_obj.speed = speed
        hero_obj.hp = hp
        hero_obj.atk = atk

    def get_hero_info(hero_obj):
        print(f"英雄属性：名字：{hero_obj.name} 移速：{hero_obj.speed} "
              f"生命值：{hero_obj.hp} 攻击力：{hero_obj.atk}")

    def set_hero_speed(hero_obj, speed_plus):
        hero_obj.speed += speed_plus

hero1_obj = Hero("鲁班七号", 450, 3000, 100)
hero2_obj = Hero("后羿", 460, 3100, 110)

print(Hero.get_hero_info)              # 普通函数
Hero.get_hero_info(hero1_obj)          # 类调用：必须手动传对象
Hero.set_hero_speed(hero1_obj, 60)     # 两个参数都要传
Hero.get_hero_info(hero1_obj)
# 输出:
# <function Hero.get_hero_info at 0x...>
# 英雄属性：名字：鲁班七号 移速：450 生命值：3000 攻击力：100
# 英雄属性：名字：鲁班七号 移速：510 生命值：3000 攻击力：100
```

**对象访问函数：绑定方法**

类里定义的函数**主要是给对象用的，而且是绑定给对象使用的**。虽然所有对象指向的都是相同的功能，但绑定到不同对象，就变成了不同的**绑定方法**：

```python
hero3_obj = Hero("虞姬", 470, 3200, 120)

print(Hero.get_hero_info)        # function：普通函数
print(hero1_obj.get_hero_info)   # bound method：绑定方法
print(hero2_obj.get_hero_info)
print(hero3_obj.get_hero_info)
# 输出:
# <function Hero.get_hero_info at 0x...>
# <bound method Hero.get_hero_info of <__main__.Hero object at 0x...>>
# <bound method Hero.get_hero_info of <__main__.Hero object at 0x...>>
# <bound method Hero.get_hero_info of <__main__.Hero object at 0x...>>
```

对象和类访问数据属性时内存地址是同一个，到了函数属性这里却不一样了：

- `bound method` 就是**绑定方法**。类的函数属性绑定给对象后，就不再是普通函数了
- 三个绑定方法的地址各不相同，但**函数代码本身只存了一份**（类的作用就是减少资源浪费）。可以理解为：函数绑定给对象后，被**包装**成了一个绑定方法，对象访问到的是这个绑定方法，而它最终仍指向原本的函数

为什么要绕这么一圈？因为这个"中间商"**在里面做了手脚**：

```python
hero1_obj.get_hero_info()      # 不用传对象！
hero2_obj.get_hero_info()
hero1_obj.set_hero_speed(100)  # 只需传 speed_plus
hero1_obj.get_hero_info()
hero2_obj.get_hero_info()      # 没调用的对象不受影响
# 输出:
# 英雄属性：名字：鲁班七号 移速：510 生命值：3000 攻击力：100
# 英雄属性：名字：后羿 移速：460 生命值：3100 攻击力：110
# 英雄属性：名字：鲁班七号 移速：610 生命值：3000 攻击力：100
# 英雄属性：名字：后羿 移速：460 生命值：3100 攻击力：110
```

`set_hero_speed` 明明定义了两个参数，但 `hero1_obj.set_hero_speed()` 不传参调用时，报错却只说缺少 `speed_plus`——和 `__init__` 一样，**绑定方法会自动把对象本身传给函数的第一个参数**，这就是"中间商"做的手脚。

**谁来调用绑定方法，就会把谁作为第一个参数传进去**：`hero1_obj` 调用 `get_hero_info` 打印的就是 `hero1_obj` 的信息，`hero2_obj` 调用打印的就是 `hero2_obj` 的。语义明确，代码也精简得多。所以以后调用类里的函数，直接**通过对象调绑定方法**即可，不用考虑第一个参数——这也是 `__init__` 不需要传第一个参数的原因。

### 1.3.4 self 参数

正因为有绑定方法，**类里定义函数时至少要有一个形参**——即便函数本身不需要参数，也要用一个形参接收绑定方法传进来的对象。

```python
class Hero:
    def test():           # 没有任何形参
        print("test")

Hero.test()               # 类调用：当普通函数用，没问题
hero_obj = Hero()
try:
    hero_obj.test()       # 对象调用：自动传入对象，但函数不接收
except TypeError as e:
    print(e)
# 输出:
# test
# Hero.test() takes 0 positional arguments but 1 was given
```

给 `test` 加一个形参（叫 `xxx`、`bbb` 都行）就不报错了。但这不规范：**第一个参数按规范应写成 `self`**。`self` 没有任何特殊之处，只是一个变量名，规范要求用这个单词。前面 `__init__`、`get_hero_info` 等函数的第一个参数 `hero_obj` 也应统一改成 `self`。


:::tip[技巧]
PyCharm 多光标批量修改：选中一个 `hero_obj` 后反复按 Alt+J（macOS 为 Ctrl+G），每按一次多选中一个同名词并增加一个光标，然后直接输入 `self` 即可一次性全部替换。
:::


有了绑定方法，使用起来更加符合习惯。比如定义一个"买装备"功能：在 `__init__` 里给对象新增属性 `equipment = []`，在 `buy_equipment` 里往 `self.equipment` 中追加装备：

```python
class Hero:
    hero_work = "射手"

    def __init__(self, name, speed, hp, atk):
        self.name = name
        self.speed = speed
        self.hp = hp
        self.atk = atk
        self.equipment = []           # 每个对象独有的装备列表

    def buy_equipment(self, e_name):  # self 由绑定方法自动传入
        self.equipment.append(e_name)

hero1_obj = Hero("鲁班七号", 450, 3000, 100)
hero2_obj = Hero("后羿", 460, 3100, 110)
hero3_obj = Hero("虞姬", 470, 3200, 120)

hero1_obj.buy_equipment("反甲")      # 给谁买，就用谁调用
print(hero1_obj.equipment, hero2_obj.equipment, hero3_obj.equipment)
hero2_obj.buy_equipment("复活甲")
hero3_obj.buy_equipment("名刀")
print(hero1_obj.equipment, hero2_obj.equipment, hero3_obj.equipment)
# 输出:
# ['反甲'] [] []
# ['反甲'] ['复活甲'] ['名刀']
```

这就是绑定方法厉害的地方：**谁调用的绑定方法，处理的就是谁的数据**。

### 1.3.5 内置类型也是类

讲基本数据类型时，字符串、整型、浮点型、列表、字典、元组、集合都有各自的功能，比如 `str.strip`，当时说"遇到 `self` 这个参数就当它不存在"。现在可以知道原因了：**基本数据类型也是类**。

```python
print(str, int, float, list, dict, tuple, set)
# 输出: <class 'str'> <class 'int'> <class 'float'> <class 'list'> <class 'dict'> <class 'tuple'> <class 'set'>

class Hero:
    pass

print(Hero)
# 输出: <class '__main__.Hero'>
```

我们自定义的 `Hero` 同样是类——可以说是定义了一个英雄类，也可以说是**定义了一种新的数据类型**，因为在 Python 里**类就是类型**。上面那些是 Python 内置好的类，直接用即可。

- 定义一个字符串、列表、字典，其实就是在**造对象**
- 通过对象点各种方法，就是在**用对象调用绑定方法**，所以当初说 `self` 可以当它不存在——它会被自动传入
- 用字符串调用 `strip`，处理的就是这个字符串本身：**谁调用的绑定方法，处理的就是谁的数据**
- 直接用引号定义字符串 `x = "abc"`，背后触发的是 `str("abc")`——这其实就是**类实例化**的过程，`x` 就是 `str` 这个类实例化出的对象

```python
x = " abc "                 # 背后相当于 x = str(" abc ")
print(type(x), x.strip())   # x 调用的 strip，处理的就是 x
# 输出: <class 'str'> abc
```

引号造字符串对象，中括号造列表对象，大括号造字典对象和集合对象，小括号造元组对象；甚至从文件里读出来的二进制数据，Python 也封装成了二进制（bytes）对象。这才有了那句"**在 Python 里一切皆对象**"——对象这个概念我们很早就在用了，只是当时不知道而已。

**列表的中括号取值与 `list.append`**

列表 `l = ["a", "b", "c"]` 用 `l[0]` 中括号加索引取值，其实是 **Python 做的语法优化**；如果没有这个优化，可能就得用 `l.first_value` 之类很笨拙的方式取值。

自定义的类目前只能用 `对象.属性` 的方式访问；如果嫌麻烦，想换成中括号的方式，在类里做进一步处理也能实现——需要在类中实现 `__getitem__` 等魔法方法，这是后面才会讲的知识点。

再看给列表添加元素：`l.append("d")` 的 `append` 本来需要两个参数，因为是**对象调用绑定方法**，第一个参数不用管。学了绑定方法后还有另一种写法——**直接通过类调用**：`l` 的类是 `list`，用 `list.append` 时就不能忽略 `self`，要先把对象 `l` 传进去：

```python
l = ["a", "b", "c"]
l.append("d")             # 对象调用绑定方法：自动传入 l
print(l)
list.append(l, "e")       # 类调用：必须手动传入对象 l
print(l)
# 输出:
# ['a', 'b', 'c', 'd']
# ['a', 'b', 'c', 'd', 'e']
```

效果完全一样。虽然以后不会这样用，但要知道为什么可以这样用。

### 1.3.6 面向对象的适用场景

到此为止，面向对象的核心内容就讲完了。需要明确：**用面向对象的思想写程序，只是增强了程序的可扩展性**；而一个软件的质量由很多方面决定，扩展性只是其中之一。所以不要觉得所有代码都应该用面向对象来写——只有在**扩展性要求很高**的地方才考虑用面向对象整合程序，很多地方用面向过程的思想就可以了。


:::note[补充]
绑定方法对象有两个关键属性：`__self__`（绑定的对象）和 `__func__`（原始函数），例如 `hero1_obj.get_hero_info.__self__ is hero1_obj` 为 `True`。其底层原理是函数实现了描述符协议（`__get__` 方法）。
:::


## 本章小结

- 对象就是容器，是数据和功能的集合体；面向对象的核心思想是**整合**，把相关的数据和功能放到同一个容器，实现**解耦合**
- 类是对象的分类，也是存放同类对象共有数据与功能的容器，目的是分类和节省资源；共有数据本质仍属于各个对象
- 程序中先定义类、再调用类产生对象；类名用驼峰体
- 类体代码在**定义阶段立即执行**，类的名称空间在定义阶段产生，可用 `__dict__` 查看
- 点语法本质是操作 `__dict__`；类的属性分为数据属性和函数属性
- 调用类：创建空对象 → 自动调用 `__init__(空对象, 括号内参数)` → 返回对象；`__init__` 必须返回 `None`
- 对象查找属性：先自己的名称空间，再类的名称空间；赋值操作只会作用于对象自身
- 类的数据属性被所有对象共享；改类影响所有对象。统计对象数量要在 `__init__` 中通过 `类名.count += 1` 修改
- 类中的函数：类调用时是普通函数，要严格传参；对象访问时是绑定方法，**谁调用就把谁作为第一个参数自动传入**，处理的就是谁的数据
- 类中函数至少要有一个形参，规范命名为 `self`
- 内置类型都是类，类就是类型；`list.append(l, x)` 与 `l.append(x)` 等价
- 面向对象只增强扩展性，扩展性要求高时才使用
