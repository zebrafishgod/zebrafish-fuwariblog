## 2.1 封装与属性隐藏

**封装（Encapsulation）** 是面向对象最核心的特性，其本质就是前面讲的**整合**——把数据和功能装到一个容器（类）里。在此基础上，Python 可以对属性做进一步处理：**隐藏属性**。

### 2.1.1 隐藏属性的语法

在属性名前加 `__`（双下划线）即可隐藏属性：

```python
class Test:
    __x = 10            # 隐藏数据属性

    def __f1(self):     # 隐藏函数属性
        print("f1")

# 通过类或对象都无法直接访问
try:
    print(Test.__x)
except AttributeError as e:
    print(e)            # 输出: type object 'Test' has no attribute '__x'

try:
    Test().__f1()
except AttributeError as e:
    print(e)            # 输出: 'Test' object has no attribute '__f1'
```

### 2.1.2 隐藏的三个特点

**特点一：本质是改名操作**

隐藏并非真正删除属性，只是在定义阶段自动改名为 `_类名__属性名`：

```python
class Test:
    __x = 10

print([k for k in Test.__dict__ if "Test" in k])
# 输出: ['_Test__x']

print(Test._Test__x)    # 用改名后的名字可以访问
# 输出: 10
```

**特点二：对外不对内**

在类的外部无法通过 `__x` 访问，但在类的内部可以访问：

```python
class Test:
    __x = 10

    def f(self):
        print(self.__x)    # 类内部可以访问

Test().f()
# 输出: 10
```

原因：在类的定义阶段，类内部所有 `__` 开头的名字都会统一改名为 `_类名__属性名`，所以类内的 `self.__x` 实际上已经变成了 `self._Test__x`。

**特点三：改名只在定义阶段发生一次**

类体代码之外定义的 `__` 属性不会改名：

```python
class Test:
    __x = 10

Test.__y = 20
print("__y" in Test.__dict__)           # 输出: True
print("_Test__y" in Test.__dict__)      # 输出: False
```


:::tip[技巧]
单下划线 `_x` 是约定俗成的"内部使用"标记，解释器不做任何处理，纯靠自觉；双下划线 `__x` 会真正改名。
:::


### 2.1.3 为何隐藏属性

**隐藏数据属性：严格控制访问**

隐藏数据属性后，需要开接口让使用者间接访问。接口本质是函数，可以在其中附加任意校验逻辑：

```python
class Person:
    def __init__(self, name, age):
        self.__name = name
        self.__age = age

    def get_name(self):
        return self.__name

    def get_age(self):
        return self.__age

    def set_age(self, new_age):
        if type(new_age) is not int:
            print("年龄必须是整型")
            return
        if not 0 <= new_age <= 150:
            print("年龄必须在 0 到 150 岁之间")
            return
        self.__age = new_age

obj = Person("张三", 18)
obj.set_age("20")       # 输出: 年龄必须是整型
obj.set_age(-5)         # 输出: 年龄必须在 0 到 150 岁之间
obj.set_age(20)
print(obj.get_age())    # 输出: 20
```

类的设计者通过隐藏属性 + 开接口的方式，严格控制使用者对属性的操作。

**隐藏函数属性：隔离复杂度**

把内部实现步骤隐藏起来，只对外提供一个功能入口，降低使用复杂度：

```python
class BuyBun:
    def __run_to_shop(self):
        print("跑到包子店")

    def __pay(self):
        print("给钱")

    def __run_back(self):
        print("拿着包子跑回来")

    def buy_bun(self):
        """对外只提供这一个入口"""
        self.__run_to_shop()
        self.__pay()
        self.__run_back()

BuyBun().buy_bun()
# 输出:
# 跑到包子店
# 给钱
# 拿着包子跑回来
```

使用者只需要知道调用 `buy_bun()`，不需要关心内部步骤。

## 2.2 property

### 2.2.1 问题引入

虽然通过开接口可以控制属性访问，但使用者需要调用方法：

```python
obj.get_age()       # 查看
obj.set_age(20)     # 修改
```

这不符合操作数据属性的思维习惯，使用者更希望：

```python
obj.age             # 查看
obj.age = 20        # 修改
del obj.age         # 删除
```

如何既让使用者用起来像数据属性，背后触发的又是设计者开的接口？答案是 `property`。

### 2.2.2 property 的用法

`property` 是 Python 内置的装饰器，**用类实现**（而非函数），作用是**把方法伪装成数据属性**。

**方式一：property(查, 改, 删)**

```python
class Person:
    def __init__(self, age):
        self.__age = age

    def get_age(self):
        return self.__age

    def set_age(self, new_age):
        if type(new_age) is not int or not 0 <= new_age <= 150:
            print("年龄无效")
        else:
            self.__age = new_age

    def del_age(self):
        del self.__age

    age = property(get_age, set_age, del_age)   # 顺序：查、改、删

obj = Person(18)
print(obj.age)      # 触发 get_age(obj)
obj.age = 20        # 触发 set_age(obj, 20)
del obj.age         # 触发 del_age(obj)
```


:::warning[注意]
`property()` 的参数顺序必须是：查、改、删，顺序错误会导致参数不匹配。
:::


**方式二：@property 语法糖（推荐）**

```python
class Person:
    def __init__(self, age):
        self.__age = age

    @property
    def age(self):                    # 查：obj.age
        return self.__age

    @age.setter
    def age(self, new_age):           # 改：obj.age = 值
        if type(new_age) is not int:
            print("年龄必须是整型")
        elif not 0 <= new_age <= 150:
            print("年龄必须在 0 到 150 岁之间")
        else:
            self.__age = new_age

    @age.deleter
    def age(self):                    # 删：del obj.age
        del self.__age

obj = Person(18)
print(obj.age)
obj.age = 20
print(obj.age)
obj.age = "abc"     # 输出: 年龄必须是整型
# 输出:
# 18
# 20
# 年龄必须是整型
```

三个方法名要统一，装饰器分别是 `@property`、`@名字.setter`、`@名字.deleter`。


:::tip[技巧]
- 只定义 `@property` 而不定义 `setter` 时，该属性是只读的。
- 典型应用：BMI = 体重 / 身高²，用 `@property def bmi(self)` 让使用者写 `p.bmi` 获取计算值。
- property 的方法名不要和存储数据的属性名相同，避免无限递归。
:::


## 2.3 继承基础

**继承（Inheritance）** 是创建新类的方式，通过继承创建的类称为**子类（Subclass）**，被继承的类称为**父类（Parent Class / Base Class）**。

### 2.3.1 继承的语法

定义子类时，在类名后的括号里写父类：

```python
class Parent:
    x = 10

class Child(Parent):        # 单继承
    pass

print(Child.x)              # 输出: 10
print(Child.__bases__)      # 输出: (<class '__main__.Parent'>,)
```

- 括号里只写一个父类：**单继承**
- 括号里写多个父类（逗号隔开）：**多继承**

### 2.3.2 新式类与经典类

这一区分只存在于 Python 2：

- **新式类**：继承了 `object` 的类
- **经典类**：没有继承 `object` 的类

在 **Python 3 中所有类默认继承 `object`，全是新式类**：

```python
class Test:             # 没写父类
    pass

print(Test.__bases__)   # 输出: (<class 'object'>,)
```

### 2.3.3 继承的特性

**遗传：子类可以访问父类的属性**

```python
class Human:
    star = "earth"

    def __init__(self, name, age, gender):
        self.name = name
        self.age = age
        self.gender = gender

class Chinese(Human):
    nation = "China"

    def speak_chinese(self):
        print(f"{self.name}正在说普通话")

dy = Chinese("董永", 18, "男")
print(dy.name, dy.nation, dy.star)
# 输出: 董永 China earth
```

查找顺序：**对象自己 → 对象的类 → 类的父类**。

**用途：解决类与类之间的代码冗余**

- **类**的出现是为了解决**对象**之间的代码冗余
- **继承**的出现是为了解决**类**之间的代码冗余


:::note[补充]
- 继承表达的是 **is-a**（"是"）的关系：学生是人、狗是动物。
- 若是 **has-a**（"有"）的关系（学生有课程），应该用**组合**：把一个对象作为另一个对象的属性。
- 继承具有**传递性**：`C(B)`、`B(A)`，则 C 也能访问 A 的属性。
:::


### 2.3.4 派生

**派生**是指子类在继承父类的基础上做出的改变，有三种情况：

**1. 派生出父类没有的新属性**

```python
class Chinese(Human):
    nation = "China"        # 父类 Human 没有这个属性
```

**2. 与父类同名，以子类为准**

```python
class Human:
    star = "earth"

class American(Human):
    star = "xxx"            # 与父类同名

print(American().star)      # 输出: xxx
```

**3. 在父类功能基础上扩展**

子类需要多一个属性 `balance`，但 name、age、gender 仍需要父类的 `__init__` 处理：

```python
class Human:
    def __init__(self, name, age, gender):
        self.name = name
        self.age = age
        self.gender = gender

class Chinese(Human):
    def __init__(self, name, age, gender, balance):
        # 重用父类的 __init__：类调用函数是普通函数，必须手动传 self
        Human.__init__(self, name, age, gender)
        self.balance = balance

dy = Chinese("董永", 18, "男", 1000)
print(dy.__dict__)
# 输出: {'name': '董永', 'age': 18, 'gender': '男', 'balance': 1000}
```

**为什么不能用 `self.__init__(...)`？**

`self` 是对象，找 `__init__` 先找对象自己，自己没有就去类 `Chinese` 中找，找到的正是当前这个 `__init__`，会变成无限递归。应该**指名道姓**地用 `Human.__init__(self, ...)`，通过类访问函数是普通函数，没有自动传参，需手动传 `self`。

## 2.4 属性查找顺序

### 2.4.1 单继承查找

单继承下的属性查找：**对象 → 对象的类 → 父类 → 继续往上……**

经典案例：

```python
class Test1:
    def f1(self):
        print("Test1.f1")

    def f2(self):
        print("Test1.f2")
        self.f1()          # 关键：self 是谁？

class Test2(Test1):
    def f1(self):
        print("Test2.f1")

obj = Test2()
obj.f2()
# 输出:
# Test1.f2
# Test2.f1
```

分析：

1. `obj.f2()`：obj 没有 → `Test2` 没有 → 父类 `Test1` 中找到，打印 `Test1.f2`
2. `self.f1()`：**哪个对象调用绑定方法，就把哪个对象传给 self**。是 obj 调用的 f2，所以 `self` 就是 obj
3. `self.f1()` 等同于 `obj.f1()`：obj 没有 → 在 `Test2` 中找到，打印 `Test2.f1`

**结论：不是"代码写在哪个类里就在哪个类里找"，而是始终从对象开始查找。**

如果就想访问 `Test1` 的 f1，有两种方案：

```python
# 方案一：直接用类名访问（普通函数，需手动传 self）
class Test1:
    def f1(self):
        print("Test1.f1")

    def f2(self):
        Test1.f1(self)      # 指名道姓

class Test2(Test1):
    def f1(self):
        print("Test2.f1")

Test2().f2()                # 输出: Test1.f1


# 方案二：用双下划线隐藏（定义阶段改名）
class Test1:
    def __f1(self):         # 变形为 _Test1__f1
        print("Test1.f1")

    def f2(self):
        self.__f1()         # 变形为 self._Test1__f1()

class Test2(Test1):
    def __f1(self):         # 变形为 _Test2__f1，不影响 _Test1__f1
        print("Test2.f1")

Test2().f2()                # 输出: Test1.f1
```

### 2.4.2 MRO 与菱形继承

**MRO（Method Resolution Order，方法解析顺序）** 是每个类都有的一个列表，记录了属性查找的顺序。用 `类名.mro()` 查看。

**菱形继承**：一个子类继承了多个父类，这些父类最终汇聚到一个非 object 的类。

```python
class A:
    def f1(self):
        print("A.f1")

class B(A):
    def f1(self):
        print("B.f1")

class C(A):
    def f1(self):
        print("C.f1")

class D(B, C):
    pass

obj = D()
obj.f1()                    # 输出: B.f1

print(D.mro())
# 输出: [<class '__main__.D'>, <class '__main__.B'>, <class '__main__.C'>, <class '__main__.A'>, <class 'object'>]
```

查找 f1：对象 → 类 D → 按 MRO 找第一个父类 B，找到 f1。

MRO 列表由 **C3 算法**构造，规则：

- 第一个是自己
- 接着按继承顺序排列父类
- 菱形中的公共父类在最后（广度优先）
- 最后是 object


:::note[补充]
- 对象没有 MRO，只有类才有。
- 可以用 `类名.__mro__` 查看（得到元组）。
- 如果继承关系无法满足 C3 规则，Python 会在定义类时直接报 `TypeError`。
:::


### 2.4.3 非菱形继承

非菱形继承：多个父类没有汇聚到一个公共父类。

```python
class A:
    def f1(self):
        print("A.f1")

class B:
    pass

class C(A):
    pass

class D(B):
    def f1(self):
        print("D.f1")

class E:
    pass

class F(C, D, E):
    pass

print([cls.__name__ for cls in F.mro()])
# 输出: ['F', 'C', 'A', 'D', 'B', 'E', 'object']
```

查找规则：**逐分支找到底**，一条分支找完再找下一条，object 永远最后。

### 2.4.4 深度优先与广度优先

只针对菱形继承而言（Python 2 经典类 vs 新式类）：

```python
#       Z
#     / | \
#    A  B  E
#    |  |  |
#    C  D  |
#     \ | /
#       F
```

- **深度优先（经典类）**：F → C → A → **Z** → D → B → E
- **广度优先（新式类）**：F → C → A → D → B → E → **Z** → object

区别：深度优先在找第一条分支时就找公共父类 Z；广度优先在所有分支找完后才找 Z。

Python 3 中所有类都是新式类，按广度优先（更准确地说是 C3 算法）。

## 2.5 MixIns 机制

### 2.5.1 多继承的优缺点

**优点**：一个子类可以同时遗传多个父类的属性，最大限度地重用代码。

**缺点**：

1. **违背思维习惯**：继承表达"是什么"的关系，生物学分类是单继承（猫 → 猫属 → 猫科），多继承在语义上说不通
2. **可读性变差**：多个父类时属性查找顺序复杂
3. 可能引发菱形继承问题

### 2.5.2 MixIns 的引入

场景：鸡、鸭、鹅都继承"家禽"类。鸭和鹅会游泳，鸡不会。

- 分别给鸭、鹅定义游泳功能 → 代码重复
- 把游泳功能放到"家禽"中 → 鸡也会游泳了，不合理

解决方案：新建一个类专门放游泳功能，让鸭、鹅多继承它。

问题：鹅既是家禽、又是"游泳类"，违背思维习惯。

**MixIns 机制**：给这种"只为混入功能而存在的类"加上 **`Mixin` 后缀**，从语义上区分"表达身份的父类"和"混入功能的工具类"。

```python
class Poultry:                  # 家禽：表达身份
    pass

class SwimMixin:                # 以 Mixin 结尾：只用来混入功能
    def swimming(self):
        print(f"{type(self).__name__} 在游泳")

class Chicken(Poultry):         # 鸡不会游泳
    pass

class Duck(SwimMixin, Poultry):
    pass

class Goose(SwimMixin, Poultry):
    pass

Duck().swimming()               # 输出: Duck 在游泳
Goose().swimming()              # 输出: Goose 在游泳
print(hasattr(Chicken(), "swimming"))   # 输出: False
```

从语义上看：鸭、鹅只有一个父类（家禽），Mixin 只是混入功能。

### 2.5.3 MixIns 注意点

1. **Mixin 类必须表示某一种功能，而不是某一种事物**。Python 中 Mixin 类一般以 `Mixin`、`able`、`ible` 作为后缀
2. **职责必须单一**：游泳功能放在 SwimMixin，飞行功能另写一个 FlyMixin
3. **不依赖子类的实现**：Mixin 应该是独立的插件，子类不继承它也能正常工作
4. **书写顺序**：表达"是什么"关系的类放在最后，且只继承一个，但可以继承多个 Mixin
5. **不要过度使用**：Mixin 越多可读性越差

```python
class SwimMixin:
    def swimming(self):
        print(f"{type(self).__name__} 在游泳")

class FlyMixin:
    def flying(self):
        print(f"{type(self).__name__} 在飞")

# 多个 Mixin 在前，表示身份的类在最后
class Duck(SwimMixin, FlyMixin, Poultry):
    pass

d = Duck()
d.swimming()
d.flying()
print([c.__name__ for c in Duck.mro()])
# 输出:
# Duck 在游泳
# Duck 在飞
# ['Duck', 'SwimMixin', 'FlyMixin', 'Poultry', 'object']
```


:::note[补充]
- Mixin 类一般不定义 `__init__`，避免和主类的初始化逻辑冲突。
- Java 用**接口（interface）**解决类似问题：接口只规定应该有什么功能，不实现具体逻辑。
- 标准库 `socketserver` 中的 `ThreadingMixIn` 就是典型案例。
:::


### 2.5.4 继承关系的选择

| 方式 | 关系 | 适用场景 |
|---|---|---|
| 单继承 | is-a | 子类"是"父类的一种 |
| MixIns | is-a + 若干"能力" | 需要给多个类附加相同的功能 |
| 组合 | has-a | 一个对象"拥有"另一个对象 |

## 2.6 super

### 2.6.1 super 的基本用法

回顾派生的第三种情况：子类重用父类功能。之前的方案是 `Human.__init__(self, ...)`，这种方式**不依赖继承关系**。

另一种方案是 **`super()`**，它**严格依赖继承关系**，按 MRO 查找。

```python
class Human:
    def __init__(self, name, age, gender):
        self.name = name
        self.age = age
        self.gender = gender

class Chinese(Human):
    def __init__(self, name, age, gender, balance):
        # Python 2: super(Chinese, self).__init__(...)
        # Python 3: 可简写为 super().__init__(...)
        super().__init__(name, age, gender)   # 自动传 self
        self.balance = balance

dy = Chinese("董永", 18, "男", 1000)
print(dy.__dict__)
# 输出: {'name': '董永', 'age': 18, 'gender': '男', 'balance': 1000}
```

`super()` 返回一个特殊对象，参照**对象所属类的 MRO**，从 **super 所在类的下一个类**开始查找属性，且**自动传 self**。

### 2.6.2 super 找的是 MRO 中的下一个类

super 查找不一定是父类，而是**对象所属类的 MRO 中，super 所在类的下一个类**：

```python
class A:
    def f1(self):
        print("A.f1")
        super().f1()        # A 没有父类定义 f1，但这里能找到

class B:
    def f1(self):
        print("B.f1")

class C(A, B):              # A 和 B 之间没有继承关系
    pass

obj = C()
print(C.mro())
obj.f1()
# 输出:
# [<class '__main__.C'>, <class '__main__.A'>, <class '__main__.B'>, <class 'object'>]
# A.f1
# B.f1
```

分析：

1. obj 找 f1：对象 → C → A，打印 `A.f1`
2. `super().f1()`：参照 **obj 所属类 C 的 MRO**，从 **A 的下一个类 B** 开始找，打印 `B.f1`

B 是 A 的父类吗？不是。所以 super 不是直接去父类找。

### 2.6.3 两种方案对比

| 方式 | 是否依赖继承 | 是否需要传 self |
|---|---|---|
| `父类名.方法(self, ...)` | 不依赖，直接通过类名调用 | 需要 |
| `super().方法(...)` | 依赖继承，按 MRO 查找 | 不需要 |

**推荐使用 super**，它能很好地与 MRO 配合。在多继承中每个类都用 `super()` 调用，可以让 MRO 上的每个类方法依次恰好执行一次。


:::warning[注意]
- super 只能用在新式类中。
- Python 2 必须写 `super(当前类, self)`，Python 3 可省略参数。
- 两种方式不要混用，统一选一种即可。
:::


## 2.7 多态

### 2.7.1 多态的概念

**多态（Polymorphism）**：同一种事物有多种形态。在程序中用继承表达：奔驰、理想、奥拓都是汽车，但各有不同。

```python
class Car:
    def run(self):
        print("开始跑", end=" ")

class Benz(Car):
    def run(self):
        super().run()
        print("加98号汽油")

class Lixiang(Car):
    def run(self):
        super().run()
        print("充电")

class Auto(Car):
    def run(self):
        super().run()
        print("加92号汽油")

car1, car2, car3 = Benz(), Lixiang(), Auto()
car1.run()
car2.run()
car3.run()
# 输出:
# 开始跑 加98号汽油
# 开始跑 充电
# 开始跑 加92号汽油
```

### 2.7.2 多态性

**多态性：可以在不考虑对象具体类型的情况下直接使用对象。**

只要确定它们都是汽车，不看具体类型也可以直接调用 `run`：

```python
def drive_car(car):
    """统一接口：只要是汽车就能传进来"""
    car.run()

drive_car(car1)
drive_car(car2)
drive_car(car3)
# 输出:
# 开始跑 加98号汽油
# 开始跑 充电
# 开始跑 加92号汽油
```

多态性的好处：**统一了使用标准，以不变应万变**。考驾照学的是"开车"（父类），学会后不管什么车都会开。这个好处本质上是**父类**带来的：父类统一了所有子类的方法。


:::note[补充]
多态的好处是**扩展性**。以后新增一种车，只要它也继承 `Car` 并实现 `run`，调用方 `drive_car` 的代码一行都不用改，这符合**开闭原则（Open-Closed Principle）**。
:::


### 2.7.3 其实你早就在用多态

Python 中所有数据类型都是类，所有数据都是对象。`len` 就是一个多态接口：

```python
print(len("hello"))         # 输出: 5
print(len([1, 2, 3]))       # 输出: 3
print(len({"a": 1, "b": 2}))# 输出: 2
```

为什么能统一使用？因为 Python 给这些类型都定义了 `__len__` 方法：

```python
def my_len(obj):
    """自己定义的统一接口"""
    return obj.__len__()

print(my_len("hello"), my_len([1, 2, 3]), my_len({"a": 1, "b": 2}))
# 输出: 5 3 2
```

`print` 能打印任意类型；`for` 循环能遍历字符串、列表、字典、文件等，也是因为它们都有 `__iter__` 方法。

### 2.7.4 鸭子类型

上面的多态讲法对所有面向对象语言都通用。但在 Python 中，**多态并不推崇用继承的方式来表达**。

**鸭子类型（Duck Typing）**：如果你走路摇摇晃晃像鸭子，叫声像鸭子，长得也像鸭子，那就可以说你是鸭子。

Python 的思想更多是从**规范层面**要求你，不严格限制。即便不继承父类，只要定义类时按统一标准来（都有相同的方法名），同样能达到统一规范的效果。**避开继承还有好处：不用继承就达到了解耦合。**

类比：Linux 的设计思想"**一切皆文件**"——所有操作对象都按文件来操作，不管它到底是不是文件：

```python
class Disk:                 # 磁盘：本身不是文件
    def read(self):
        print("disk read")

    def write(self):
        print("disk write")

class Memory:               # 内存：本身也不是文件
    def read(self):
        print("memory read")

    def write(self):
        print("memory write")

class Txt:                  # txt：本身就是文件
    def read(self):
        print("txt read")

    def write(self):
        print("txt write")

# 三者之间没有继承关系，只是按规范做得像文件，就能统一使用
for obj in (Disk(), Memory(), Txt()):
    obj.read()
    obj.write()
# 输出:
# disk read
# disk write
# memory read
# memory write
# txt read
# txt write
```

这就是 Python 推崇的鸭子类型：**不是用父类去限制子类，而是不继承父类，只把这些类做得像一点就行了。**


:::warning[注意]
鸭子类型耦合低，但代价是缺少约束——如果某个类把方法名写成了 `reed`，只有运行到那一行才会报 `AttributeError`。想要强约束，就用抽象基类。
:::


## 2.8 抽象基类

如果不想用鸭子类型，就想用父类来规范子类，可以引入**抽象基类（Abstract Base Class）**。

### 2.8.1 抽象基类的定义

需要导入 `abc` 模块：

1. 父类括号中写 `metaclass=abc.ABCMeta`（或继承 `abc.ABC`）
2. 在要强制子类实现的方法上加装饰器 `@abc.abstractmethod`

```python
import abc

class Car(metaclass=abc.ABCMeta):       # 抽象基类
    @abc.abstractmethod
    def run(self):
        pass

class Benz(Car):
    def run(self):                      # 实现了 run
        print("加98号汽油")

class Lixiang(Car):
    def run(self):
        pass                            # 先 pass 空着也行

class Auto(Car):                        # 没有定义 run
    pass

Benz().run()                            # 输出: 加98号汽油

try:
    Auto()                              # 子类没有实现 run -> 报错
except TypeError as e:
    print("报错:", e)
# 输出: 报错: Can't instantiate abstract class Auto without an implementation for abstract method 'run'

try:
    Car()                               # 抽象基类本身也不能实例化
except TypeError as e:
    print("报错:", e)
# 输出: 报错: Can't instantiate abstract class Car without an implementation for abstract method 'run'
```

子类如果不写父类规定的 `run`：只要用子类实例化对象就直接报错。**抽象基类本身也不能实例化**，它只用来规范标准。


:::note[补充]
- 也可以写成 `class Car(abc.ABC):`，效果相同。
- 抽象基类是在**实例化时**检查，而不是定义类时。
- 标准库 `collections.abc` 中的 `Iterable`、`Mapping` 等就是典型的抽象基类。
- 这和 Java 接口很像：只规定应该有哪些方法，不实现具体功能。但**不是 Python 推崇的，Python 推崇鸭子类型**。
:::


## 2.9 类方法与静态方法

### 2.9.1 类方法

前面学的绑定方法是**绑定给对象**使用的，会自动把对象传进去。还有一种**绑定给类**使用的方法，专门给类调用，会自动把类传进去。

**一个方法该绑定给类还是对象，取决于方法里用到的是对象还是类。**

场景：有一个配置文件 `settings.py`，需要从中读取 IP 和端口来实例化：

```python
# settings.py
IP = "127.0.0.1"
PORT = 3306
```

如果这种实例化方式经常用，每次都写 `MySQL(settings.IP, settings.PORT)` 比较麻烦，可以定义一个方法 `instance_from_conf`。这个方法需要**类**而不是对象。

用 **`@classmethod`** 装饰器，通过类调用时自动把类传给 `cls`：

```python
import settings

class MySQL:
    def __init__(self, ip, port):
        self.ip = ip
        self.port = port

    @classmethod
    def instance_from_conf(cls):
        """绑定给类的方法：通过类调用时，自动把类传给 cls"""
        obj = cls(settings.IP, settings.PORT)
        return obj

obj = MySQL.instance_from_conf()    # 自动传入 MySQL
print(obj.__dict__)
# 输出: {'ip': '127.0.0.1', 'port': 3306}
```

用 `cls(...)` 而不是写死 `MySQL(...)`，子类继承后调用 `instance_from_conf()`，得到的是子类对象。

**类方法的应用场景比较窄**——它让我们多了一种新的造对象的方式（替代构造器，alternative constructor）。标准库的 `dict.fromkeys()`、`datetime.datetime.now()` 都是类方法。


:::note[补充]
- 规范要求参数叫 `cls`（class 是关键字不能用）。
- 对象也能调用类方法，但传进去的仍然是类。
:::


### 2.9.2 静态方法

类中的函数既不需要类也不需要对象，就是一个独立的功能，用 **`@staticmethod`** 装饰成**非绑定方法（静态方法）**：**对象和类都可以调用它，而且没有自动传参的效果**。

```python
class MySQL:
    def __init__(self, ip, port):
        self.ip = ip
        self.port = port

    def f1(self):                       # 绑定给对象的方法
        print(self.ip, self.port)

    @staticmethod
    def f2():                           # 静态方法
        print("嘿嘿嘿")

    @classmethod
    def instance_from_conf(cls):        # 绑定给类的方法
        import settings
        return cls(settings.IP, settings.PORT)

obj = MySQL("127.0.0.1", 3306)
obj.f2()                                # 输出: 嘿嘿嘿
MySQL.f2()                              # 输出: 嘿嘿嘿

print(obj.f1)                           # <bound method MySQL.f1 of ...>
print(obj.f2)                           # <function MySQL.f2 at ...>
print(MySQL.f2)                         # <function MySQL.f2 at ...>
print(MySQL.instance_from_conf)         # <bound method MySQL.instance_from_conf of ...>
```

静态方法不管通过对象还是类调用，都是普通函数（function）。

| 类型 | 装饰器 | 自动传入 | 判断依据 |
|---|---|---|---|
| 绑定给对象的方法 | 无 | 对象 `self` | 函数体用到对象 |
| 绑定给类的方法 | `@classmethod` | 类 `cls` | 函数体用到类 |
| 非绑定方法（静态方法） | `@staticmethod` | 无 | 类和对象都用不到 |


:::tip[技巧]
静态方法常用于放在类中"归类"的工具函数，例如用 `uuid.uuid4().hex` 生成唯一 id 的 `create_id()`。
:::


## 本章小结

- **封装**就是整合；用 `__` 前缀隐藏属性，本质是改名为 `_类名__属性名`；对外不对内；改名只在定义阶段发生一次。
- 隐藏数据属性是为了严格控制访问（开接口 + 校验），隐藏函数属性是为了隔离复杂度。
- **property** 把方法伪装成数据属性：`property(查, 改, 删)` 或 `@property` + `@名字.setter` + `@名字.deleter`。
- **继承**是创建新类的方式，解决类之间的代码冗余；Python 3 所有类默认继承 `object`，都是新式类。
- **派生**三种情况：新增独有属性、与父类同名时以子类为准、在父类功能基础上扩展（`父类名.方法(self, ...)` 或 `super()`）。
- 单继承查找：对象 → 类 → 父类；遇到 `self.xxx`，self 是调用者对象，要从对象重新找。
- 多继承按**MRO**（C3 算法）查找；菱形继承时新式类广度优先（公共父类最后）；非菱形时逐分支找到底。
- **MixIns**：Mixin 类名以 `Mixin/able/ible` 结尾，只用来混入功能；表示身份的类只有一个且放在最后；职责单一、不依赖子类。
- **super()** 参照对象所属类的 MRO，从 super 所在类的下一个类开始查找，自动传 self；推荐使用。
- **多态**：同一种事物有多种形态；**多态性**：不考虑对象具体类型而直接使用。好处是统一使用标准、以不变应万变；`len`、`print`、`for` 都是多态性的体现。
- **鸭子类型**：不依赖继承，只要"长得像"就能统一使用，是 Python 推崇的方式；Linux"一切皆文件"就是这种思想。
- **抽象基类**：`metaclass=abc.ABCMeta` + `@abc.abstractmethod`，子类不实现抽象方法就无法实例化；不是 Python 推崇的。
- **@classmethod**：绑定给类，自动传 `cls`，主要用于提供新的造对象方式（替代构造器）。
- **@staticmethod**：非绑定方法，类和对象都能调用，不自动传参，就是普通函数。
