## 3.1 反射

### 3.1.1 动态语言与反射机制

- Python 是**强类型、动态、解释型**语言。
- **动态语言**：定义变量时不指定类型，**执行赋值时才识别类型**。`age = 18` 不是没有类型，而是运行到这句才确定是 `int`。
- **静态语言**：运行前就要规定好类型，如 `int age = 18;`，运行时不再分析类型。

```python
age = 18                # 执行赋值时才确定类型
print(type(age))        # 输出: <class 'int'>
```

**反射机制（Reflection）**：程序**运行过程中**，动态获取对象信息、动态调用对象方法的能力。反射被视为动态语言的关键特性。


:::warning[注意]
"只有动态语言才有反射"是不对的。静态语言也可以有反射，如 Go、Java 都有，只是实现起来比 Python 繁琐。Python 一切皆对象，属性都能在运行时查到，所以反射特别简单。
:::


### 3.1.2 为什么需要反射
**结论**：动态语言不到执行那一刻，不知道拿到的数据是什么类型、有哪些属性，所以要先让程序自己判断"有没有"，再决定用不用。

**原因**：程序一旦运行就和写代码的人没关系了。开发者知道对象有什么属性，程序不知道。比如函数收到一个对象参数，直接访问不存在的属性就报错：

```python
def f1(obj):
    print(obj.age)

try:
    f1(18)                      # 整型对象没有 age 属性
except AttributeError as e:
    print("报错:", e)
# 输出: 报错: 'int' object has no attribute 'age'
```

思路：**先判断有没有，有才访问，没有就结束**。用已有知识可以借助 `__dict__`，但它有局限：

```python
class Human:
    def __init__(self, age):
        self.age = age


def f1(obj):
    if "age" not in obj.__dict__:   # 不在 __dict__ 中就是没有
        return
    print(obj.age)


f1(Human(73))                       # 输出: 73
try:
    f1(18)                          # 不是所有对象都有 __dict__
except AttributeError as e:
    print("报错:", e)
# 输出: 报错: 'int' object has no attribute '__dict__'
```

解决思路没问题，只是 `__dict__` 不够通用。**反射就是一套更通用的方法，让程序动态分析对象里有什么、能 get 出什么**。

**类比**：你和同事合作，他产生的数据传给你，你根本不知道里面有哪些属性。必须通过代码分析出数据有什么属性、有没有我要的——有就获取，没有就算了。这是动态语言的特点决定的。


:::note[补充]
反射是很多框架的基础。Web 框架根据请求方法字符串 `"get"`/`"post"` 找视图类中对应方法，ORM 根据字段名字符串给对象赋值。
:::


### 3.1.3 反射的实现：dir + 四个内置函数

**1. dir：查看对象能点出哪些属性**

```python
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def info(self):
        print("name:", self.name, "age:", self.age)


obj = Human("张大仙", 73)
print(dir(obj)[-3:])
# 输出: ['age', 'info', 'name']
```

`dir(obj)` 返回一个列表，里面都是字符串。但不能写 `obj."name"`——点后面跟属性名，不能跟字符串。要**通过字符串反射到真正的属性上**，就用下面四个函数。

**2. 四个内置函数**

通过字符串形式操作对象属性：

| 函数 | 作用 | 等价写法 |
|---|---|---|
| `hasattr(obj, "name")` | 判断是否有某属性 | — |
| `getattr(obj, "name")` | 获取某属性 | `obj.name` |
| `setattr(obj, "name", 值)` | 给某属性赋值 | `obj.name = 值` |
| `delattr(obj, "name")` | 删除某属性 | `del obj.name` |

```python
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def info(self):
        print("name:", self.name, "age:", self.age)


obj = Human("张大仙", 73)

print(hasattr(obj, "name"))     # 输出: True
print(hasattr(obj, "x"))        # 输出: False

print(getattr(obj, "name"))     # 相当于 obj.name，输出: 张大仙

setattr(obj, "name", "米白")    # 相当于 obj.name = "米白"
print(obj.name)                 # 输出: 米白

delattr(obj, "name")            # 相当于 del obj.name
print(obj.__dict__)             # 输出: {'age': 73}
```

**适用范围**：不只是对象，**类也可以传进去**（类也是对象），后面写类属性名即可。不只是数据属性，**函数属性也一样**：写上字符串形式的函数名，拿到的就是函数内存地址——**通过对象拿到的是绑定方法，通过类拿到的是普通函数**。

```python
# 接上例
print(getattr(Human, "info"))   # 通过类：普通函数
print(getattr(obj, "info"))     # 通过对象：绑定方法
# 输出:
# <function Human.info at 0x...>
# <bound method Human.info of <__main__.Human object at 0x...>>

getattr(Human("张大仙", 73), "info")()   # 拿到绑定方法后加括号调用
# 输出: name: 张大仙 age: 73
```


:::note[补充]
反射对模块同样适用。`import time` 后 `getattr(time, "time")()` 可获取当前时间戳。
:::


### 3.1.4 反射案例

**案例 1：解决整型 18 的问题**

一开始用 `__dict__` 看不了整型有没有 `age`，现在用 `hasattr` 就可以：

```python
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj = Human("张大仙", 73)

print(hasattr(18, "age"))           # 输出: False

# 写法一：先判断再获取
if hasattr(18, "age"):
    print(getattr(18, "age"))
else:
    print("没有age")
# 输出: 没有age

# 写法二：一行搞定——getattr 第三个参数是获取不到时返回的默认值
print(getattr(18, "age", None))     # 输出: None
print(getattr(obj, "age", None))    # 输出: 73
```

**案例 2：FTP 功能分发——根据用户输入调用对应功能**

定义 `Ftp` 类，封装 `put` 和 `get` 两个功能，再写一个 `interact` 与用户交互：用户输入 put 就执行 put，输入 get 就执行 get。

问题：一是用户可能输入不存在的功能；二是 `input` 接收的是字符串，不能用 `self.opt` 调用（`opt` 是字符串）。用反射解决：程序不知道 self 有没有用户输入的属性，就先判断，有就获取并加括号调用，没有就提示。

```python
class Ftp:
    def put(self):
        print("正在上传数据")

    def get(self):
        print("正在下载数据")

    def warning(self):
        print("功能不存在")

    def interact(self):
        opt = input("请输入功能>>: ").strip()
        # 找不到 opt 对应的方法，就执行 warning
        getattr(self, opt, self.warning)()


# obj = Ftp()
# obj.interact()
# 运行示例：
# 输入 put 输出: 正在上传数据
# 输入 xxx 输出: 功能不存在
```

这和以前讲过的"函数字典"（把函数名整理到字典里、用户选择功能编号执行）很像，也算一种反射应用，只是没现在的方式简洁。


:::warning[注意]
直接将用户输入映射到方法名时要注意安全。用户输入 `__init__` 或 `interact` 也能被 `getattr` 找到。实际项目中常加校验，如只允许不以下划线开头的方法，或维护白名单。
:::


## 3.2 魔法方法

### 3.2.1 魔法方法概念

**内置方法**（也叫魔法方法、Magic Method）：定义在类里，以**双下划线开头、双下划线结尾**的方法。

**特点**：

- **在满足某种条件时自动执行**。如 `__init__` 在实例化对象时自动执行。
- **定制化我们的对象或类**。`__init__` 作用就是给对象定制独有的属性。

列表能点出很多双下划线开头结尾的方法，以前说"遇到它们就当不存在"。现在知道了：它们会在满足条件时自动触发。比如 `__len__` 会在调用 `len()` 时自动执行。一般不主动调用它们。

### 3.2.2 `__str__` 定制打印

**触发时机**：用 `print` 打印对象时，自动执行这个对象的 `__str__` 方法。

列表是对象，我们自定义类的 obj 也是对象，但打印效果不同：打印列表看到内容，打印 obj 看到内存地址。因为内置类型 Python 做了定制化处理；自定义类没考虑这层，打印的就是原始内存地址。

```python
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj = Human("张大仙", 73)
print([1, 2, 3])    # 输出: [1, 2, 3]
print(obj)          # 输出: <__main__.Human object at 0x...>
```

**需求**：打印对象时直接显示对象信息，如 `张大仙:73`。定制一个 `__str__` 方法：

**排查步骤**（帮助理解原理）：

1. 在 `__str__` 里先只打印一句"`__str__` 运行了"：打印对象时确实执行了，但同时报错；注释掉 `print(obj)` 就既不打印也不报错——说明**打印对象时 `__str__` 才会执行**。
2. 报错信息是 `TypeError: __str__ returned non-string (type NoneType)`：**`__str__` 必须返回字符串**，没写 return 默认返回 None。
3. return 一个字符串（如"嘿嘿嘿"）后，打印对象的结果就是 `__str__` 的返回值。也就是 `print(obj)` 打印的是 `obj.__str__()` 的返回值。

```python
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"{self.name}:{self.age}"


obj = Human("张大仙", 73)
print(obj)              # 输出: 张大仙:73

obj2 = Human("米白", 18)
print(obj2)             # 输出: 米白:18
```

打印哪个对象，哪个对象就自动调用 `__str__` 并把自己传进去，返回对应的字符串。返回内容可以是任何字符串，想打印什么都可以自己定制。


:::note[补充]
`str(obj)` 同样触发 `__str__`。`__repr__` 用于交互式环境直接显示对象、以及容器内元素显示（如 `print([obj])`）。只定义 `__repr__` 时 `print` 也会用它；两者都定义时 `print` 优先用 `__str__`。
:::


### 3.2.3 `__del__` 资源清理

**作用**：在删除对象时先执行它。删除对象时先不着急删，先执行 `__del__`，再删。

```python
class Human:
    def __init__(self, name):
        self.name = name

    def __del__(self):
        print("__del__运行了")


obj = Human("张大仙")
print("=====程序最后一行=====")
# 输出:
# =====程序最后一行=====
# __del__运行了
```

没删对象为什么还是运行了？加个标记能看出：`__del__` 既不是定义完类后执行的，也不是实例化对象后执行的，而是**程序最后一行代码执行完、程序结束时**才执行——程序结束要释放内存空间，就要删除对象，删除对象就先执行 `__del__`。

如果标记之前写 `del obj`：这行会把变量名 obj 和对象的内存地址**解除绑定关系**，对象被当作垃圾、被垃圾回收机制回收，于是 `__del__` 在标记之前运行了。

```python
class Human:
    def __init__(self, name):
        self.name = name

    def __del__(self):
        print("__del__运行了")


obj = Human("张大仙")
del obj                 # 解除绑定 -> 对象被回收 -> 先执行 __del__
print("=====程序最后一行=====")
# 输出:
# __del__运行了
# =====程序最后一行=====
```

平时写代码一般不主动删，都是等程序运行完自己删。

**`__del__` 的用途**：考虑对象被删之前应该做什么。删对象是在回收资源，计算机资源无非两种：**应用程序资源**和**操作系统资源**。对象只占用应用程序资源时，`__del__` 没什么实际作用。

但有一种情况：对象内部有属性**引用了系统资源**，比如打开文件、发起网络连接。对象本身占用应用程序资源，它的属性占用操作系统资源。对象被删后，**Python 回收的只是应用程序资源**（程序运行完直接释放应用程序内存），**操作系统资源 Python 不管**。所以要在对象被删之前告诉操作系统"这个对象没了"。回收系统资源是操作系统干的事，我们只需告诉它：把文件关了，或者把网络连接断了。

```python
class Human:
    def __init__(self, name, path):
        self.name = name
        self.f = open(path, "w", encoding="utf-8")

    def __del__(self):
        # 对象被删前，通知操作系统回收资源
        self.f.close()
        print("文件已关闭")


obj = Human("张大仙", "D:/bili_work/check/v3-进阶01-03/demo.txt")
obj.f.write("hello")
del obj
# 输出: 文件已关闭
```


:::warning[注意]
`__del__` 触发时机依赖引用计数和垃圾回收，不完全可控（如循环引用时可能延迟）。实际开发中释放资源更推荐 `with` 语句（上下文管理器）或显式调用 `close()`，`__del__` 只作兜底。
:::


## 3.3 元类

### 3.3.1 类也是对象

在 Python 里**一切皆对象，就连类也是对象**。基于类可以创建对象：`obj = Human(...)`。如果类也是对象，那 `Human` 也一定是"调用了某个类"得到的。我们用 `class` 关键字定义类，表面上没调用什么"造类的类"，但**任何关键字背后对应的都是某些类的功能**——`class` 的底层替我们完成了。

把 `Human` 当作对象，它的类就叫**元类（Metaclass）**：

```text
元类 → 实例化 → 类（Human） → 实例化 → 对象（obj）
```

查看一个类的元类，和查看对象的类一样，用 `type`：

```python
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def info(self):
        print(f"名字: {self.name}, 年龄: {self.age}")


obj = Human("小明", 18)

print(type(obj))     # 输出: <class '__main__.Human'>  对象的类是 Human
print(type(Human))   # 输出: <class 'type'>            Human 的类（元类）是 type
print(type(str))     # 输出: <class 'type'>            内置类也由 type 产生
```

结论：`type` 是**内置的元类**。不光用 `class` 定义的类，内置的类（如 `str`）也都是元类 `type` 实例化产生的。

**元类与父类**：

- `object` 是所有类的**父类**（继承关系的顶端）
- `type` 是所有类的**元类**（实例化关系的源头）
- `type(type)` 的结果仍是 `type`，而 `type` 本身也继承自 `object`

### 3.3.2 class 关键字创建类的过程

`class` 背后一定有一步是调用内置元类 `type` 并传入参数，得到 `Human` 这个类。要分析的就是：传了哪些参数？造类所需的数据一定和这个类有关：

**1. 类名**：字符串 `"Human"`

**2. 基类**：继承的父类。没写括号时默认是 `object`；可以继承多个，所以用元组：`(object,)`

**3. 名称空间**：类体代码本质是一段字符串，类体代码在**定义阶段**就会执行，执行时产生的名字组成类的名称空间（一个字典）。这步用内置函数 `exec` 模拟：
   - 第1个参数：要执行的代码字符串 `class_body`
   - 第2个参数：全局名称空间。类体若引用了全局名字，通过这个字典传进去；这里没引用，传空字典即可
   - 第3个参数：局部名称空间 `class_dic`，执行过程中产生的名字都放进这里

**4. 调用元类**：没指定元类时，用内置元类 `type`，把前三步的数据传进去：`type(class_name, class_bases, class_dic)`，返回值就是类

```python
# 第1步: 类名
class_name = "Human"

# 第2步: 基类
class_bases = (object,)

# 第3步: 执行类体代码，拿到类的名称空间
class_body = """
def __init__(self, name, age):
    self.name = name
    self.age = age

def info(self):
    print(f"名字: {self.name}, 年龄: {self.age}")
"""
class_dic = {}
exec(class_body, {}, class_dic)
print(class_dic)
# 输出: {'__init__': <function __init__ at 0x...>, 'info': <function info at 0x...>}

# 第4步: 调用元类，得到类
Human = type(class_name, class_bases, class_dic)
print(Human)                      # 输出: <class '__main__.Human'>

obj = Human("小明", 18)
obj.info()                        # 输出: 名字: 小明, 年龄: 18
```

对比用 `class` 造出来的类的 `Human.__dict__`：`class` 帮我们造的名称空间里多了很多内置属性（如 `__module__`、`__dict__`、`__weakref__`、`__doc__`），而我们用 `exec` 造的只有类体代码里的名字。没必要做得一模一样，把主要逻辑分析出来即可。

**变量名不是类**：`type(...)` 的返回值才是类。把它赋给 `A`、`B`、`C` 都可以，打印出来依然是 `<class '__main__.Human'>`——类名是传进去的字符串 `"Human"`。变量名最好也叫 `Human`，提示性更强。同理，`class Human:` 里的 `Human` 也只是一个指向类的变量名。

```python
C = type("Human", (object,), {})
print(C)          # 输出: <class '__main__.Human'>   类名来自字符串，与变量名无关
```

**总结**：`class` 关键字背后做的就是这四步：获取类名、获取基类、获取名称空间、调用元类。得到的类，其实就是元类实例化之后的对象。

分析完这四步并不是说以后不用 `class` 了，而是可以按需求**定制**这个过程。前三步（拿类名、拿基类、拿名称空间）没什么好控制的，主要研究**第四步**：拿到这三个数据后、调用元类实例化类时进行定制，比如把名称空间里的属性隐藏掉，或者要求类名不能有下划线、一写就报错。但第四步现在调用的是内置元类，内部发生的事无法控制；要控制它，就得**自定义元类**。


:::note[补充]
`type` 有两种用法：传1个参数 `type(obj)` 是查看对象类型；传3个参数 `type(name, bases, dict)` 是创建新类。`exec` 详细用法见第11章。
:::


### 3.3.3 自定义元类

没有指定元类时，类默认用内置元类。指定元类的写法是在括号里写关键字参数 `metaclass=`；如果还要继承其他父类，把父类写在前面，`metaclass` 放在最后即可：

```python
class Human(object, metaclass=type):   # 显式写出默认情况: 调用内置元类 type
    pass
```

想让第四步调用自己的元类，就自定义一个。注意：**只有继承了 `type` 的类才是元类**，所以自定义元类必须继承 `type`（元类本身又是怎么来的，不必再往深处研究）。

```python
class MyType(type):        # 必须继承 type
    pass


class Human(object, metaclass=MyType):
    def __init__(self, name, age):
        self.name = name
        self.age = age


print(type(Human))         # 输出: <class '__main__.MyType'>
```

现在 `class` 造 `Human` 仍是四步，只是第四步调用的是 `MyType`，实例化得到 `Human`。元类也是类，回忆类实例化的三步：

1. 先产生一个空对象——注意 `MyType` 的对象就是 `Human`
2. 调用 `__init__` 初始化这个对象。现在是调用 `MyType` 造 `Human`，所以调用的是 **`MyType` 的 `__init__`**
3. 返回初始化好的对象，也就是 `Human`

在 `MyType` 中定义一个只有 `self` 的 `__init__` 看看效果：

```python
class MyType(type):
    def __init__(self):
        print("MyType.__init__")


try:
    class Human(metaclass=MyType):
        pass
except TypeError as e:
    print(e)
# 输出: MyType.__init__() takes 1 positional argument but 4 were given
```

报错指向 `class Human` 这一行，也就是第四步调用 `MyType` 时出错：调用 `MyType` 会传入类名、基类、名称空间 3 个参数，并触发 `__init__`；`__init__` 是绑定方法，又会自动把空对象作为第一个参数传入，一共 4 个。而我们只定义了 `self` 一个形参。补上形参就不报错了：

```python
class MyType(type):
    def __init__(self, class_name, class_bases, class_dic):
        print("MyType.__init__ 被调用")


class Human(metaclass=MyType):
    pass
# 输出: MyType.__init__ 被调用
```

### 3.3.4 元类的 `__init__` 限制类定义

自定义元类之后能做的事就很多了。先学一个新关键字 **`raise`**：主动抛出一个异常。

```python
raise NameError("类名不能有下划线")
# 程序执行到这一行直接报错:
# NameError: 类名不能有下划线
```

`NameError` 就是一种错误类型。报错信息前面都会有类型，如 `TypeError`、`ValueError`、`IndexError`、`ImportError` 等，都可以用 `raise` 主动抛出。

class 造类的第四步已经被我们接管：调用自定义元类时会触发它的 `__init__`，传入 4 个参数——`self`（正在定义的类本身）、类名、基类、名称空间。有了这些就可以做各种限制。

**需求 1：类名不能有下划线。** 拿到 `class_name` 后判断即可。

**需求 2：定义类必须写文档注释。** 文档注释（三引号写的注释）也是类体代码的一部分，最终会进入名称空间 `class_dic`，键为 `__doc__`；删掉文档注释，`__doc__` 就没有了。所以用 `class_dic.get("__doc__")` 判断，没有就抛 `SyntaxError`。

```python
class MyType(type):
    def __init__(self, class_name, class_bases, class_dic):
        # 需求1: 类名不能有下划线
        if "_" in class_name:
            raise NameError("类名不能有下划线")
        # 需求2: 必须写文档注释
        if not class_dic.get("__doc__"):
            raise SyntaxError("定义类必须写注释")


class Human(metaclass=MyType):
    """测试元类"""

    def __init__(self, name, age):
        self.name = name
        self.age = age


print(Human.__doc__)              # 输出: 测试元类

try:
    class Hu_man(metaclass=MyType):   # 类名带下划线，定义时就报错
        """测试元类"""
except NameError as e:
    print("NameError:", e)        # 输出: NameError: 类名不能有下划线

try:
    class Student(metaclass=MyType):  # 没写文档注释
        pass
except SyntaxError as e:
    print("SyntaxError:", e)      # 输出: SyntaxError: 定义类必须写注释
```

在元类的 `__init__` 里，有定义的类本身、类名、基类、名称空间——类的所有数据都在这里，可以根据这四个参数做各种操作和限制。


:::note[补充]
`raise` 与异常处理的更多内容见第 12 章。
:::


### 3.3.5 `__new__` 方法

**引入**：用元类造类分三步——产生空对象、调用元类的 `__init__`、返回初始化好的对象（也就是类）。上一节定制了第二步，第一步"产生空对象"也一定触发了某个方法，它就是 **`__new__`**：调用类时**第一个**执行的方法，在 `__init__` 之前被调用。

即使不知道 `__new__`，也能推导出 `__init__` 之前一定还执行了别的代码。来看一个现象：

```python
class MyType(type):
    def __init__(self, class_name, class_bases, class_dic):
        print("class_bases 参数:", class_bases)
        print("self.__bases__:", self.__bases__)


class Human(metaclass=MyType):      # 没有写父类 object
    pass
# 输出:
# class_bases 参数: ()
# self.__bases__: (<class 'object'>,)
```

- 定义类时没写 `object`，传进来的 `class_bases` 就是空元组；写上 `(object, ...)` 才会有。它只是一个参数，你传它就有，不传就没有。
- 而 `self` 在 `MyType` 里，就是 `MyType` 的对象 `Human`；打印它的 `__bases__`，却已经继承了 `object`。

我们常说"Python 3 中类默认继承 `object`"，但这不是凭空继承来的，一定有代码做了这件事——而 `__init__` 收到的参数还是空的，说明在 `__init__` **之前**还有代码帮我们做了继承，这就是 `__new__`。

**`__new__` 必须返回对象**：在元类中定义 `__new__` 只打印、不返回，会发现 `__new__` 运行了，`__init__` 却没有运行。因为 `__new__` 是用来造空对象的，没返回就是没造出对象，第一步没完成就不会执行第二步。

```python
class MyType(type):
    def __new__(cls, *args, **kwargs):
        print("MyType.__new__")
        print(cls)       # 元类 MyType 本身
        print(args)      # class 机制第4步传进来的: (类名, 基类, 名称空间)
        print(kwargs)    # 按关键字传的参数，这里为空 {}
        # 没有 return，等于没造出对象

    def __init__(self, class_name, class_bases, class_dic):
        print("MyType.__init__")     # 不会执行


class Human(metaclass=MyType):
    pass
# 输出:
# MyType.__new__
# <class '__main__.MyType'>
# ('Human', (), {'__module__': '__main__', '__qualname__': 'Human', ...})
# {}
print(Human)          # 输出: None
```

参数说明：`cls` 是元类 `MyType` 本身；`args` 是 class 机制第四步按位置传进来的类名、基类（`Human` 没继承任何类，所以是空元组）、名称空间；`kwargs` 接收按关键字传的参数，这里都是按位置传，所以为空。

那怎么造 `MyType` 的对象（也就是 `Human` 类）呢？这涉及更底层的方法，没必要研究那么深。我们重写了 `__new__` 又没法自己造对象，就**调用父类（内置元类 `type`）的 `__new__`** 帮我们造，并把它的返回值作为我们的返回值。注意 `cls` 也要传：所有的自动传值都不是凭空来的，这里相当于在动底层代码，没有自动传参的说法，都得自己传。

```python
class MyType(type):
    def __new__(cls, *args, **kwargs):
        print("MyType.__new__: 产生空对象 Human")
        # 在这之前可以做各种定制
        return super().__new__(cls, *args, **kwargs)   # 也可以写 type.__new__(cls, *args, **kwargs)

    def __init__(self, class_name, class_bases, class_dic):
        print("MyType.__init__: 初始化 Human")
        print("self.__bases__:", self.__bases__)


class Human(metaclass=MyType):
    pass
# 输出:
# MyType.__new__: 产生空对象 Human
# MyType.__init__: 初始化 Human
# self.__bases__: (<class 'object'>,)
```

`type` 的 `__new__` 内部做了很多事：比如没有继承任何父类就让它继承 `object`，还会加入很多内置属性。这就解释了为什么在 `__init__` 中打印 `self.__bases__` 会看到自动继承了 `object`。这里 `super()` 和 `type` 两种写法都可以。

**总结 class 造类的步骤**：

1. 拿类名
2. 拿基类
3. 执行类体代码，产生名称空间
4. 调用元类：三个参数先传给元类的 `__new__`；`__new__` 造好空对象后，把空对象和这三个参数一起传给 `__init__` 进行初始化；最后返回初始化好的类


:::note[补充]
普通类同样有 `__new__`：创建对象时先由 `object.__new__` 造空对象，再调用 `__init__`。若 `__new__` 不返回本类的实例，`__init__` 不会执行。`__new__` 的典型用途有控制实例创建（如单例模式）、继承不可变类型（`int`、`str`、`tuple`）时修改其值。至于"是谁先调用 `__new__` 再调用 `__init__` 的"，答案是 `__call__`，见下节。
:::


## 3.4 `__call__` 与实例化控制

### 3.4.1 `__call__` 的引入

调用类的三个步骤中，前两步（`__new__` 造空对象、`__init__` 初始化）已经讲完，还剩第三步：初始化好的对象到底是在哪里被返回的？

如果调用 `MyType` 只是调用了 `__new__`，那返回值就是 `__new__` 的返回值，这很好理解。但事实并非如此——它调用了 `__new__` 之后还调用了 `__init__`。所以要思考两个问题：

1. 调用 `MyType` 之后的返回值到底是谁的返回值？
2. 为什么调用类会是"先 `__new__`、再 `__init__`、最后返回对象"这三步？

这些步骤一定不是凭空来的。Python 底层一定有一段代码在调用类的时候帮我们做了这三步，也就是说**调用 `MyType` 一定等价于调用了某个方法**，这个方法内部先调 `__new__`，再调 `__init__`，最后返回对象。这个方法就是 **`__call__`**。

### 3.4.2 `__call__` 让对象可调用

先把元类放一边，单独研究 `__call__`。定义一个类，加括号调用它得到对象 `obj`。类也是对象（元类造的对象），类这个对象能加括号调用，那 `obj` 这个对象能不能加括号调用？

```python
class Test:
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj = Test("张大仙", 73)
try:
    obj()
except TypeError as e:
    print(e)        # 输出: 'Test' object is not callable
```

报错说 `Test` 的对象不能调用。想让 `obj` 能加括号调用，就在它的类里加一个 `__call__` 方法：

```python
class Test:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __call__(self, *args, **kwargs):
        print("Test.__call__", args, kwargs)
        return "abc"


obj = Test("张大仙", 73)
res = obj(1, 2, 3, x=4, y=5)   # 对象加括号调用 -> 自动触发 __call__
print(res)
# 输出:
# Test.__call__ (1, 2, 3) {'x': 4, 'y': 5}
# abc
```

结论：

- `__call__` 是对象的绑定方法，触发条件是**对象加括号调用**
- 调用 `obj` 就是调用 `__call__`，所以 **`obj(...)` 的返回值就是 `__call__` 的返回值**
- 调用时自动把对象自己作为第一个参数传入，我们传的参数交给 `*args` 和 `**kwargs`（也可以单独设置形参）

**往上推一层**：`Test` 本身也是元类实例化的对象，它也能加括号调用，说明它的类（元类）里也一定有 `__call__`。再看用自定义元类 `MyType` 造出的 `Human`：`Human` 能加括号调用，说明 `MyType` 里有 `__call__`；我们没在 `MyType` 里定义它，就会去父类——内置元类 `type`——里找，最终找到 `type.__call__`。

而 class 机制的第四步是调用 `MyType(...)`，`MyType` 能加括号调用，说明 `MyType` 的类里也有 `__call__`：

```python
class MyType(type):
    pass


class Test:
    pass


print(type(MyType))       # 输出: <class 'type'>        MyType 由 type 造出
print(MyType.__bases__)   # 输出: (<class 'type'>,)     MyType 的基类也是 type
print(type(Test))         # 输出: <class 'type'>
print(Test.__bases__)     # 输出: (<class 'object'>,)
```

注意：**继承了谁，类型不一定就是谁**。`Test` 的基类是 `object`，但类型是 `type`——基类和类型是两回事。只是内置元类 `type` 比较特殊，往上分析，所有类最终都是由它造出来的。所以调用 `MyType`，就是调用 `MyType` 的类即 `type` 里的 `__call__`，最后返回 `Human`。

**谁加括号，触发谁的类里的 `__call__`**：

| 谁加括号调用 | 触发谁的 `__call__` |
|---|---|
| 对象 `obj()` | 对象的类 `Test` / `Human` 中的 `__call__` |
| 类 `Human()` | 类的元类（自定义元类 `MyType`）中的 `__call__` |
| 自定义元类 `MyType(...)` | 内置元类 `type` 中的 `__call__` |


:::note[补充]
内置函数 `callable(x)` 判断对象能否加括号调用。带 `__call__` 的对象也常用来写"有状态的函数"，如计数器、用类实现的装饰器。
:::


### 3.4.3 元类 `__call__` 控制实例化过程

自定义元类加括号调用时触发的是内置元类的 `__call__`，这个我们改不了。我们能控制的是两个地方：

- 用**自定义元类的 `__call__`** 定制**类加括号调用**（即控制对象的产生）
- 用**类的 `__call__`** 定制**对象加括号调用**

`Human` 造好之后，接下来要用 `Human("张大仙", 73)` 实例化对象。此时要控制的不再是 `Human` 的产生，而是 `Human` 的**对象**的产生：

- `MyType` 里的 `__new__`、`__init__` 是控制 `Human` 产生的：`MyType(...)` 触发 `type.__call__`，它调用 `MyType` 的 `__new__`、`__init__`，返回初始化好的 `Human`。这与 `obj` 的产生无关。
- `Human(...)` 加括号，触发的是 `Human` 的类即 **`MyType` 的 `__call__`**。它同样要做三件事：调用 `Human` 的 `__new__`、调用 `Human` 的 `__init__`、返回初始化好的对象。

先省略三件事，直接返回 `"abc"`，可以看到调用 `Human` 的返回值就是 `__call__` 的返回值：

```python
class MyType(type):
    def __call__(self, *args, **kwargs):
        return "abc"


class Human(metaclass=MyType):
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj = Human("张大仙", 73)
print(obj)        # 输出: abc
```

**完成三件事**：

- `self` 是谁？在哪个类里，`self` 就是哪个类的对象。现在在 `MyType` 里，`MyType` 的对象是 `Human`，所以 `self` 就是 `Human`。`args`、`kwargs` 就是调用 `Human(...)` 时传进来的参数——`__call__` 相当于 `Human` 的绑定方法，自动把 `Human` 作为第一个参数传入。
- **第一步**：调用 `self.__new__` 造空对象。`Human` 没定义 `__new__` 会去父类 `object` 里找；这里我们自己定义一个。`__new__` 是静态方法，`cls` 就是 `Human` 本身，我们不知道怎么造空对象，只能调用父类 `object` 的 `__new__`，**只需传 `cls` 一个参数**（这和造元类对象时不同：自定义元类的父类是 `type`，那里要调 `type.__new__` 并传类名等参数；而 `Human` 的父类是 `object`）。
- 注意在 `MyType.__call__` 中调用 `self.__new__(self)` 时**必须手动传 `self`**：这里是通过类 `Human` 访问其属性 `__new__`（一个静态方法），没有自动传参；只有对象调用绑定方法时才自动传 `self`。
- **第二步**：调用 `self.__init__(human_obj, *args, **kwargs)` 初始化。同样是类访问自己的函数，没有自动传参；`__init__` 里的 `self` 是 `Human` 的对象，把刚造好的空对象和参数传进去。
- **第三步**：返回初始化好的 `human_obj`。

```python
class MyType(type):
    def __call__(self, *args, **kwargs):
        print(self, args, kwargs)                  # self 是 Human
        # 第一步: 调用 Human 的 __new__ 造空对象（类访问静态方法，手动传 cls）
        human_obj = self.__new__(self)
        # 第二步: 调用 Human 的 __init__ 初始化对象
        self.__init__(human_obj, *args, **kwargs)
        # 第三步: 返回初始化好的对象
        return human_obj


class Human(metaclass=MyType):
    def __new__(cls, *args, **kwargs):
        print("Human.__new__")
        return super().__new__(cls)                # object.__new__ 只需要 cls

    def __init__(self, name, age):
        print("Human.__init__")
        self.name = name
        self.age = age


obj = Human("张大仙", 73)
print(obj.__dict__)
# 输出:
# <class '__main__.Human'> ('张大仙', 73) {}
# Human.__new__
# Human.__init__
# {'name': '张大仙', 'age': 73}
```

**定制对象属性**：流程清楚后，想在实例化（类加括号调用）过程中定制对象，就在元类的 `__call__` 里操作 `human_obj`。例如给 `Human` 所有对象的属性名都加前缀 `H_`：遍历原 `__dict__`，把拼接后的新属性名和原值放进新字典，再用新字典覆盖 `human_obj.__dict__`。

```python
class MyType(type):
    def __call__(self, *args, **kwargs):
        human_obj = self.__new__(self)
        self.__init__(human_obj, *args, **kwargs)
        # 定制: 所有属性名加上 H_ 前缀
        dic = {}
        for key in human_obj.__dict__:
            dic["H_" + key] = human_obj.__dict__[key]
        human_obj.__dict__ = dic
        return human_obj


class Human(metaclass=MyType):
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj = Human("张大仙", 73)
print(obj.__dict__)    # 输出: {'H_name': '张大仙', 'H_age': 73}
```

定制对象共有**三个地方**：元类的 `__call__`、类的 `__new__`、类的 `__init__`（因为 `__call__` 调用的就是后两者）。

另外，如果 `Human` 里也定义了 `__call__`，它只在 `Human` 的**对象** `obj` 加括号调用时才触发；想让 `obj()` 做一些操作，就写在那里。

**完整串起来**：

| 时机 | 触发的方法 |
|---|---|
| 定义类 `class Human(metaclass=MyType)` | `MyType(...)` → `type.__call__` → `MyType.__new__` + `MyType.__init__` |
| 调用类 `Human(...)` | `MyType.__call__` → `Human.__new__` + `Human.__init__` |
| 调用对象 `obj(...)` | `Human.__call__` |

### 3.4.4 属性查找

已知的查找顺序是：对象 → 类 → 父类 → ... → `object`，都没有就报错。学了元类后要注意：**父类和元类是两个东西**。

示例结构：`obj` 由 `ScPerson` 实例化；`ScPerson` 继承 `Chinese`；`Chinese` 的元类是 `MyType`（`MyType` 继承 `type`），`Chinese` 的父类是 `Human`；`Human` 继承 `Animal`，`Animal` 最终继承 `object`。每个类里都定义一个 `age` 属性：

```python
class MyType(type):
    age = 18


class Animal:
    age = 17


class Human(Animal):
    age = 16


class Chinese(Human, metaclass=MyType):
    age = 15


class ScPerson(Chinese):
    age = 14


obj = ScPerson()

# 依次删除各类的 age，观察查找结果
print(obj.age, ScPerson.age)   # 输出: 14 14
del ScPerson.age
print(obj.age, ScPerson.age)   # 输出: 15 15
del Chinese.age
print(obj.age, ScPerson.age)   # 输出: 16 16
del Human.age
print(obj.age, ScPerson.age)   # 输出: 17 17
del Animal.age
print(ScPerson.age)            # 输出: 18   通过类查找，父类都没有时会去元类找
try:
    print(obj.age)             # 通过对象查找，到 object 就停止，不会找元类
except AttributeError as e:
    print("报错:", e)
```

**结论**：

- **通过对象**找属性：对象 → 类 → 父类 → `object`，到 `object` 为止，**不会**去元类找
- **通过类**找属性：先顺着父类路线找，所有父类（包括 `object`）都没有时，**最后会去元类找**

可以把继承关系画在一条虚线下面、元类画在虚线上面：对象只在虚线下面找，类会找到虚线上面的元类。

**元类会被子类继承**：只有 `Chinese` 指定了元类，但继承它的 `ScPerson` 的元类也是 `MyType`；而 `Human` 及其父类没用自定义元类，默认是内置元类 `type`。即**只要父类使用了自定义元类，所有继承它的子类都会使用这个元类**。

```python
# 接上例
print(type(Chinese))    # 输出: <class '__main__.MyType'>
print(type(ScPerson))   # 输出: <class '__main__.MyType'>
print(type(Human))      # 输出: <class 'type'>
```

**回到元类的 `__call__`**：`ScPerson()` 触发的是 `MyType.__call__`，其中的 `self` 就是 `ScPerson`。`self.__new__` 会按属性查找顺序往上找，这些类都没写 `__new__`，最终找到 `object.__new__`。

虽然这里两者是同一个东西，但在 `__call__` 里**最好用 `self.__new__`，不要直接写 `object.__new__`**：通过 `self` 调用会有查找过程，把中间继承的每个类都找一遍；直接用 `object.__new__` 就跳过了查找，以后在 `ScPerson` 或其他父类里自定义的 `__new__` 就毫无意义了。


:::tip[技巧]
可以用 `ScPerson.__mro__` 查看"继承层"的查找顺序；类查找属性时先走完 MRO，再到元类（及元类的父类 `type`）中查找。
:::


## 3.5 单例模式

### 3.5.1 单例模式概述

**单例模式（Singleton）**：一种软件设计模式，目的是**保证某一个类只能有一个实例对象存在**。

**为什么需要**：如果用同一个类产生很多对象，而这些对象只是为了执行某一个或某几个功能，频繁创建和销毁对象就浪费内存资源。单例模式只允许内存中有一个实例，减少了内存消耗，在频繁创建销毁对象、性能又不好优化时优势明显。

实现单例模式大概有五种方式：

1. 模块导入（最简单，**用得最多**）
2. 类装饰器
3. 类的绑定方法（类方法）
4. `__new__` 方法
5. 元类

后四种在面试中问得比较多。

### 3.5.2 方式一：模块导入

**Python 模块就是天然的单例模式**。模块只在第一次导入时执行，之后的导入直接使用缓存（`sys.modules`）。

把类和实例化好的对象放进一个模块（如 `settings.py`），其他地方直接导入这个对象，不管导入多少次，用到的都是同一个对象。

```python
# settings.py
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj = Human("张大仙", 73)
```

```python
# 其他文件中使用
from settings import obj      # 无论在哪里导入多少次，都是同一个 obj
```

### 3.5.3 方式二：类装饰器

以前的装饰器都用来装饰函数，其实装饰类也一样：函数能加括号调用，类也能加括号调用。`@singleton_mode` 写在类头顶，就相当于 `Human = singleton_mode(Human)`。参数接收的是类，所以不再叫 `func`，改叫 `cls`。

在外层先定义 `obj = None`，内层判断：如果 `obj` 为 `None`，就正常调用类产生对象并保存到这个变量。内层函数要修改外层的 `obj`，必须用 **`nonlocal`** 声明，否则只是在内层新建了一个局部变量。

```python
def singleton_mode(cls):
    obj = None

    def wrapper(*args, **kwargs):
        nonlocal obj                     # 修改外层函数的 obj
        if not obj:                      # 还没有对象，才调用类产生对象
            obj = cls(*args, **kwargs)
        return obj

    return wrapper


@singleton_mode                          # Human = singleton_mode(Human)
class Human:
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj1 = Human("张大仙", 73)
obj2 = Human("张大仙", 75)
print(obj1 is obj2)       # 输出: True
```

### 3.5.4 方式三：类方法

给类定义一个类属性 `obj = None`，再定义一个类方法 `get_obj`：在里面通过 `cls(*args, **kwargs)` 造对象并赋给 `cls.obj`，最后返回 `cls.obj`。为了实现单例，要先判断：类属性为 `None` 说明还没创建对象，才去创建；已经有对象就直接返回已存在的对象。

```python
class Human:
    obj = None

    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def get_obj(cls, *args, **kwargs):
        if not cls.obj:                    # 还没有创建过对象
            cls.obj = cls(*args, **kwargs)
        return cls.obj


obj1 = Human.get_obj("张大仙", 73)
obj2 = Human.get_obj("张大仙", 75)
print(obj1 is obj2)       # 输出: True
```


:::warning[注意]
用这种方式造对象时不能直接 `Human(...)`，必须通过 `Human.get_obj(...)` 才有单例效果。
:::


### 3.5.5 方式四：`__new__`

改回正常的 `Human(...)` 调用，把 `get_obj` 换成 `__new__`。在 `__new__` 里**不能直接 `cls(...)`**：类加括号会触发元类的 `__call__`，`__call__` 又会调用当前类的 `__new__`，就变成无限递归了。前面说过，在 `__new__` 里我们并不知道怎么造对象，只能调用父类的 `__new__`，把 `cls` 传给它。

```python
class Human:
    obj = None

    def __new__(cls, *args, **kwargs):
        if not cls.obj:
            cls.obj = super().__new__(cls)    # 调用父类 object 的 __new__ 造空对象
        return cls.obj

    def __init__(self, name, age):
        self.name = name
        self.age = age


obj1 = Human("张大仙", 73)
obj2 = Human("张大仙", 75)
print(obj1 is obj2)       # 输出: True
print(obj1.age)           # 输出: 75
```


:::warning[注意]
这种写法中 `__init__` 每次调用都会重新执行，所以上例中 `obj1.age` 最终是 `75`。
:::


### 3.5.6 方式五：元类

定义元类 `MyType(type)`，把 `obj = None` 放到元类里。`Human(...)` 造对象触发的是元类的 `__call__`，在里面判断 `if not self.obj`：`self` 是 `Human`，`Human` 自己没有 `obj`，父类 `object` 也没有，最后会去元类找（3.4.4 节的查找顺序），所以能找到。为 `None` 时就正常调用父类（`type`）的 `__call__`，得到初始化好的对象，赋给 `self.obj`。

注意 `self.obj = ...` **不是修改元类的 `obj` 属性**：`self` 是 `Human`，所以这是给 `Human` 添加了一个 `obj` 属性；下次调用 `Human` 时，找到的就是 `Human` 自己的 `obj`。`obj` 也可以放到 `Human` 里，但它只是为了实现单例，和 `Human` 本身的功能关系不大，最好放在元类里。

```python
class MyType(type):
    obj = None

    def __call__(self, *args, **kwargs):
        if not self.obj:                                 # Human -> object -> 元类 MyType 中找到 obj
            self.obj = super().__call__(*args, **kwargs)  # 给 Human 添加 obj 属性
        return self.obj


class Human(metaclass=MyType):
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj1 = Human("张大仙", 73)
obj2 = Human("张大仙", 75)
print(obj1 is obj2)       # 输出: True
print(obj1.__dict__)      # 输出: {'name': '张大仙', 'age': 73}
```

除了直接调用父类的 `__call__`，也可以自己做三步：`self.__new__(self)` 造空对象，`self.__init__(self.obj, *args, **kwargs)` 初始化，最后返回。其中初始化这一步可以**不放在判断里**：第二次调用时不会再造新对象，但会重新执行 `__init__`，相当于给原来的对象重新初始化属性。放在判断里面还是外面看需求。

```python
class MyType(type):
    obj = None

    def __call__(self, *args, **kwargs):
        if not self.obj:
            self.obj = self.__new__(self)           # 第一步: 只在第一次造空对象
        self.__init__(self.obj, *args, **kwargs)    # 第二步: 放在判断外，每次都重新初始化
        return self.obj                             # 第三步: 返回对象


class Human(metaclass=MyType):
    def __init__(self, name, age):
        self.name = name
        self.age = age


obj1 = Human("张大仙", 73)
print(obj1.__dict__)      # 输出: {'name': '张大仙', 'age': 73}
obj2 = Human("张大仙", 75)
print(obj2.__dict__)      # 输出: {'name': '张大仙', 'age': 75}
print(obj1 is obj2)       # 输出: True
```

**很多类都要做成单例**时，每个类都写 `metaclass=MyType` 比较麻烦。可以定义一个使用该元类的父类，什么都不用写，让其他类继承它即可——前面讲过，父类用了自定义元类，所有子孙类创建时都会用这个元类。

```python
class MyType(type):
    obj = None

    def __call__(self, *args, **kwargs):
        if not self.obj:
            self.obj = super().__call__(*args, **kwargs)
        return self.obj


class Meta(metaclass=MyType):    # 公共父类，什么都不用写
    pass


class Human(Meta):
    def __init__(self, name, age):
        self.name = name
        self.age = age


print(Human("张大仙", 73) is Human("张大仙", 75))   # 输出: True
```

**`None` 就是单例**：代码里用到的所有 `None` 都是同一个对象。这也是为什么判断时推荐写 `x is None` 而不是 `x == None`——`None` 只有一个对象，只要变量指向 `None`，就一定是同一个对象。


:::note[补充]
上面的示例用 `if not obj` 判断。若对象自身可能为"假"（如定义了 `__len__` 返回 0），更严谨的写法是 `if obj is None`。多线程环境下"判断为空再创建"可能被两个线程同时通过，需要加锁（`threading.Lock`）。
:::


## 本章小结

- **反射机制**：动态语言的关键特性，程序运行中动态获取对象信息、动态调用方法；通过 `dir` 查看属性列表，`hasattr`、`getattr`、`setattr`、`delattr` 操作属性
- **魔法方法**：双下划线包围，特定条件自动触发；`__str__` 定制打印（必须返回字符串），`__del__` 在对象删除前触发（用于释放系统资源）
- **元类**：类也是对象，由元类实例化产生；`type` 是内置元类；`class` 四步骤为拿类名、拿基类、拿名称空间、调用元类
- **自定义元类**：必须继承 `type`，通过 `metaclass=` 指定；在 `__init__` 中限制类定义（配合 `raise`），在 `__new__` 中控制类创建（必须返回对象）
- **`__call__`**：对象加括号调用时触发，返回值就是调用结果；谁加括号触发谁的类里的 `__call__`；元类 `__call__` 控制类实例化（`__new__` → `__init__` → 返回对象）
- **属性查找**：对象查到 `object` 为止（不到元类），类在父类都没有时查元类；元类会被子类继承；在 `__call__` 中用 `self.__new__` 而非 `object.__new__`
- **单例模式**：五种实现方式——模块导入（最常用）、类装饰器（`nonlocal`）、类方法（需通过 `get_obj` 调用）、`__new__`（`__init__` 每次都执行）、元类（最灵活，可配合公共父类）
