## 11.1 time 模块：时间的三种形式

`time` 和 `datetime` 都是内置模块，`import` 进来就能用。但它们的功能都建立在**时间的三种形式**之上，先把这个概念弄清。
时间有三种形式，用途各不相同：

- 时间戳（timestamp）：从 1970-01-01 00:00:00 UTC 到现在的秒数，float 类型，用来**算时间间隔**
- 格式化字符串（format string）：按指定格式显示的字符串，如 `2026-10-13 19:18:00`，用来展示时间
- 结构化时间（struct_time）：含年月日时分秒等字段的对象，用来单独取出年、月、日、星期等整型值

```python
import time

# 第一种：时间戳
print(time.time())                            # 例如: 1791890296.8044925

# 第二种：格式化字符串
print(time.strftime('%Y-%m-%d %H:%M:%S'))     # 例如: 2026-10-13 19:18:16

# 第三种：结构化时间
res = time.localtime()
print(res)                                    # time.struct_time(tm_year=2026, tm_mon=10, tm_mday=13, ...)
print(res.tm_year, res.tm_mon, res.tm_mday)   # 例如: 2026 10 13
```

**为什么时间戳最适合算间隔？** 因为它就是一个纯数字，加减法、比较大小都直接可用。装饰器里统计函数耗时用的就是它。
```python
import time

start = time.time()
time.sleep(1)                 # 暂停 1 秒
stop = time.time()
print(stop - start)           # 例如: 1.0005，即中间经过的秒数
```

**为什么还需要结构化时间？** 格式化字符串虽然也能取到年份（用 `%Y`），但拿到的是字符串；结构化时间拿到的是整型，可以直接参与计算和比较。
**时间戳的起点 1970-01-01 00:00:00 被称为「Unix 纪元」（epoch）。** `time.time()` 返回的是 UTC 时间戳，所以它在世界各地都一样；而 `localtime()` 拿到的是本地时区的时间，两者会差一个时区偏移量。
### 11.1.1 格式化字符串：strftime

`strftime` 用百分号占位符控制时间显示格式，常用的格式符如下。
**年、月、日、时、分、秒**：`%Y` 四位数年份、`%m` 月份（`10`）、`%d` 这个月的第几天、`%H` 小时（24 小时制）、`%M` 分钟、`%S` 秒。
**星期与其它**：`%A` 星期英文全称（如 `Tuesday`）、`%a` 星期英文缩写（如 `Tue`）、`%w` 星期数字（周日为 0）、`%j` 一年中的第几天（`286`）、`%p` 上午/下午（`AM` / `PM`）。
**两个组合符**：`%X` 等价于 `%H:%M:%S`，`%x` 是默认格式的日期（如 `10/13/26`），`%%` 表示一个百分号本身。
```python
import time

print(time.strftime('%Y-%m-%d %H:%M:%S'))     # 例如: 2026-10-13 19:18:16
print(time.strftime('%Y-%m-%d %X'))           # %X 即时分秒，结果同上
print(time.strftime('%x'))                    # 输出: 10/13/26
print(time.strftime('%A'))                    # 输出: Tuesday
print(time.strftime('%Y-%m-%d %H:%M:%S %A'))  # 例如: 2026-10-13 19:18:16 Tuesday
```


:::warning[注意]
`%x` 和 `%X` 是**系统本地默认格式**，Windows 中文环境下 `%x` 是 `10/13/26`、`%X` 是 `19:18:16`；换成别的系统或区域设置可能不一样。要固定格式，就自己把 `%Y-%m-%d` 这类占位符写全。
:::

`strftime` 的 **f 是 format**（格式化），`strptime` 的 **p 是 parse**（解析），一个"格式化出去"、一个"解析进来"，靠这个字母就能记住谁是谁。
### 11.1.2 结构化时间的字段

`time.localtime()` 返回 `struct_time`，常用字段如下。

- `tm_year` 年，`tm_mon` 月（month 缩写），`tm_mday` 一个月中的第几号
- `tm_hour` / `tm_min` / `tm_sec` 时 / 分 / 秒
- `tm_wday` 一周中的第几天，从 0 开始，周一为 0、周日为 6
- `tm_yday` 一年中的第几天，`tm_isdst` 是否夏令时（一般用不到）

### 11.1.3 三种形式的相互转换

**关键结论：时间戳和格式化字符串不能直接互转，必须经过结构化时间过渡。**

```text
             localtime / gmtime                 strftime
  时间戳  ----------------------->  结构化时间  ----------------->  格式化字符串
          <-----------------------              <-----------------
                   mktime                           strptime
```

**时间戳 → 结构化时间：`localtime` / `gmtime`。** 不传参数时转换当前时间；传一个秒数则转换那个时间点。
```python
import time

print(time.localtime(time.time()))   # 当前时间戳 -> 本地结构化时间
print(time.localtime(111111111))     # 自己写的时间戳，北京时间: 1973-07-10 08:11:51
print(time.gmtime(111111111))        # 世界标准时间: 1973-07-10 00:11:51，相差 8 小时
```

`gmtime` 的参数和 `localtime` 一样，区别只是返回 **UTC 世界标准时间**。以伦敦格林尼治天文台的本初子午线为零度线，向西、向东各划出 12 个时区，相邻时区相差 1 小时；我国（北京时间）在东八区，比世界标准时间**快 8 小时**——伦敦还是 0 点时，我们已经是早上 8 点。
**结构化时间 → 格式化字符串：`strftime`。** 只传格式字符串时默认转换当前时间，传入第二个参数（结构化时间）就转换指定的时间。
```python
import time

res = time.localtime(111111111)
print(time.strftime('%Y-%m-%d %H:%M:%S'))         # 当前时间
print(time.strftime('%Y-%m-%d %H:%M:%S', res))    # 输出: 1973-07-10 08:11:51
```

**格式化字符串 → 结构化时间：`strptime`。** 第一个参数是要转换的字符串，第二个参数用百分号写出它对应的格式，这样它才知道哪部分是年、哪部分是月。
```python
import time

t = '1983-12-07 01:02:02'
print(time.strptime(t, '%Y-%m-%d %H:%M:%S'))
# 输出: time.struct_time(tm_year=1983, tm_mon=12, tm_mday=7, tm_hour=1, tm_min=2, tm_sec=2, tm_wday=2, tm_yday=341, tm_isdst=-1)
print(time.strptime(t, '%Y-%m-%d %X'))     # 时分秒也可以写成 %X
```

**结构化时间 → 时间戳：`mktime`。**

```python
import time

res = time.strptime('1983-12-07 01:02:02', '%Y-%m-%d %H:%M:%S')
print(time.mktime(res))     # 输出: 439578122.0
```


:::warning[注意]
转换时**字符串与格式必须一一对应**，否则会报 `ValueError`。比如 `time.strptime('1983-12-07', '%Y/%m/%d')` 会因为分隔符不一致而失败。
:::

### 11.1.4 应用场景：会员续费

用户购买了 7 天 VIP，我们把到期时间算出来存进文件；用户又续了一个月时，需要把时间从文件读出来——读出来的是字符串而不是时间对象。
这时只能走"字符串 → 结构化 → 时间戳 → 加秒数 → 再转回字符串"这条路：

```python
import time

fmt = '%Y-%m-%d %H:%M:%S'
expire = '2026-10-17 10:00:00'                           # 从文件中读出的到期时间

ts = time.mktime(time.strptime(expire, fmt))             # 字符串 -> 结构化 -> 时间戳
ts += 30 * 24 * 60 * 60                                  # 加上 30 天的总秒数
print(time.strftime(fmt, time.localtime(ts)))            # 输出: 2026-11-16 10:00:00
```

`asctime()` 用固定格式输出当前时间（如 `Tue Oct 13 19:18:16 2026`），`ctime(时间戳)` 直接把时间戳转成这种固定格式的字符串。这两个用得不多，主要原因是**不能自定义格式**。

:::warning[注意]
Python 3.12 起 `datetime.datetime.utcnow()` 已被弃用（会给出 `DeprecationWarning`），推荐写 `datetime.datetime.now(datetime.timezone.utc)`。
:::

## 11.2 datetime 模块：可读时间与时间加减

时间戳用法简单但不可读，格式化字符串可读但每次都要写一大堆百分号。`datetime` 模块同时解决了这两个问题。
```python
import datetime

res = datetime.datetime.now()
print(res)                          # 例如: 2026-10-13 19:18:26.777486

# 最后一段是微秒，不想要可以用 replace 把 microsecond 设为 0
print(res.replace(microsecond=0))   # 例如: 2026-10-13 19:18:26
print(datetime.date.today())        # 输出: 2026-10-13，只有日期
print(datetime.time(11, 30, 25))    # 输出: 11:30:25，只有时间
```

注意这里的 `replace` 和字符串的 `replace` 不是一回事，它是 `datetime` 类自己定义的方法。
**`datetime` 既是模块名也是模块中的类名**，所以 `import datetime` 后要写 `datetime.datetime.now()`；也可以 `from datetime import datetime` 后直接写 `datetime.now()`。
### 11.2.1 timedelta 做时间加减

**结论：`datetime` 对象可以直接加、减一个 `timedelta`，这是它比 `time` 模块最方便的地方。**

`timedelta` 的参数有周（weeks）、天（days）、小时（hours）、分钟（minutes）、秒（seconds）、毫秒（milliseconds）、微秒（microseconds），最常用的是天。
```python
import datetime

now = datetime.datetime.now()

# 用户充值了 7 天会员，计算到期时间（之后写进数据库）
print(now + datetime.timedelta(days=7))

print(now + datetime.timedelta(days=25))     # 25 天后
print(now + datetime.timedelta(days=-25))    # 25 天前
print(now - datetime.timedelta(days=25))     # 同样是 25 天前

print(now + datetime.timedelta(weeks=2))     # 2 周后，即 14 天后

# 没有"年"的参数，按一年 365 天自己乘
print(now + datetime.timedelta(days=365 * 5))   # 约 5 年后

delta = datetime.timedelta(days=5, hours=13, minutes=2, seconds=1, weeks=1)
print(delta)                  # 输出: 12 days, 13:02:01
print(delta.days)             # 输出: 12
print(delta.total_seconds())  # 输出: 1083721.0，换算成总秒数
```

`timedelta` **只保存 `days`、`seconds`、`microseconds` 三个"规整后"的单位**，`weeks`、`hours` 等都会先折算进去。所以 `1 周 5 天 13 小时` 打印出来是 `12 days, 13:02:01`，而不是 `1 week, 5 days`。
减时间常用于查询数据：要查最近 10 天的数据，就把当前时间减 10 天，再筛选出所有时间大于这个节点的记录。

:::warning[注意]
`timedelta` 没有 `months`、`years` 参数。因为每月天数不固定，按 365 天算年份跨闰年会差一天。需要精确按月、按年加减，可以用第三方库 `python-dateutil` 的 `relativedelta`。
:::

### 11.2.2 与字符串、时间戳的互转

`datetime` 对象可以和各处得到的字符串、时间戳互相转换，这几个方法最适合背下来。
```python
import datetime

fmt = '%Y-%m-%d %H:%M:%S'
d = datetime.datetime.strptime('2026-10-13 12:00:00', fmt)   # 字符串 -> datetime
print(d, type(d))                 # 输出: 2026-10-13 12:00:00 <class 'datetime.datetime'>

print(d.strftime(fmt))            # datetime -> 字符串，输出: 2026-10-13 12:00:00
print(d.timestamp())              # datetime -> 时间戳，输出: 1791864000.0
print(datetime.datetime.fromtimestamp(111111111))   # 时间戳 -> datetime，输出: 1973-07-10 08:11:51

# 取年月日时分秒、星期
print(d.year, d.month, d.day, d.hour, d.minute, d.second)   # 输出: 2026 10 13 12 0 0
print(d.weekday(), d.isoweekday())   # 输出: 1 2   —— weekday 从 0 开始（周一为 0），isoweekday 从 1 开始

# 两个日期相差多少天
print(datetime.date(2027, 10, 13) - datetime.date(2026, 10, 13))   # 输出: 365 days, 0:00:00
```

- `datetime.strptime(s, fmt)`：字符串 → datetime，必须给出格式
- `d.strftime(fmt)`：datetime → 字符串，必须给出格式
- `d.timestamp()`：datetime → 时间戳；`datetime.fromtimestamp(ts)`：时间戳 → datetime
- `datetime.date.today()`：直接得到今天的日期
- `d.weekday()` / `d.isoweekday()`：星期几，分别从 0 / 1 开始

`strptime` 是 `datetime` 的类方法，要用 `datetime.datetime.strptime(...)` 调用；而 `strftime`、`timestamp` 是实例方法，得先有对象再调用。
## 11.3 random 模块：随机数

`random` 是内置模块，用来生成随机数。传参时注意 `randint` 和 `randrange` 的区间差别：

- `random()`：随机小数，不用传参，范围 `[0, 1)`
- `uniform(a, b)`：随机小数，范围 `a~b`
- `randint(a, b)`：随机整数，闭区间，两端都包含
- `randrange(a, b)`：随机整数，顾头不顾尾，取不到 `b`
- `choice(seq)`：从序列中随机取一个元素（字符串、列表、元组、range 都可以）
- `sample(seq, k)`：一次随机取 k 个，返回列表，取 1 个也是列表
- `shuffle(lst)`：原地打乱顺序，只能用于可变类型

```python
import random

print(random.random())             # 例如: 0.6394267984578837，0 到 1 的小数
print(random.uniform(1, 10))       # 例如: 6.3702679851883735，1 到 10 的小数
print(random.randint(-100, 100))   # 例如: 42，两端都能取到
print(random.randrange(1, 3))      # 只会是 1 或 2，取不到 3

lst = ['梦泪', 18, ('抽烟', '喝酒', '烫头')]
print(random.choice(lst))          # 例如: 梦泪
print(random.sample(lst, 2))       # 例如: [18, ('抽烟', '喝酒', '烫头')]
print(random.sample(lst, 1))       # 只取 1 个，仍然是列表，例如: ['梦泪']

l1 = [1, 3, 5, 7, 9]
random.shuffle(l1)
print(l1)                          # 例如: [7, 1, 9, 5, 3]
```

**注意：`randint(a, b)` 是闭区间，`randrange(a, b)` 是左闭右开，两者差的就是 `b` 本身**，这也是最常考的对比点。
`random` 生成的是伪随机数（由种子推出来），用于抽奖、发牌没问题，但**不能用于密码、令牌等安全场景**。这类需求应使用内置模块 `secrets`，如 `secrets.token_hex(16)`。
### 11.3.1 实战：随机密码生成器

**题目：随机生成一个 16 位密码，必须包含大写字母、小写字母、数字和符号。**

思路是循环 16 次，每次从四类字符中随机挑一个拼上去。手写 a~z、A~Z、0~9 和一堆符号太笨了——回忆字符编码：**每个字符在编码表中都对应一个数字**，只要知道每类字符的数字范围，在范围里随机取一个数，再用 `chr` 转成字符即可。
数字与字符的互转靠两个内置函数：`chr(97)` 得到 `a`，`ord('a')` 得到 `97`。四类字符在 ASCII 表中的范围是：

- 小写字母 a~z：97~122
- 大写字母 A~Z：65~90
- 数字 0~9：48~57
- 符号：33~47（还有其它符号区段，需要可以再加）

步骤只有三步：先用 `random.choice(char_list)` 随机选出一类字符（结果是一个 `[起, 止]` 范围）；再用 `random.randint(*char_range)` 在这个范围内随机取一个整数——`*` 用在实参里是打散，等价于写 `char_range[0], char_range[1]`；最后用 `chr` 把数字转成字符，拼到 `pwd` 上。
循环变量用不到时，按规范写成下划线 `_`。把长度做成参数并给默认值 16：

```python
import random


def pwd_gen(n=16):
    """随机生成长度为 n 的密码"""
    # 四类字符在编码表中的范围：小写字母、大写字母、数字、符号
    char_list = [[97, 122], [65, 90], [48, 57], [33, 47]]
    pwd = ''
    for _ in range(n):
        char_range = random.choice(char_list)            # 随机选一类
        pwd += chr(random.randint(*char_range))          # 在范围内取数字再转字符
    return pwd


print(pwd_gen())     # 例如: jUo2Y8/,RLeI3,Db
print(pwd_gen(8))    # 例如: I8M05Ww/
```

### 11.3.2 保证四种字符都出现

上面的函数有个问题：只传 6 位多跑几次，会发现有时密码里只有三种甚至两种字符（比如一个符号都没有）。
**方法一：生成后检查，不合法就重新生成。** 长度小于 4 时不可能满足要求，直接返回空字符串；否则用一个标记列表，遍历密码、用 `ord` 判断每个字符落在哪个范围，四个标记全为 `True` 才算合格。
```python
import random


def pwd_gen_retry(n=16):
    if n < 4:                                        # 少于 4 位不可能包含四种字符
        return ''
    char_list = [[97, 122], [65, 90], [48, 57], [33, 47]]
    while True:
        pwd = ''
        for _ in range(n):
            pwd += chr(random.randint(*random.choice(char_list)))

        flags = [False] * 4                          # 分别标记：小写、大写、数字、符号
        for c in pwd:
            num = ord(c)
            if 97 <= num <= 122:
                flags[0] = True
            elif 65 <= num <= 90:
                flags[1] = True
            elif 48 <= num <= 57:
                flags[2] = True
            elif 33 <= num <= 47:
                flags[3] = True

        if all(flags):                               # 也可以用 flags[0] and flags[1] and ...
            return pwd
        print('密码不合法')


print(len(pwd_gen_retry(6)))    # 输出: 6（可能先打印几次"密码不合法"）
```

**方法二：一步到位。** 每轮把四种字符各取一个，循环 `n // 4 + 1` 次（多循环一次，因为长度可能不是 4 的倍数），凑够后切片切掉多余字符，洗牌打乱顺序再拼成字符串。
```python
import random


def pwd_gen_fast(n=16):
    if n < 4:
        return ''
    char_list = [[97, 122], [65, 90], [48, 57], [33, 47]]
    chars = []
    for _ in range(n // 4 + 1):
        for char_range in char_list:                 # 四种字符每种各取一个
            chars.append(chr(random.randint(*char_range)))
    chars = chars[:n]                                # 切掉多出来的字符
    random.shuffle(chars)                            # 洗牌打乱顺序
    return ''.join(chars)


print(len(pwd_gen_fast(8)))    # 输出: 8
```

两种方法各有缺点：方法一判断多，可能反复重新生成；方法二生成的密码有规律，例如 8 位密码一定是四种字符各两个。
**方法三（两者结合）：** 先四种字符各取一个，保证一定包含四种字符，剩下的位数用方法一的方式随机取，最后洗牌。这样既不用失败重试，也没有固定配比的规律。这个留作练习（见本章练习 4）。
## 11.4 os 模块：文件与目录操作

`os` 是 Operating System（操作系统）的缩写，**`os` 模块提供的就是 Python 程序与操作系统交互的接口**——创建目录、删除文件、重命名、获取文件信息、执行终端命令等。
它还能极大增强代码的可移植性：用 `os.path.dirname` 动态获取项目根目录，同样的代码拿到 Linux 上运行也没有任何问题，`os` 模块不受平台限制。
常用的目录与文件操作如下：

- `os.getcwd()`：获取当前工作目录；默认和 `sys.path` 的第一个值一样，即执行文件所在目录
- `os.chdir(路径)`：切换工作目录，相当于在 cmd 里敲 `cd 路径`
- `os.listdir(路径)`：获取目录下所有文件和文件夹（包括隐藏文件），返回列表；不传路径时为当前工作目录
- `os.mkdir(路径)`：创建单层文件夹；已存在时再创建会报错
- `os.makedirs(路径)`：创建多层文件夹（如 `a\b\c`）
- `os.remove(路径)`：删除一个文件，删不了文件夹
- `os.rmdir(路径)`：删除单级空目录，里面不能有任何东西，连空的子文件夹都不行
- `os.rename(旧, 新)`：重命名文件或文件夹
- `os.system(命令)`：执行终端命令

```python
import os

print(os.getcwd())          # 例如: D:\teach

os.mkdir('data')            # 相对路径，基于当前工作目录
os.chdir('data')            # 相当于 cd data
print(os.listdir())         # data 下所有名字
print(os.listdir('..'))     # '..' 是上一层目录
os.chdir('..')

os.makedirs(r'test1\test2\test3', exist_ok=True)   # 一次创建多层，路径前加 r 防止转义
print(os.listdir('test1'))  # 输出: ['test2']

with open(r'test1\aa.txt', mode='wt', encoding='utf-8') as f:
    f.write('hi')
os.remove(r'test1\aa.txt')  # 删除文件
os.rename('test1', 'test_one')   # 重命名
print(os.path.exists('test_one'))   # 输出: True
```

所有能传路径的参数都可以传绝对路径；上面为了演示用的是相对路径，即基于当前工作目录（`os.getcwd()` 拿到的那个目录）。
`os.makedirs(路径, exist_ok=True)` 在文件夹已存在时不报错，写脚本时建议都带上。另外 `os.rmdir` 只能删空目录，要删整棵目录树得用 `shutil.rmtree`（见 11.7）。
### 11.4.1 os.system 与乱码

`os.system` 可以执行任何终端命令。Windows 上的 `tree` 命令会以当前工作目录为起点，把所有文件夹以树形结构显示出来：

```python
import os

os.system('tree')    # 在 PyCharm 中运行可能出现乱码
```

**为什么乱码？** PyCharm 默认用 UTF-8 解码，而 `tree` 调用的是系统功能，中文版 Windows 的编码是 GBK（代码页 936）。解决办法有两种：改 PyCharm 的编码（`File → Settings → Editor → File Encodings` 改成 GBK），或改 Windows 的系统编码（勾选「Beta：使用 Unicode UTF-8 提供全球语言支持」后重启）。
**但不推荐改 PyCharm 的编码**——这是一种退步，应当统一用 UTF-8。更稳妥的做法是换个能自己解码的工具，见 11.9 的 `subprocess`。

:::warning[注意]
改系统编码有副作用：Windows 自带软件（记事本等）读写都变成 UTF-8，**以前用 GBK 保存的文件会乱码**。可以打开后用「另存为」改成 UTF-8，或用 Python 转存：

```text
# 把 GBK 编码的旧文件转存为 UTF-8
with open('old.txt', mode='rt', encoding='gbk') as f1, \
        open('new.txt', mode='wt', encoding='utf-8') as f2:
    f2.write(f1.read())
```
:::



:::warning[注意]
**警惕 `rm -rf /`。** `os.system` 能执行任何终端命令，而 Linux 的 `rm -rf /` 是删除根目录下一切的命令：Linux 不像 Windows 分 C、D、E 盘，整个系统只有一个「大文件夹」，`/` 就是根目录，系统文件也在其中。这条命令**没有任何二次确认**，不管文件还是文件夹、有没有内容通通删掉，连系统都会被干掉——「删库跑路」说的就是它。

即使只想删一个文件，也建议**先把它移到临时文件夹，过一段时间再删**，养成好习惯。
:::

### 11.4.2 环境变量

`os.environ` 返回系统环境变量，结果是一个字典（实际封装成了一个类，当作字典用即可）。有些内容不适合直接写进代码，比如数据库密码、账户密码，可以写到本机环境变量里，用的时候再取出来，增加安全性。
在系统的环境变量窗口中，用户变量、系统变量都可以点「新建」添加。修改环境变量后需要重启（至少重启终端/PyCharm）才能读到。
```python
import os

print(os.environ)                  # environ({...})，当作字典看即可
print(os.environ['PATH'])          # 用中括号取值，不存在会报 KeyError
print(os.environ.get('path'))      # Windows 上大小写都能取到；不存在时返回 None
print(os.getenv('PATH'))           # 等价于 os.environ.get
```

Windows 上环境变量名习惯显示成大写，但取值时大小写都可以；Linux/macOS 上则严格区分大小写。
### 11.4.3 os.stat 与文件名后缀

`os.stat` 获取文件或目录的详细信息：

```python
import os

with open('demo.txt', mode='wt', encoding='utf-8') as f:
    f.write('hello')

info = os.stat('demo.txt')
print(info.st_size)     # 文件大小，单位字节，输出: 5
print(info.st_atime)    # 最后一次访问时间（时间戳）
print(info.st_mtime)    # 最后一次修改时间（时间戳）
```

`st_ctime`（创建时间在 Windows 上；Linux 上是「元数据变更时间」）等字段含义可以查文档。这几个时间都是时间戳，要转成可读格式用 11.1 的知识即可。
`os.name` 顺便记一下：Windows 返回 `'nt'`，Linux/macOS 返回 `'posix'`，可以据此针对不同系统做不同处理。
```python
import os

print(os.name)    # Windows 输出: nt；Linux 输出: posix
```

### 11.4.4 os.path：路径处理

跨平台路径问题几乎全靠 `os.path` 解决，这一组函数必须记牢：

- `os.path.split(p)`：把路径拆成 `(目录, 文件名)` 元组；传的是文件夹路径时，从最后一层前面拆
- `os.path.dirname(p)` / `os.path.basename(p)`：分别是 `split` 结果的第一、第二个元素
- `os.path.exists(p)`：路径是否存在（文件或文件夹都算）
- `os.path.isabs(p)` / `os.path.isfile(p)` / `os.path.isdir(p)`：是否绝对路径 / 是否存在文件 / 是否存在目录
- `os.path.join(...)`：拼接多个路径，可以传任意多个
- `os.path.getatime` / `getmtime` / `getctime` / `getsize`：最后访问 / 修改 / 创建时间、文件大小

```python
import os

p = r'D:\teach\data\a.txt'
print(os.path.split(p))                  # 输出: ('D:\\teach\\data', 'a.txt')
print(os.path.split(r'D:\teach\data'))   # 文件夹也照样拆: ('D:\\teach', 'data')
print(os.path.dirname(p))                # 输出: D:\teach\data
print(os.path.basename(p))               # 输出: a.txt
print(os.path.isabs(p))                  # 输出: True
print(os.path.join(r'D:\teach', 'test', 'a.b.c.txt'))   # 输出: D:\teach\test\a.b.c.txt
print(os.path.exists('.'), os.path.isdir('.'), os.path.isfile('.'))   # 输出: True True False
```

**配合这些函数可以实现「统计整个文件夹大小」**：用 `os.listdir` 拿到所有名字，遍历时用 `os.path.join` 拼成完整路径，用 `os.path.isdir` 判断——是文件夹就**递归**调用自己，是文件就累加大小。具体代码见 11.4.5。
`os.path.join` 遇到绝对路径参数时会丢弃前面的部分，如 Linux 下 `os.path.join('a', '/b')` 得到 `'/b'`。Python 3.4+ 还有面向对象的 `pathlib`：`Path(__file__).resolve().parent.parent` 得到上上级目录，`BASE_DIR / 'log' / 'user.log'` 拼接路径，可读性更好。
**`__file__` 与项目根目录**：每个 Python 文件都有属性 `__file__`，表示当前文件的路径；`os.path.dirname()` 拿父级目录，调用两次就能从启动文件推回项目根目录。这是第 10 章讲目录规范时的核心技巧，这里再复习一遍。
```python
import os

path = r'D:\teach\catalog\bin\run.py'
print(os.path.dirname(path))                    # 输出: D:\teach\catalog\bin
print(os.path.dirname(os.path.dirname(path)))   # 输出: D:\teach\catalog
```

```python
# 文件: catalog/bin/run.py —— 动态获取项目根目录并加入 sys.path
import os
import sys

BASE_DIR = os.path.dirname(os.path.dirname(__file__))   # run.py -> bin -> catalog
sys.path.append(BASE_DIR)

from core.core import main

if __name__ == '__main__':
    main()
```

### 11.4.5 实战：统计文件夹大小

用 `os.listdir` 拿到目录下所有名字，遍历时用 `os.path.join` 拼成完整路径，用 `os.path.isdir` 判断——是文件夹就**递归**调用自己，是文件就累加大小。
```python
import os


def dir_size(path):
    total = 0
    for name in os.listdir(path):
        sub = os.path.join(path, name)       # 拼成完整路径
        if os.path.isdir(sub):
            total += dir_size(sub)           # 是文件夹就递归
        else:
            total += os.path.getsize(sub)    # 是文件就累加大小
    return total


print(dir_size('.'))    # 例如: 10240（当前目录的总字节数）
```

## 11.5 sys 模块

`sys` 模块面向的是**解释器本身**。前面学过 `sys.path`，这里再补齐几个常用属性：

- `sys.path`：模块搜索路径列表，第一项是执行文件所在文件夹
- `sys.argv`：通过终端传给程序的参数，是列表
- `sys.platform`：平台标识，Windows 是 `'win32'`，Linux 是 `'linux'`，macOS 是 `'darwin'`
- `sys.version` / `sys.version_info`：Python 版本字符串 / 版本元组，如 `(3, 13, 7, 'final', 0)`
- `sys.executable`：当前解释器的绝对路径（多版本共存时排查问题用）
- `sys.exit(code)`：结束程序；不传参数或传 0 表示正常退出，传非 0 表示异常退出
- `sys.stdout` / `sys.stderr`：标准输出流 / 标准错误流，`sys.stdout.write('x')` 不自动换行

### 11.5.1 sys.argv 与命令行参数

`sys.argv` 用来获取**通过终端传入的参数**。在 cmd 中执行 Python 程序是「解释器 + 文件路径」，用户还可以在后面跟参数，如 `python run.py 1 2 3`。程序中打印 `sys.argv` 会得到一个列表：**第一个值是 py 文件的路径，后面依次是传入的参数**。
用 `input` 也能拿到用户输入，为什么还要这个功能？因为有些场景下更方便。比如 Windows 终端的 `copy` 命令接收源文件路径和目标文件路径（把文件直接拖进 cmd 就能得到路径），一回车就复制好了。我们用 Python 来实现一个 copy：

```python
# 文件: mycopy.py
# 用法: python mycopy.py 源文件路径 目标文件路径
import sys

from_path = sys.argv[1]    # 0 号索引是执行文件路径，1 号是源文件路径
to_path = sys.argv[2]      # 2 号是新文件路径

# 用 rb/wb 模式，什么文件都能拷贝
with open(from_path, mode='rb') as f1, open(to_path, mode='wb') as f2:
    for line in f1:        # 逐行读写，大文件也不会占满内存
        f2.write(line)
```

在终端执行 `python mycopy.py C:\Users\xx\Desktop\test1.txt C:\Users\xx\Desktop\test2.txt`，桌面上就多了 `test2.txt`。
用户传入的路径可能不合法，可以用 `os` 模块功能判断并提示。更规范的做法是校验参数个数，不合法时用 `sys.exit(1)` 以非 0 退出码结束：

```python
import os
import sys

if len(sys.argv) != 3 or not os.path.isfile(sys.argv[1]):
    print('用法: python mycopy.py 源文件 目标文件')
    sys.exit(1)
```


:::warning[注意]
`sys.exit(1)` 里的数字会作为进程退出码传给操作系统，脚本化的自动化流程（CI、计划任务）就靠它判断程序是否成功，`0` 表示成功、非 0 表示失败。
:::

## 11.6 序列化：json

**序列化（serialization）**：把内存中的数据类型转成一种**特定格式**，这种格式可以存到硬盘，也可以传输给其他平台。**反序列化（deserialization）**：把过程反过来，将特定格式还原成原来的数据类型。
```text
内存中的数据类型 ---序列化---> 特定格式（json / pickle） ---> 存硬盘 / 传给其他平台
内存中的数据类型 <--反序列化--- 特定格式（json / pickle）
```

特定格式主要有两种：json 和 pickle（pickle 见 11.7）。
### 11.6.1 序列化的两大用途

**用途一：存档。** 程序的运行过程就是状态不断变化的过程，程序运行中产生的变量值就是用来记录运行状态的。把它们序列化存到硬盘，就把程序**此刻的运行状态永久保存**下来了。
类比：就像玩可以存档的游戏。游戏中得到装备、任务进度推进，对玩家是游戏状态，对程序员就是一个个变量值。玩到一半要吃饭，把此刻的状态序列化写进硬盘关机；回来再反序列化成对应的数据类型，就能从上次的节点继续玩。
**用途二：跨平台数据交互。** 生命周期较长的软件里可能同时存在多种语言开发的组件：一个 5 年前用 Java 写，一个 2 年前用 Python 写，一个产生的数据另一个也要用。Python 的列表，Java 要对应成自己的数据结构（数组），但二者并不兼容。于是大家约定一种中间格式：各自把数据类型序列化成这种格式，所有语言都能识别。
**结论：跨平台只能用 json，存档用 pickle。** 因为 json 要兼容所有语言，而 Python 有的类型别的语言不一定有，比如集合，所以 **json 不能支持 Python 的所有数据类型**；pickle 则支持 Python 几乎所有类型。
跨平台交互只能交互各语言共有的类型，要传集合就先把集合转成列表再序列化。
### 11.6.2 json 的 dumps 与 loads

`json` 是内置模块，直接导入。`dumps` 把 Python 对象序列化成字符串，`loads` 把 json 字符串反序列化回 Python 对象。
```python
import json

dic = {'name': '梦泪', 'age': 18, 'salary': 3.5, 'married': False,
       'hobbies': ['抽烟', '喝酒', '烫头']}

json_res = json.dumps(dic)
print(json_res)
# 输出: {"name": "\u5f20\u5927\u4ed9", "age": 18, "salary": 3.5, "married": false, "hobbies": ["\u62bd\u70df", "\u559d\u9152", "\u70eb\u5934"]}
print(type(json_res))    # 输出: <class 'str'>

print(json.dumps(dic, ensure_ascii=False))
# 输出: {"name": "梦泪", "age": 18, "salary": 3.5, "married": false, "hobbies": ["抽烟", "喝酒", "烫头"]}

print(json.dumps(dic, sort_keys=True))   # 按 key 排序，便于比对
print(json.dumps(dic, indent=4))         # 带缩进，方便人看
```

观察结果里的几个变化：

- 单引号都变成了双引号，因为双引号是所有语言通用的写法
- 汉字变成了 Unicode 转义（`\u5f20`）。`ensure_ascii` 默认为 `True`，即保证输出全是 ASCII 字符，汉字只能转义；传 `ensure_ascii=False` 汉字就正常显示。不加也不影响反序列化，加上只是看着舒服
- `18`、`3.5` 不变；Python 的 `False` 变成小写 `false`；列表仍是中括号
- 结果的类型是字符串。json 只是一种数据格式，规定字符串用双引号、布尔值用小写 `true/false`……序列化的结果就是一串字符串，可以写进硬盘，也可以通过网络传给其他平台

**Python 与 json 的类型对应关系：**

| Python | json |
|---|---|
| `dict` | `{}` |
| `list` / `tuple` | `[]` |
| `str` | 双引号字符串 |
| `int` / `float` | 数字 |
| `True` / `False` | `true` / `false` |
| `None` | `null` |


:::warning[注意]
json 里的字符串**必须用双引号**，`json.loads("{'a': 1}")` 会报 `json.JSONDecodeError`。另外字典的 int 型 key 序列化后会变成字符串（json 的 key 只能是字符串）。
:::

### 11.6.3 json 写文件与读文件：dump 与 load

第一种方式把两步分开：`dumps` + `f.write`、`f.read` + `loads`。第二种方式一步到位：`json.dump(对象, 文件对象)` 自动先 `dumps` 再 `f.write`，同样可以传 `ensure_ascii=False`；`json.load(文件对象)` 不用先 `f.read()`，直接把文件对象传进去。
```python
import json
import os

dic = {'name': '梦泪', 'age': 18, 'hobbies': ['抽烟', '喝酒', '烫头']}
os.makedirs('data', exist_ok=True)

with open(r'data\test.json', mode='wt', encoding='utf-8') as f:
    json.dump(dic, f, ensure_ascii=False)      # 序列化 + 写入，一步搞定

with open(r'data\test.json', mode='rt', encoding='utf-8') as f:
    print(json.load(f))                        # 输出: {'name': '梦泪', 'age': 18, 'hobbies': ['抽烟', '喝酒', '烫头']}

# 3.6 之后，loads 也能直接接收 bytes
with open(r'data\test.json', mode='rb') as f:  # b 模式不能再传 encoding
    print(json.loads(f.read()))                # 输出同上
```

文件后缀名可以随便写（`.txt`、`.json` 都行），后缀只提示文件里存的是什么数据，不影响内容。存 json 数据习惯写 `.json`。
json 只支持各语言共有的类型，序列化集合会直接报错：

```python
import json

try:
    json.dumps({1, 2, 3})
except TypeError as e:
    print(e)     # 输出: Object of type set is not JSON serializable
```


:::warning[注意]
关于 bytes 的版本差异：**Python 3.6 之后** `json.loads` 能直接反序列化 bytes；**Python 3.6 之前**的 Python 3 不行，因为 Python 3 里字符串和 bytes 是两种东西；而 **Python 2.7** 可以，因为 Python 2 的字符串类型本身就是 bytes（`str is bytes` 为 `True`）。
:::

## 11.7 pickle 与 XML

### 11.7.1 pickle

`pickle` 是内置模块，用法和 json 一模一样，也有 `dump`、`dumps`、`load`、`loads`，区别是它**支持 Python 几乎所有数据类型**（包括集合、自定义对象）。
```python
import pickle

dic = {'name': '梦泪', 'age': 18, 'nums': {1, 2, 3}}    # 含集合也不报错

res = pickle.dumps(dic)
print(type(res))                 # 输出: <class 'bytes'>   —— 结果是 bytes，不是字符串

with open('data.pickle', mode='wb') as f:    # 所以写文件要用 b 模式
    f.write(res)

with open('data.pickle', mode='rb') as f:
    print(pickle.load(f))        # 输出: {'name': '梦泪', 'age': 18, 'nums': {1, 2, 3}}
```

直接打开 pickle 文件看到的是一堆乱码。可以给 `dump/dumps` 传 `protocol=0`，内容就是纯 ASCII 的了，只是格式和 json 有些差异——不用管它，不影响反序列化。Python 3.13 中 `pickle.DEFAULT_PROTOCOL` 是 4，最高支持到 5。

:::warning[注意]
**不要反序列化来源不可信的 pickle 数据。** pickle 在还原对象时可以执行任意代码，攻击者构造一个恶意 pickle 文件就能在你的机器上执行命令。安全的 json 没有这个问题，这也是跨平台传输要用 json 的原因之一。
:::

### 11.7.2 曾经的跨平台格式 XML

在 json 出现之前，还有一种古老的跨平台数据交互格式 XML，样子有点像 HTML：

```xml
<students>
    <student><name>张三</name><age>18</age><gender>男</gender></student>
    <student><name>李四</name><age>19</age><gender>女</gender></student>
</students>
```

这相当于 Python 里一个大列表里放两个字典，每个字典有 name、age、gender。只是标签格式太笨重，不如 json 简洁，现在基本不用了。遇到需要用 XML 的老项目，Python 也有内置的 `xml.etree.ElementTree` 模块。
## 11.8 猴子补丁

**猴子补丁（monkey patch）** 不是新知识点，而是一种编程思想：**用自己的代码替换所用模块的源代码**，给别人的模块打补丁。
场景：项目已经写了很多代码，各处都在调 `json.dumps`、`json.loads`。某天发现 `loads` 有不足，或者有了更好的方案（比如更快的 `ujson`），就可以用一个更完美的 `loads` 替换掉 `json.loads`：

```python
import json
import ujson                      # 第三方模块，需先 pip install ujson

original_loads = json.loads       # 保存原功能，便于取消补丁
json.loads = ujson.loads          # 打补丁：替换 json 名称空间里 loads 的内存地址
# 注意：不加括号！加括号就变成调用函数了
```

也可以把它定义成一个函数，同时替换 `dumps` 和 `loads`，在入口文件里调用一次：

```python
import json
import ujson


def monkey_patch_json():
    """用 ujson 的功能替换 json 的同名功能"""
    json.__name__ = 'ujson'        # 把模块名字也换成 ujson
    json.dumps = ujson.dumps
    json.loads = ujson.loads


monkey_patch_json()                # 在入口文件里调用一次
```

这有点像装饰器，不过装饰器是**增加**功能，猴子补丁是**替换**功能。
**为什么要打补丁，而不是直接 `import ujson as json`？** 因为 `import ujson as json` 只影响**当前文件**的名称空间，别的模块里 `import json` 拿到的仍是原来的 `json`——它们是不同的名称空间。要统一替换就得把所有文件都改一遍。而打补丁时，所有模块导入的都是**同一个 json 模块对象**，在入口处改一次，处处生效。
**也不能直接改 json 模块的源代码。** 改源码虽然能让所有地方生效，但模块不是我们写的，里面一个变量可能关联很多地方，改完一处很可能别处崩溃。一般不要改别人的源码，最好是临时打个补丁。
**补丁打在哪里？** 回忆模块导入：**模块首次导入后会加载到内存，之后不管在哪个文件导入，都是先从内存里找。** 项目本质上就是一个文件 `run.py`——功能分散在不同文件里，运行的是 `run.py`，遇到 `main` 就导入进来，`main` 里再导入别的……这也是为什么项目里所有文件的 `sys.path` 都参照执行文件的 `sys.path`。
所以应该在**首次导入模块的地方，也就是入口文件里**打补丁：

```python
# 文件: catalog/run.py
import json

import my_patch                 # 假设自己写的更好的实现放在 my_patch.py 中

json.loads = my_patch.loads     # 在入口文件打补丁，全项目的 json.loads 都随之改变

from core.core import main      # 之后导入的模块里调用 json.loads，用的都是新功能

if __name__ == '__main__':
    main()
```

要取消补丁或换成别的补丁，只改入口文件即可。这就是猴子补丁的核心思想。猴子补丁也常用于单元测试中替换掉网络请求、数据库等功能，缺点是替换是「隐形」的，滥用会让问题难以排查。
## 11.9 shutil 模块

`shutil` 也是内置模块，用来处理文件、文件夹以及压缩包。常用功能如下：

- `shutil.copyfileobj(f1, f2)`：传两个**打开的文件对象**，从老文件读、写入新文件
- `shutil.copyfile(a, b)`：直接按路径拷贝内容，不用自己打开文件
- `shutil.copy(a, b)`：拷贝内容**和权限**
- `shutil.copy2(a, b)`：拷贝内容**和状态信息**（时间等，最完整）
- `shutil.copystat(a, b)`：只拷贝文件信息（访问时间、修改时间等），不拷内容，`b` 必须已存在
- `shutil.copymode(a, b)`：只拷贝文件权限，不拷内容
- `shutil.copytree(src, dst, ignore=...)`：拷贝整个文件夹，可用 `ignore` 排除不需要的文件
- `shutil.rmtree(path)`：递归删除整个文件夹（不进回收站，慎用）
- `shutil.move(src, dst)`：移动文件或文件夹
- `shutil.make_archive(base_name, format, root_dir)`：创建压缩包，`format` 可选 `zip`、`tar`、`gztar`、`bztar`、`xztar`
- `shutil.unpack_archive(文件名, extract_dir)`：解压

```python
import os
import shutil

os.makedirs(r'src_dir\sub', exist_ok=True)
for name in ('a.txt', 'run.py', 'user.txt'):
    with open(os.path.join('src_dir', name), mode='wt', encoding='utf-8') as f:
        f.write(name)

shutil.copyfile(r'src_dir\a.txt', 'b.txt')    # 拷贝文件内容
shutil.copystat(r'src_dir\a.txt', 'b.txt')    # 再拷贝文件信息，b.txt 必须已存在

with open(r'src_dir\a.txt', 'rb') as f1, open('c.txt', 'wb') as f2:
    shutil.copyfileobj(f1, f2)                # 传文件对象

# 拷贝文件夹，排除以 .py 结尾和以 user 开头的文件
shutil.copytree('src_dir', 'dst_dir',
                ignore=shutil.ignore_patterns('*.py', 'user*'))
print(os.listdir('dst_dir'))                  # 输出: ['a.txt', 'sub']

shutil.move('c.txt', r'dst_dir\c.txt')        # 移动文件

# 创建压缩包：生成 backup.zip，内容是 src_dir 里的东西
print(shutil.make_archive('backup', 'zip', root_dir='src_dir'))   # 输出: ...\backup.zip

shutil.rmtree('dst_dir')                      # 递归删除整个文件夹
```

针对压缩文件，Python 还有两个内置模块 `zipfile` 和 `tarfile`；如果只想处理 zip，用它们比 `shutil.make_archive` 更灵活（可以往已有压缩包里加文件、按需解压单个文件）。
所谓「权限」，是指打开文件其实是向操作系统发请求，操作系统对文件有权限限制，不是所有人都能打开电脑上所有文件。平时打开的都是自己权限范围内的文件，所以很少遇到；普通用户想改管理员创建的文件就会出现权限问题。
## 11.10 configparser：ini 配置文件

第 10 章讲软件目录规范时，配置文件 `settings.py` 就是一个 Python 文件，里面定义了一堆变量。`configparser` 模块则用来加载另一种**特定格式**的配置文件。
在 `conf` 文件夹下新建 `test.ini`。后缀用 `.ini` 或 `.cfg` 都行，后缀本身不重要，只是别人一看就知道这是配置文件：

```ini
# 注释可以用井号
; 也可以用分号
[default]
delay = 10
salary = 3.5
compression = true

[db]
host = 127.0.0.1
port: 3306
user = root
```

中括号里的 `[default]`、`[db]` 是每一部分配置的标题，叫 section，名字可以随便取，也可以继续添加更多 section。每个 section 下的配置项叫 option，可以写成 `key = value`，也可以写成 `key: value`。
读取配置的思路很简单：**先找 section 名，再找它下面的 option（等号左边的 key），通过 key 拿到 value。**

```python
import configparser

config = configparser.ConfigParser()          # 调用后得到一个配置对象
config.read('test.ini', encoding='utf-8')     # 读取配置文件，可指定编码

print(config.sections())          # 1. 所有 section，输出: ['default', 'db']
print(config.options('db'))       # 2. 某个 section 下所有 key，输出: ['host', 'port', 'user']
print(config.items('db'))         # 3. 所有 (key, value)，输出: [('host', '127.0.0.1'), ('port', '3306'), ('user', 'root')]

delay = config.get('default', 'delay')
print(delay, type(delay))         # 输出: 10 <class 'str'>   —— get 拿到的是字符串

print(config.getint('default', 'delay'))            # 输出: 10
print(config.getfloat('default', 'salary'))         # 输出: 3.5
print(config.getboolean('default', 'compression'))  # 输出: True
```

- `sections()`：所有 section 名，列表
- `options(section)`：该 section 下所有 key，列表
- `items(section)`：所有 `(key, value)` 元组组成的列表
- `get(section, option)`：字符串；`getint` / `getfloat` / `getboolean`：int / float / bool

`getboolean` 获取布尔值时，配置文件里写 `true`、`True`、`TRUE` 大小写都能识别。

:::warning[注意]
`get` 拿到的**永远是字符串**，想当整型用要自己 `int()` 转换，或者直接用 `getint`。另外，大写的 `[DEFAULT]` 是 configparser 的**特殊 section**：它不会出现在 `sections()` 里，里面的配置项会被所有 section 继承。本节示例用的是小写的 `default`，只是一个普通 section，不要在这一点上踩坑。
:::

`configparser` 也能修改配置文件，值必须是字符串，最后用 `write` 写回（注意：写回会**丢失注释**）：

```python
import configparser

config = configparser.ConfigParser()
config.read('test.ini', encoding='utf-8')
config.set('db', 'port', '3307')              # 改已有的项
if not config.has_section('redis'):
    config.add_section('redis')               # 新增 section
config.set('redis', 'host', 'localhost')      # 新增 option
config.remove_option('default', 'salary')     # 删除 option
with open('test.ini', 'wt', encoding='utf-8') as f:
    config.write(f)
```

实际项目里配置文件一般由用户自己维护，程序很少去改它；只有写带界面的程序、让用户点选修改配置时才会用到。实践中可以在 `lib/common.py` 里封装一个获取配置项的函数，其他部分要用配置时调它就行。
## 11.11 subprocess：执行终端命令

`subprocess` 和 `os.system` 很像，都是用来**执行终端命令**的，但 `subprocess` 能拿到命令的执行结果，还能分别处理正确输出和错误输出。目前重点掌握 `subprocess.Popen`。
```python
import subprocess

obj = subprocess.Popen(
    'tree',                     # 要执行的终端命令
    shell=True,                 # 通过操作系统的终端（shell）来执行
    stdout=subprocess.PIPE,     # 命令正常执行的结果丢进这个管道
    stderr=subprocess.PIPE,     # 命令出错的结果丢进另一个管道
)

res = obj.stdout.read()         # 从正确管道的另一头取结果
print(type(res))                # 输出: <class 'bytes'>
err = obj.stderr.read()         # 错误管道里没有数据
print(err)                      # 输出: b''

print(res.decode('gbk'))        # 用系统编码解码：Windows 默认是 gbk
```

**管道（pipe）** 可以想象成一根水管：水从一头流进去，从另一头流出来。命令正常执行的结果从 `stdout` 这头放进去，我们再从另一头 `obj.stdout.read()` 取出来；出错的结果则进 `stderr` 管道。每调用一次 `subprocess.PIPE` 就新建一个管道。
取出的结果前面有个 `b`，说明是 **bytes**。这正是 `subprocess` 相对 `os.system` 的优势：`os.system` 直接按字符串输出，编码不一致就乱码；而 `subprocess` 拿到 bytes，可以**按正确的编码自己解码**。用什么编码？命令是系统的命令，结果用的是**系统的编码**：Windows 默认 `gbk`，改过系统编码则是 `utf-8`。`tree` 是 Windows 命令，Linux/macOS 下可以换成 `ls -l`，解码用 `utf-8`。
### 11.11.1 为什么分正确、错误两个管道

故意把命令写错再运行：

```python
import subprocess

obj = subprocess.Popen('treeeee', shell=True,       # 一个不存在的命令
                       stdout=subprocess.PIPE, stderr=subprocess.PIPE)
print(obj.stdout.read().decode('gbk'))   # 正确管道：空内容
print(obj.stderr.read().decode('gbk'))   # 错误管道：'treeeee' 不是内部或外部命令，也不是可运行的程序
```

既然结果不是正确就是错误，为什么不用一个管道接收？因为**一条命令的结果可能既有正确又有错误**。在 cmd 里可以用 `&`（数字 7 上面那个符号）把多条命令写在一条语句里：

```bat
dir & xxxx
```

回车后，前半部分是 `dir` 的正确结果，后半部分是 `xxxx` 的错误提示。你没法说这条语句整体是「正确」还是「错误」，所以必须分两个管道：

```python
import subprocess

obj = subprocess.Popen('dir & xxxx', shell=True,
                       stdout=subprocess.PIPE, stderr=subprocess.PIPE)
print(obj.stdout.read().decode('gbk'))   # 有内容：dir 的结果
print(obj.stderr.read().decode('gbk'))   # 也有内容：xxxx 的错误提示
```


:::warning[注意]
`shell=True` 时千万不要把用户输入直接拼进命令字符串，否则有**命令注入**风险。
:::

既然能自己控制解码方式，就**没必要再去改系统的编码**了，建议把系统编码改回默认的 GBK（取消勾选「使用 Unicode UTF-8 提供全球语言支持」并重启）。有些第三方软件是按 Windows 默认的 GBK 设计的，系统编码改成 UTF-8 反而可能让它们乱码。

:::tip[技巧]
`obj.communicate()` 可以等命令结束并一次性拿到 `(stdout, stderr)`，比先读 stdout 再读 stderr 更稳妥（读法不当可能死锁）。Python 3.7+ 还有更简洁的 `subprocess.run(命令, shell=True, capture_output=True)`，结果在 `.stdout`、`.stderr`，`.returncode` 为 0 表示成功。
:::

## 11.12 hashlib：哈希算法

**哈希（hash）是一类算法**，不是一种。可以把它看成一个函数：传入一段内容，返回一串哈希值（也叫散列值、摘要）。常见算法有 MD5、SHA1、SHA256、SHA512 等，功能一样，只是复杂度和输出长度不同。

:::warning[注意]
**MD5 和 SHA1 已被破解**（可以人为构造出哈希相同的两段不同内容），新项目应使用 SHA256 及以上。
:::

哈希值有三个特点：

1. **输入敏感**：输入哪怕只改一个标点，哈希值都会发生巨大变化；反过来，输入一样、算法一样，哈希值一定一样。
2. **不可逆**：无法通过哈希值反推出原文。
3. **计算极快、长度固定**：10GB 的高清电影和 10KB 的文本都能快速算出结果；同一种算法，无论输入多长，输出长度都固定（MD5 是 32 位十六进制，SHA256 是 64 位）。
```python
import hashlib

print(hashlib.md5(b'hello').hexdigest())    # 输出: 5d41402abc4b2a76b9719d911017c592
print(hashlib.md5(b'hello').hexdigest())    # 再算一次，结果完全一样
print(hashlib.md5(b'hello!').hexdigest())   # 只加一个标点，结果面目全非，输出: 5a8dd3ad0756a93ded72b823b19dd877
print(len(hashlib.md5(b'a' * 1000000).hexdigest()))   # 输入再长，长度依然是 32
```

### 11.12.1 hashlib 的基本用法

`hashlib` 是内置模块，下面有 `md5` 以及一系列 `sha` 算法，用法完全一样。可以把它理解成一个「哈希工厂」，三步走：

1. `h = hashlib.md5()`：建一个哈希工厂
2. `h.update(数据)`：给工厂运送原材料，数据必须是 **bytes**，可以分多次运
3. `h.hexdigest()`：向工厂要加工结果，即**所有原材料合在一起**算出的哈希值（32 位十六进制字符串）

```python
import hashlib

h1 = hashlib.md5()                    # 1. 哈希工厂
h1.update('abc'.encode('utf-8'))      # 2. 运送原材料，字符串要先 encode 成 bytes
h1.update('123'.encode('utf-8'))      #    可以接着运
print(h1.hexdigest())                 # 3. 结果是 'abc123' 的哈希值，输出: e99a18c428cb38d5f260853678922e03

# 分成几次 update 不影响结果
h2 = hashlib.md5()
for part in ('ab', 'c', '1', '23'):
    h2.update(part.encode('utf-8'))
print(h2.hexdigest())                 # 输出: e99a18c428cb38d5f260853678922e03，和上面完全一样
```


:::warning[注意]
`update` 只接受 bytes，直接传字符串会报 `TypeError: Strings must be encoded before hashing`。
:::

## 11.13 hashlib 的两大用途

### 11.13.1 密码的密文传输与存储

以 QQ 登录为例：输入账号密码点登录，客户端把账号密码通过网络传到服务端，服务端判断对了就放行。问题是——只要数据经过网络，数据包就**可能被截获**。攻击者截到数据包一看是**明文**（账号 666、密码 123），就可以直接登录你的账号。
所以要把密码先用哈希算法转成哈希值（密文）再传输（账号一般保持明文，只加密密码）。由于哈希值不可反解，服务端存储的也必须是**用同样算法算出来的密文**：注册时存密文，登录时传密文，服务端**密文对密文**比对。前提是**注册和登录用的算法必须一致**。
```python
import hashlib

# 注册：服务端只保存密码的哈希值
db_password = hashlib.sha256('123'.encode('utf-8')).hexdigest()

# 登录：对输入的密码做同样的运算，用密文比对密文
inp = '123'
if hashlib.sha256(inp.encode('utf-8')).hexdigest() == db_password:
    print('登录成功')      # 输出: 登录成功
```

### 11.13.2 哈希碰撞与撞库

哈希值不可逆，但攻击者**不一定要逆推**。同一算法输出长度固定，哈希值总数有限，而输入可以有无穷多种，必然会发生**碰撞**：只要找到一段内容、它的哈希值和你密码的哈希值相同，就能拿它登录你的账号。
只要算力足够，就能算出你的密码。例如 8 位纯数字密码只有 10⁸ = 1 亿种组合，把 0 到 1 亿的哈希值都算出来逐个比对，一台普通四核 CPU 秒级时间就能破解。所以密码**尽量不要用纯数字**：网上有常用密码库（彩虹表），算出库里每个密码的哈希值和截获的密文对比，你的密码恰好在库里就被破解了——俗称**撞库**。
**结论：没有绝对的安全，我们能做的只是让攻击者的破解成本越来越高**，这就需要「加盐」（见 11.13.5）。
### 11.13.3 文件完整性校验

输入不变则哈希值不变，输入有一点点变化哈希值就变——基于这个特性可以做文件完整性校验。
打开 Python 官网 Downloads → Windows，展开某个版本，页面下方列出了各安装包和对应的 MD5 值，这是官方对安装包算出来的。我们下载安装包后，以二进制方式读出内容，同样用 MD5 计算：

- 哈希值和官网一样：安装包完整，没有被篡改
- 不一样：安装包有问题，不要使用。因为下载的数据可能被中途截获，被人加了病毒再发给你

小文件的校验很简单，b 模式读到的就是 bytes，直接传给 `update`：

```python
import hashlib

# 演示用：生成一个文件，代替下载好的安装包
with open('python-3.10.5-amd64.exe', mode='wb') as f:
    f.write(b'pretend this is an installer' * 1000)

with open('python-3.10.5-amd64.exe', mode='rb') as f:   # 二进制方式打开
    m = hashlib.md5()                # 官网提供的是 MD5 值，所以用 md5
    m.update(f.read())               # b 模式读到的就是 bytes
    print(m.hexdigest())             # 和官网公布的 MD5 值对照，一样就没问题
```

### 11.13.4 大文件的抽样校验

一部 30GB 的电影一次性 `f.read()` 读进内存不现实；一行行读虽然省内存，但文件很大时依然慢。
换个思路：**在文件里选几个点，各取一小段做哈希运算**。比如把指针移到 1/10 处读 100 字节 `update` 一次，再移到 2/10 处读 100 字节……只取 10 个点，速度就快多了。取几个点、每次读多少都由你规定，**服务端和客户端用同样的方法**校验即可。
这样没有校验全部数据，但已经能大概率防止文件被篡改。极端情况下两个文件不同、恰好选中的几个点数据相同，概率极低，没必要为此牺牲速度。迅雷这类下载工具用的就是这种思路。
```python
import hashlib
import os

path = 'big_file.bin'
with open(path, mode='wb') as f:          # 演示用：生成一个约 1MB 的文件
    f.write(os.urandom(1024 * 1024))

print(os.path.getsize(path))              # 方式1：os 模块获取字节数，输出: 1048576

with open(path, mode='rb') as f:
    f.seek(0, 2)                          # 方式2：指针移到文件末尾
    size = f.tell()                       # 指针位置 = 文件总字节数
    print(size)                           # 输出: 1048576，和方式1一样

    one_ten = size // 10                  # 文件的十分之一，整除避免小数
    m = hashlib.md5()
    for i in range(10):                   # 取 10 个点
        f.seek(i * one_ten, 0)            # 参照文件开头移动：第 1 次 0，第 2 次 1/10……
        m.update(f.read(100))             # 每个点读 100 字节送进工厂
    print(len(m.hexdigest()))             # 输出: 32

os.remove(path)
```

第一次循环 `i = 0`，指针停在开头；第二次 `i = 1`，移到 1/10 处；之后每次往后移 1/10。对两个安装包分别运行，哈希值一样就说明文件没问题。

:::warning[注意]
抽样校验用准确性换速度。如果要求一个字节都不能错（如软件发布的安全校验），仍需读全部内容，但应按固定大小分块读，避免一次读进内存：

```text
with open(path, mode='rb') as f:
    m = hashlib.sha256()
    while chunk := f.read(1024 * 1024):    # 每次 1MB
        m.update(chunk)
```

Python 3.11+ 还可以直接写 `hashlib.file_digest(f, 'md5')`。
:::

### 11.13.5 密码加盐

哈希值虽不可逆，但可以通过碰撞算出密码，于是有了**密码加盐（salt）**。按字面理解就行：你的密码是一盘菜，我们往上面加点佐料。
```python
import hashlib

pwd = 'xyxy520'

# 1. 原生密码，没加盐
print(hashlib.md5(pwd.encode('utf-8')).hexdigest())
# 输出: e63f8ff0a7f7ab59c9b3253902220d84

# 2. 在密码前后加盐
m = hashlib.md5()
m.update('天青色等烟雨'.encode('utf-8'))   # 前面加点盐
m.update(pwd.encode('utf-8'))
m.update('而我在等你'.encode('utf-8'))     # 后面也加点盐
print(m.hexdigest())
# 实际运算的是"天青色等烟雨xyxy520而我在等你"，输出: 05a70458c4db20f6f0229b85b22e52e5
```

盐的内容是什么、加在什么位置都由你自己规定，甚至可以每隔一个字符插一点盐。只要：用户注册时按这个加盐方式把加盐后的密文存到服务端；用户登录时按**同样的加盐方式**加密后再比对。
这样即便密码简单到全是数字，攻击者想通过碰撞破解也变得很困难：就算撞到了密码原文，他不知道盐是什么、加在哪里，算出的哈希值还是对不上。

:::warning[注意]
固定的盐一旦泄露，所有用户都受影响；如果每个用户用同一个盐，攻击者破解出一个等于破解全部。更安全的做法是**每个用户一个随机盐**，和哈希值一起保存；实际项目还应使用故意算得很慢的算法（如标准库的 `hashlib.pbkdf2_hmac`，迭代十万次），让暴力破解的成本高到不可接受。

```text
import hashlib
import os

salt = os.urandom(16)                                          # 每个用户随机生成
key = hashlib.pbkdf2_hmac('sha256', b'xyxy520', salt, 100_000) # 迭代 10 万次
# salt 和 key 一起存进数据库
```
:::


还是那句话：**世界上没有绝对的安全**，加盐只是提高了攻击者的成本。
## 11.14 pip 与第三方模块

前面讲猴子补丁时想用第三方模块 ujson 替换 `json`，但第三方模块不是 Python 自带的，用之前要先安装。
### 11.14.1 用 pip 安装

打开 cmd，用 `pip install 模块名`（macOS/Linux 上一般写 `pip3`）安装。之所以能直接敲 `pip`，是因为安装 Python 时已经把 pip 所在的文件夹加进了环境变量。
```bash
pip install ujson
```

安装成功会看到类似 `Successfully installed ujson-5.4.0` 的提示。不指定版本时默认装最新版；指定版本用 `==`：

```bash
pip install ujson==5.4.0
```

**切换国内镜像源。** pip 默认从国外服务器下载，有时很慢。可以在命令后加 `-i` 指定国内镜像源（搜「pip 镜像源」能找到很多），例如清华源：

```bash
pip install ujson -i https://pypi.tuna.tsinghua.edu.cn/simple
```

注意每个参数之间要用空格隔开。这种方式**只是临时有效**，下次装别的模块还得再加 `-i`。一劳永逸的办法是执行一次下面的命令，以后 pip 默认就走这个源：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

常用的 pip 命令如下：

- `pip install 模块名`：安装（`==版本号` 指定版本）
- `pip uninstall 模块名`：卸载
- `pip list`：查看已安装的模块
- `pip show 模块名`：查看版本与安装位置
- `pip install -r requirements.txt`：按依赖文件一次装好全部依赖
- `python -m pip install --upgrade pip`：升级 pip 自身

安装完成后，有时会出现一段黄色的 `WARNING`，提示应该升级 pip。这只是警告而不是报错，只要能正常安装第三方模块，不升级也没关系。在 cmd 里按 `Ctrl + C` 可以取消正在输入的命令，也可以终止正在运行的命令。

:::warning[注意]
电脑上有多个 Python 时，`pip` 装的模块只属于对应的那个解释器，另一个解释器里会报 `ModuleNotFoundError`。可以用 `import sys; print(sys.executable)` 查看当前运行的是哪个解释器，再用「`解释器路径 -m pip install 模块名`」装给它。
:::

2. 选择 `Python Interpreter`，这里列出了当前解释器环境中已安装的第三方模块。
3. 点 `+` 号，在搜索框输入模块名（如 `ujson`），选中后点下方 `Install Package`。

PyCharm 默认同样从国外源安装。修改方法：在搜索界面点 `Manage Repositories`，选中默认的源、点编辑按钮，粘贴国内镜像源地址后 OK；如果列表里没有默认的源，点 `+` 号添加即可。
装好后在 Python 里能导入就说明成功了：

## 本章小结

- 时间有三种形式：时间戳（算间隔）、格式化字符串（展示）、结构化时间（取整型字段）。三者互转必须经过结构化时间：`localtime/gmtime`、`strftime`、`strptime`、`mktime`；字符串与格式必须一一对应。北京时间比 UTC 快 8 小时。
- `datetime.datetime.now()` 直接得到可读时间，`replace(microsecond=0)` 去掉微秒；`+ / - timedelta(days=..., weeks=...)` 做时间加减，没有年、月的参数。`strptime`/`strftime`/`timestamp`/`fromtimestamp` 完成与字符串、时间戳的互转。
- `random`：`random`、`uniform`、`randint`（闭区间）、`randrange`（顾头不顾尾）、`choice`、`sample`、`shuffle`（只能打乱可变类型）。密码生成器靠 `chr`/`ord` 配合编码范围取字符，用标记列表或「先各取一个再洗牌」保证包含四类字符。
- `os`：`getcwd/chdir/listdir/mkdir/makedirs/remove/rmdir/rename/system`；`os.environ` 取环境变量（字典）；`os.stat` 取文件信息；`os.name` 区分平台；`os.path` 的 `split/dirname/basename/join/exists/isabs/isfile/isdir/getsize` 是跨平台路径的基础。
- `os.system` 乱码是 UTF-8 与系统 GBK 不一致；推荐让 `subprocess` 自己解码，而不是改 PyCharm 或系统编码。牢记 `rm -rf /` 的危害，删除前先把文件移到临时目录。
- `sys`：`sys.path` 模块搜索路径、`sys.argv` 命令行参数（第一个是执行文件路径）、`sys.platform`、`sys.exit`、`sys.stdout`。`sys.argv` 配合 `os` 判断可以实现自己的 copy 命令。
- 序列化把内存数据转成 json / pickle 格式，用于存档和跨平台交互。跨平台只能用 json（不支持集合等 Python 独有类型），存档用 pickle（支持几乎全部类型，结果是 bytes，禁用不可信来源的数据）。
- json：`dumps/loads` 配文件读写，`dump/load` 直接操作文件；`ensure_ascii=False` 正常显示中文，`indent` 美化输出，3.6+ 可直接处理 bytes。
- 猴子补丁把自己的实现替换掉模块的属性，在**入口文件**打一次即全项目生效；不要改别人模块的源码，`import xxx as yyy` 只影响当前文件的名称空间。
- `shutil`：`copyfileobj/copyfile/copy/copy2/copystat/copymode/copytree(ignore=)/rmtree/move/make_archive`。
- `configparser` 读 ini 文件：`read`、`sections`、`options`、`items`、`get`（**永远是字符串**）、`getint`、`getfloat`、`getboolean`。
- `subprocess.Popen(命令, shell=True, stdout=PIPE, stderr=PIPE)` 执行命令，结果是 bytes、按系统编码解码；正确和错误输出要分两个管道，因为一条命令可能同时产生两种输出。用 `obj.communicate()` 一次性读更稳妥。
- 哈希三特点：输入敏感、不可逆、算得快且长度固定；两大用途：密码密文存储传输、文件完整性校验。`hashlib` 三步走：建工厂 → `update(bytes)` 可多次 → `hexdigest()`；大文件抽样校验；密码加盐提高撞库成本，但没有绝对的安全。
- 第三方模块用 `pip install` 安装，`-i` 临时换源、`pip config set` 永久换源；PyCharm 在 `Python Interpreter` 页点 `+` 安装、在 `Manage Repositories` 换源。

1. 写出把时间戳 `0` 转换成 `年-月-日 时:分:秒` 的北京时间和世界标准时间的代码。
<details><summary>参考答案</summary>

```python
import time

fmt = '%Y-%m-%d %H:%M:%S'
print(time.strftime(fmt, time.localtime(0)))   # 北京时间输出: 1970-01-01 08:00:00
print(time.strftime(fmt, time.gmtime(0)))      # 世界标准时间输出: 1970-01-01 00:00:00
```

时间戳 0 就是 Unix 纪元原点，本地时间正好比 UTC 快 8 小时。
</details>

2. 会员到期时间存为字符串 `'2026-01-31 12:00:00'`，续费 30 天后到期时间是多少？分别用 `time` 和 `datetime` 实现。
<details><summary>参考答案</summary>

```python
import time
import datetime

s = '2026-01-31 12:00:00'
fmt = '%Y-%m-%d %H:%M:%S'

ts = time.mktime(time.strptime(s, fmt)) + 30 * 24 * 60 * 60
print(time.strftime(fmt, time.localtime(ts)))   # 输出: 2026-03-02 12:00:00

d = datetime.datetime.strptime(s, fmt) + datetime.timedelta(days=30)
print(d.strftime(fmt))                          # 输出: 2026-03-02 12:00:00
```

`time` 走「字符串 → 结构化 → 时间戳 → 加秒数 → 再转回字符串」；`datetime` 则 `strptime` 成对象后直接加 `timedelta`，明显更简洁。
</details>

3. 用「先四种字符各取一个，剩下的位数随机取，最后洗牌」的思路，实现一定包含大小写字母、数字和符号的密码生成器；并说明长度不足 4 位时怎么办。
<details><summary>参考答案</summary>

```python
import random


def pwd_gen(n=16):
    if n < 4:                                    # 少于 4 位不可能包含四种字符
        return ''
    char_list = [[97, 122], [65, 90], [48, 57], [33, 47]]
    # 先四种字符各取一个，保证一定包含四种字符
    chars = [chr(random.randint(*r)) for r in char_list]
    # 剩下的位数随机选类型再取字符
    for _ in range(n - 4):
        chars.append(chr(random.randint(*random.choice(char_list))))
    random.shuffle(chars)                        # 洗牌打乱顺序
    return ''.join(chars)


print(len(pwd_gen(8)), len(pwd_gen(16)))    # 输出: 8 16
```

长度小于 4 时直接返回空字符串。这个版本既不需要失败重试（方法一），也没有「8 位一定是每类各两个」的规律（方法二）。
</details>

4. 完善 `mycopy.py`：判断参数个数和源文件是否存在，不合法时提示用户并退出；改为逐块读写，避免大文件一次性读入内存。

```python
import os
import sys

if len(sys.argv) != 3:

if not os.path.isfile(sys.argv[1]):

print('拷贝完成')
```

6. `test.ini` 的 `[default]` 下有 `delay = 10`，分别用 `get` 和 `getint` 读取，说明结果类型；并解释为什么文件名要用 `.ini` 而不是随便写。
<details><summary>参考答案</summary>

```python
import configparser

with open('test.ini', 'wt', encoding='utf-8') as f:   # 先准备文件
    f.write('[default]\ndelay = 10\n')

config = configparser.ConfigParser()
config.read('test.ini', encoding='utf-8')
print(type(config.get('default', 'delay')))      # 输出: <class 'str'>
print(type(config.getint('default', 'delay')))   # 输出: <class 'int'>
```

`get` 得到字符串 `'10'`，`getint` 相当于先 `get` 再 `int()` 转换。后缀名本身不影响文件内容，用 `.ini`（或 `.cfg`）只是为了让别人一眼看出这是配置文件。
</details>

7. 为什么执行 `dir & xxxx` 这类命令时，需要分别读取 `stdout` 和 `stderr` 两个管道？

<details><summary>参考答案</summary>

因为一条命令的结果**可能同时包含正确和错误两部分**：`dir` 的结果进 `stdout` 管道，`xxxx` 的错误提示进 `stderr` 管道。只用一根管道就没法区分哪部分是正确输出、哪部分是错误信息，所以必须分两个。
</details>

8. 改写注册登录：注册时把「用户名:加盐后的 md5 密文」写入 `user.txt`，登录时用同样的加盐方式比对。
<details><summary>参考答案</summary>

```python
import hashlib


def encrypt(pwd):
    """加盐方式：密码前后各加一段盐，注册和登录必须一致"""
    m = hashlib.md5()
    m.update('天青色等烟雨'.encode('utf-8'))
    m.update(pwd.encode('utf-8'))
    m.update('而我在等你'.encode('utf-8'))
    return m.hexdigest()


def register(name, pwd):
    with open('user.txt', mode='at', encoding='utf-8') as f:
        f.write(f'{name}:{encrypt(pwd)}\n')        # 只存密文，不存明文


def login(name, pwd):
    with open('user.txt', mode='rt', encoding='utf-8') as f:
        for line in f:
            user, secret = line.strip().split(':')
            if user == name and secret == encrypt(pwd):   # 密文比对密文
                return True
    return False


register('xiaoming', '123')
print(login('xiaoming', '123'))    # 输出: True
print(login('xiaoming', '456'))    # 输出: False
```

</details>

9. 一个项目的 `core.py`、`db_handle.py` 都调用了 `json.loads`，现在要统一替换成自己的实现，补丁应该打在哪里？为什么？

<details><summary>参考答案</summary>

打在**入口文件**（如 `run.py`）里、导入其他模块之前。模块首次导入后就加载到内存，之后各处导入拿到的都是内存里的同一个模块对象；在入口文件替换 json 名称空间中 `loads` 的内存地址，后续所有引用 `json.loads` 的地方都会跟着变。取消或更换补丁也只需改入口文件，且不必动 json 模块的源码。
</details>
