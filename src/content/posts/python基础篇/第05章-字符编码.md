## 5.1 字符编码的基础概念

### 5.1.1 字符编码用在哪里

字符编码主要用在两个地方:

1. **文本文件的读写**:文本文件由字符组成,读写文件时需要编码解码
2. **Python 定义字符串**:`name = '梦泪'` 这种语法涉及字符在内存中的存储

**文本编辑器读取文件的三个步骤**

1. 启动编辑器:程序从硬盘加载到内存
2. 读取文件:把文件内容从硬盘读到内存
3. 显示内容:把内存中的数据显示到屏幕

**Python 解释器执行 py 文件的三个阶段**

1. 启动 Python 解释器:从硬盘加载到内存
2. 读取 py 文件:把文件内容从硬盘读到内存
3. 识别 Python 语法:把内容当作 Python 语法识别并执行

前两个阶段是文本文件读写,第三个阶段定义字符串时,都涉及字符编码。
### 5.1.2 什么是字符编码

**字符编码表是字符与数字一一对应的关系。** 计算机只能识别二进制数(0和1),人类使用的字符必须转成数字才能被计算机识别。
类比:假设规定"仙"对应数字 10086,那么:

- 输入"仙" → 查表转成 10086 → 转成二进制存入内存/硬盘(这叫**编码 encode**)
- 读取时 → 取出二进制转成 10086 → 查表转成"仙"显示(这叫**解码 decode**)

```python
# Python 中查字符对应的数字
n = ord('仙')
print(n)            # 输出: 20185
print(bin(n))       # 二进制,输出: 0b100111011011001
print(chr(n))       # 反向转回字符,输出: 仙
```

**关键结论**:编码和解码必须使用同一张表,否则就会出现乱码。
### 5.1.3 存储单位换算

| 单位 | 换算 |
|---|---|
| 1 Byte(字节) | 8 bit(位) |
| 1 KB | 1024 Byte |
| 1 MB | 1024 KB |
| 1 GB | 1024 MB |
| 1 TB | 1024 GB |
| 1 PB | 1024 TB |

## 5.2 字符编码的发展历程

### 5.2.1 ASCII 码表

现代计算机起源于美国,最早的 **ASCII 码表**只考虑了英文字符。
**特点**

- 用 8 位二进制(1 Byte)表示一个英文字符
- 实际只用了 7 位(2⁷=128 个字符),留 1 位扩展空间
- 收录内容:控制字符 33 个、空格 1 个、数字 10 个、大小写字母 52 个、标点符号等

| 编号范围 | 内容 |
|---|---|
| 0~31、127 | 33 个控制字符(ESC、退格等) |
| 32 | 空格 |
| 48~57 | 数字 0~9 |
| 65~90 | 大写字母 A~Z |
| 97~122 | 小写字母 a~z |
| 其他 | 标点符号、运算符等 |

```python
print(ord('1'))      # 输出: 49
print(ord('z'))      # 输出: 122
print(ord('A'))      # 输出: 65
print('a' > 'B')     # 字符串比大小参照 ASCII 表,输出: True
```

### 5.2.2 GBK 编码

计算机传到中国后,ASCII 无法表示中文,中国制定了 **GBK 编码**。
**特点**

- 英文 1 字节,中文 2 字节
- 通过**首位标识**区分:首位为 0 表示英文(1 字节),首位为 1 表示中文(2 字节)

**技术细节**:GBK 表中的"仙"对应 `484B`,但实际存储时每个字节的首位加 1,变成 `C8CB`:

```python
# 0x48 + 0x80 = 0xC8
# 0x4B + 0x80 = 0xCB
print(hex(0x48 + 0x80))    # 输出: 0xc8
print(hex(0x4B + 0x80))    # 输出: 0xcb
```

**局限**:日本有 Shift_JIS、韩国有 EUC-KR,各国编码不兼容,**诸侯并起导致世界范围内无法统一**。
### 5.2.3 Unicode 万国码

为了统一全世界的字符,1988-1991 年间制定了 **Unicode(万国码)**。
**特点**

- 每个字符统一用 2 字节(16 位)表示
- 涵盖全世界所有语言的字符
- **兼容旧编码**:通过映射表与 GBK、ASCII 等对应

**优点**:全球统一,不再乱码。
**缺点**:

1. **空间浪费**:英文原本 1 字节,现在变 2 字节,存储空间翻倍
2. **IO 延迟增加**:文件变大,从硬盘读写的时间增加


:::note[补充]
Unicode 只是字符集(规定了每个字符的编号),具体如何存储需要编码方案,如 UTF-8、UTF-16、UTF-32。
:::

### 5.2.4 UTF-8 编码

为了解决 Unicode 直接存硬盘的问题,出现了 **UTF-8 编码**。
**特点**

- 英文 1 字节,中文 3 字节(一般情况)
- 可变长编码:根据字符不同使用不同字节数

**编码规则**

| Unicode 范围 | UTF-8 编码(二进制模板) | 字节数 |
|---|---|---|
| 0x0000~0x007F | `0xxxxxxx` | 1 |
| 0x0080~0x07FF | `110xxxxx 10xxxxxx` | 2 |
| 0x0800~0xFFFF | `1110xxxx 10xxxxxx 10xxxxxx` | 3 |

**转换示例:汉字"联"(Unicode: U+8054)**

1. 8054 在 0x0800~0xFFFF 范围,用 3 字节模板:`1110xxxx 10xxxxxx 10xxxxxx`
2. 8054 的二进制:`1000 0000 0101 0100`
3. 填入模板:
   - `1110` + `1000` → `11101000` (E8)
   - `10` + `000001` → `10000001` (81)
   - `10` + `010100` → `10010100` (94)
4. 结果:`E8 81 94`

```python
s = '联'
utf8_bytes = s.encode('utf-8')
print(utf8_bytes)                    # 输出: b'\xe8\x81\x94'
print(' '.join(hex(b) for b in utf8_bytes))   # 输出: 0xe8 0x81 0x94
```

**优点**

- 节省存储空间(对于英文为主的文本)
- 减少 IO 时间
- 兼容 ASCII(ASCII 字符的 UTF-8 编码与 ASCII 相同)

**原则**:内存用 Unicode(方便处理),硬盘存 UTF-8(节省空间),读写时自动转换。
## 5.3 硬盘 IO 与存储优化

### 5.3.1 机械硬盘的工作原理

**机械硬盘(HDD)结构**

- 磁盘盘片:存储数据
- 磁道:盘片上的同心圆环
- 扇区:磁道被分成的小块
- 磁头:读写数据

**IO 延迟 = 平均寻道时间 + 平均旋转时间**

- 寻道时间:磁头移动到目标磁道,约 5ms
- 旋转时间:磁盘旋转到目标扇区,7200 转/分约 4ms
- 总延迟:约 9ms

**优化原则**:能从内存读就不要从硬盘读,尽量减少文件读写。
### 5.3.2 固态硬盘

**固态硬盘(SSD)特点**

- 无机械部件,读写速度快
- 先擦后写,擦写次数有限
- 价格较高

**为什么不能替代内存**

1. 擦写寿命有限
2. 速度仍比内存慢
3. 价格高

### 5.3.3 为什么要用 UTF-8

如果 Unicode 直接存硬盘:

1. 英文文件大小翻倍,浪费空间
2. IO 时间增加,程序变慢

UTF-8 的设计:

- 英文 1 字节,中文 3 字节,**整体上更高效**
- 内存用 Unicode 处理,硬盘存 UTF-8,读写时自动转换


:::warning[注意]
这就是为什么 Python3 默认用 UTF-8 读写文件,而不是 Unicode。
:::

### 5.3.4 著名的"联通"Bug

**问题重现**

在 Windows 旧版记事本中,新建文件输入"联通"二字保存,关闭后再打开,显示为"j" + 乱码。
**原因分析**

1. "联通"的 GBK 编码:`C1 AA CD A8`
2. UTF-8 的 2 字节模板:`110xxxxx 10xxxxxx`
3. 巧合:`C1` 的二进制 `11000001` 符合第一字节模板,`AA` 的二进制 `10101010` 符合第二字节模板
4. 记事本误判为 UTF-8,按 UTF-8 解码:
   - `C1 AA` 被当作 1 个 UTF-8 字符,解码为"j"
   - `CD A8` 不符合 UTF-8 规则,显示为乱码

**结论**:"存乱了"还是"取乱了"?

- 数据本身没问题(GBK 编码正确),是**取乱了**(用错了解码方式)
- 只要用 GBK 打开就正常显示

```python
# 模拟"联通"Bug
text = '联通'
gbk_bytes = text.encode('gbk')
print(gbk_bytes)    # 输出: b'\xc1\xaa\xcd\xa8'

# 错误地用 UTF-8 解码
try:
    result = gbk_bytes.decode('utf-8')
except UnicodeDecodeError as e:
    print(f'解码失败: {e}')
# 现代 Python 会报错,而旧记事本会尝试强制解码
```

## 5.4 Python 中的编码解码

### 5.4.1 Python2 vs Python3

**文件读取默认编码**

- Python2:默认 ASCII
- Python3:默认 UTF-8

**字符串在内存中的存储**

- Python2:按文件头编码存储,需要 `u'字符串'` 指定 Unicode
- Python3:统一用 Unicode 存储,不会乱码


:::warning[注意]
本教程主要讲 Python3,Python2 已于 2020 年停止支持。
:::

### 5.4.2 文件头编码声明

**第一阶段和第二阶段:读取 py 文件**

Python3 默认用 UTF-8 读取文件,如果文件不是 UTF-8 编码,需要在文件**第一行**声明:

```python
# coding:gbk
# 或
# -*- coding: gbk -*-
```

**注意**:

- 文件头只控制 Python 如何"读取"文件
- 文件实际用什么编码保存,由文本编辑器决定
- **两者必须匹配**,否则读取时会乱码或报错

### 5.4.3 encode 和 decode

**encode:字符串 → bytes**

```python
s = '你好'
b = s.encode('utf-8')
print(b)            # 输出: b'\xe4\xbd\xa0\xe5\xa5\xbd'
print(type(b))      # 输出: <class 'bytes'>
```

**decode:bytes → 字符串**

```python
b = b'\xe4\xbd\xa0\xe5\xa5\xbd'
s = b.decode('utf-8')
print(s)            # 输出: 你好
print(type(s))      # 输出: <class 'str'>
```

**bytes 类型**

- Python 对二进制数据的封装
- 显示时:英文/数字显示为字符,其他显示为 `\xhh` 十六进制
- 创建方式:
  - `b'abc'` (只能包含 ASCII 字符)
  - `'你好'.encode('utf-8')`
  - `bytes('你好', encoding='utf-8')`

```python
b1 = b'abc'
print(b1)           # 输出: b'abc'

b2 = '你好123'.encode('utf-8')
print(b2)           # 输出: b'\xe4\xbd\xa0\xe5\xa5\xbd123'
```

### 5.4.4 终端编码

不同终端的默认编码不同:

- PyCharm 内置终端:UTF-8
- Windows CMD/PowerShell:GBK

如果代码中有中文,在 CMD 中运行可能乱码,需要:

1. 保存文件时用 GBK 编码
2. 或者在 CMD 中用 `chcp 65001` 切换到 UTF-8

```python
# 示例:打印中文在不同终端的表现
print('你好,世界')
# PyCharm: 正常显示
# Windows CMD(GBK): 可能乱码,除非文件是 GBK 编码
```

## 5.5 乱码问题的解决

### 5.5.1 两种乱码情况

1. **存乱了**:数据永久损坏,无法恢复
   - 例如:本该用 UTF-8 保存,却用了 GBK

2. **取乱了**:数据完好,用正确的编码重新读取即可
   - 例如:文件是 GBK,却用 UTF-8 打开

### 5.5.2 防止乱码的原则

**保存文件时**

1. 统一用 UTF-8 保存
2. 如果必须用其他编码,在文件头声明

**读取文件时**

1. 明确文件的编码
2. 用对应的编码打开
3. 不确定时可以尝试常见编码(UTF-8、GBK)

**Python 代码中**
```python
# 读文件时指定编码
with open('test.txt', 'r', encoding='utf-8') as f:
    content = f.read()

# 写文件时指定编码
with open('test.txt', 'w', encoding='utf-8') as f:
    f.write('你好')
```

### 5.5.3 实战:编码转换

**场景**:有一个 GBK 编码的文件,需要转成 UTF-8。
```python
# 读取 GBK 文件
with open('gbk_file.txt', 'r', encoding='gbk') as f:
    content = f.read()

# 写入 UTF-8 文件
with open('utf8_file.txt', 'w', encoding='utf-8') as f:
    f.write(content)
```

**原理**:

1. 用 GBK 读取 → 内存中是 Unicode
2. 用 UTF-8 写入 → 自动转成 UTF-8 存入硬盘

### 5.5.4 常见报错

**UnicodeDecodeError**

```python
# 文件是 GBK,但用 UTF-8 打开
with open('gbk_file.txt', 'r', encoding='utf-8') as f:
    content = f.read()
# 报错: UnicodeDecodeError: 'utf-8' codec can't decode byte...
```

**解决方法**:

1. 确认文件的真实编码
2. 用正确的编码打开
3. 或者用 `errors='ignore'` 忽略错误(会丢失部分数据)

```python
with open('gbk_file.txt', 'r', encoding='utf-8', errors='ignore') as f:
    content = f.read()
```


:::warning[注意]
`errors='ignore'` 会丢弃无法解码的字节,只在无法确定编码且丢失数据可接受时使用。
:::

## 本章小结

- **字符编码用在两处**:文本文件读写、Python 定义字符串。
- **字符编码表**:字符与数字一一对应,编码(encode)和解码(decode)必须用同一张表。
- **编码发展**:ASCII(英文 1 字节) → GBK 等各国编码(英文 1 字节,中文 2 字节) → Unicode(统一 2 字节) → UTF-8(可变长,英文 1 字节,中文 3 字节)。
- **UTF-8 优势**:兼容 ASCII,节省空间,减少 IO 时间;内存用 Unicode,硬盘存 UTF-8。
- **硬盘 IO**:机械硬盘有寻道和旋转延迟(约 9ms),固态硬盘快但有擦写寿命限制;优化原则是减少硬盘读写。
- **"联通"Bug**:GBK 编码的"联通"被误判为 UTF-8,属于"取乱了"而非"存乱了"。
- **Python 编码**:Python3 默认 UTF-8;文件头声明(`# coding:编码`)控制读取,必须与文件实际编码匹配;`encode()` 和 `decode()` 在字符串和 bytes 之间转换。
- **防止乱码**:统一用 UTF-8;明确文件编码;读写文件时指定 `encoding` 参数。
