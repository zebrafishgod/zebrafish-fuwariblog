## 12.1 正则表达式入门与限定符

### 什么是正则表达式

**正则表达式（regular expression，简称 regex）可以看成一种"查找规则"**，作用是帮我们匹配符合指定规则的字符串。

**它是跨语言的规则，不是某门语言的功能**。每种编程语言里写法都一样，只是实现匹配的函数不同。

常见的应用场景：

- PyCharm 等 IDE 自动匹配关键字、给不同关键字上色；
- 网站注册时用正则判断密码复杂度、校验手机号邮箱格式；
- 写爬虫时从网页文本里提取需要的数据；
- 各种编辑器的查找替换功能。

### 在编辑器中体验正则替换

**正则替换可以一次改完一整片文本，不用逐行手工改**。一段 HTTP 请求头文本，要改成字典的写法，手动一行行改很麻烦，用正则一次搞定：

1. 按 `Ctrl + R` 打开 PyCharm 的替换面板；
2. **点亮搜索框右侧的 `.*` 按钮**，开启正则匹配（不点亮就只是普通文本查找）；
3. 查找框填 `(.*): (.*)`，替换框填 `'$1': '$2',`，点 `Replace All`。

```text
替换前：                          替换后：
Host: www.baidu.com              'Host': 'www.baidu.com',
Connection: keep-alive           'Connection': 'keep-alive',
Accept-Language: zh-CN           'Accept-Language': 'zh-CN',
```

其中 `$1`、`$2` 分别代表第 1、第 2 个小括号里匹配到的内容。


:::tip[技巧]
一行太长时可以开启自动换行：`Settings` 里搜索 `wrap`，找到 `Soft-Wrap` 右键加个快捷键（如 `Alt + Z`），之后按快捷键即可切换。
:::


在替换框里输入正则后，**被成功匹配的文本会高亮显示**，可以借这种方式边写边验证规则。

### 限定符：控制前面一个字符出现的次数

**限定符（quantifier）永远只管它前面那一个字符**，这是后面所有量词用法的前提。

**六个常用限定符的含义如下**：

| 限定符 | 含义 |
|---|---|
| `*` | 前面的字符出现 0 次或多次 |
| `+` | 前面的字符出现 1 次或多次 |
| `?` | 前面的字符出现 0 次或 1 次（可有可无） |
| `{5}` | 恰好 5 次 |
| `{2,5}` | 2 到 5 次（含两端） |
| `{2,}` | 2 次及以上 |

```python
import re

s = 'xg xyg xyyg xyyyyg xyyyyyg'
print(re.findall(r'xy*g', s))         # 输出: ['xg', 'xyg', 'xyyg', 'xyyyyg', 'xyyyyyg']
print(re.findall(r'xy+g', s))         # 输出: ['xyg', 'xyyg', 'xyyyyg', 'xyyyyyg']
print(re.findall(r'xy{5}g', s))       # 输出: ['xyyyyyg']
print(re.findall(r'xy{2,5}g', s))     # 输出: ['xyyg', 'xyyyyg', 'xyyyyyg']
print(re.findall(r'xy{2,}g', s))      # 输出: ['xyyg', 'xyyyyg', 'xyyyyyg']
print(re.findall(r'flags?', 'flag flags'))   # 输出: ['flag', 'flags']
```


:::note[补充]
这里提前用到了 `re.findall(规则, 字符串)`：找出所有匹配结果，以列表返回（12.4 节详讲）。规则字符串前加 `r` 表示原始字符串，可避免反斜杠被 Python 先转义一次。`xy{2,5}g` 里的 `{2,5}` 作用范围是 `g` 前面的那个 `y`，不是整个 `xy`。
:::


## 12.2 分组、字符类、元字符与贪婪匹配

### 小括号、或运算与字符组

**限定符只针对一个字符**。想让一组字符整体重复，先用小括号括起来，再写限定符——这才是分组最基础的用途。

**或运算用竖线 `|`**：匹配 `play the piano` 或 `play the guitar`，写成 `play the (piano|guitar)`。**小括号不能少**，否则 `play the piano|guitar` 的意思会变成"要么是 `play the piano`，要么是 `guitar`"。

**字符组用中括号 `[]`，中括号里的字符任取其一**。常用写法有：

| 写法 | 含义 |
|---|---|
| `[xyg]+` | 由 x、y、g 之一构成的单词 |
| `[a-z]` | 所有小写字母 |
| `[a-zA-Z]` | 所有英文字母 |
| `[a-zA-Z0-9]` | 所有英文字母和数字 |
| `[^0-9]` | `^` 写在中括号开头表示**取反**：所有非数字字符，包括换行符、制表符等 |

### 元字符

**正则内置了一批常用字符类型，称为元字符（metacharacter）**，大多以反斜杠开头，用来代替一长串字符组。

| 元字符 | 含义 |
|---|---|
| `\d` / `\D` | 数字字符（等价 `[0-9]`）/ 非数字字符 |
| `\w` / `\W` | 单词字符（字母、数字、下划线）/ 非单词字符 |
| `\s` / `\S` | 空白字符 / 非空白字符 |
| `\b` | 单词边界 |
| `.` | 句点符，任意字符，但**不包括换行符** |
| `^` | 匹配**行首**，如 `^x` 只匹配行首的 x |
| `$` | 匹配**行尾**，如 `x$` 只匹配行尾的 x |


```python
import re

print(re.findall(r'(?:xy)+', 'xyxyxy ab xy'))          # 输出: ['xyxyxy', 'xy']
print(re.findall(r'play the (?:piano|guitar)', 'play the piano, play the guitar'))
# 输出: ['play the piano', 'play the guitar']
print(re.findall(r'\b[xyg]+\b', 'xyg gyx abc yy'))     # 输出: ['xyg', 'gyx', 'yy']
print(re.findall(r'[^0-9]+', 'ab12cd3'))              # 输出: ['ab', 'cd']
print(re.findall(r'\d+', 'a1b22c333'))                # 输出: ['1', '22', '333']
```


:::warning[注意]
`^` 写在**中括号外面**是"匹配行首"，写在**中括号里面**（紧跟左括号）是"取反"，两者完全不同，要分清位置。
:::



:::note[补充]
在编辑器里写 `(xy)+` 没问题，但在 Python 里小括号会被当作分组，`findall` 只返回括号里的内容，所以上面的例子用了 `(?:...)`，原因见 12.5 节。
:::


### 贪婪匹配与懒惰匹配

**`*`、`+`、`{}` 默认都是贪婪匹配（greedy），会尽可能多吃字符**，这是正则最容易踩的坑之一。比如想匹配 HTML 里的单个标签，写 `<.+>`，`.` 代表任意字符，`.+` 会一路吃到最后一个 `>`，把整个字符串都吞掉。

结论 → 原因 → 例子：

- **结论**：在量词后面加一个 `?`，就从贪婪切换成**懒惰匹配（lazy / non-greedy）**，尽可能少匹配；
- **原因**：`+?` 表示"匹配 1 次以上，但能少就少"；
- **例子**：`<.+?>` 会先匹配到第一个 `>` 就停。

```python
import re

html = '<div><span>内容</span></div>'
print(re.findall(r'<.+>', html))    # 贪婪，输出: ['<div><span>内容</span></div>']
print(re.findall(r'<.+?>', html))   # 懒惰，输出: ['<div>', '<span>', '</span>', '</div>']
```

### 转义

**想让带特殊含义的符号只当普通字符，就给它加反斜杠**。想匹配 `.` 这个字符本身，直接写 `.` 会匹配任意字符，所以在前面加反斜杠：`\.`。这跟 Python 字符串里用反斜杠转义是一个道理。需要转义的还有 `\*`、`\+`、`\?`、`\(`、`\[` 等有特殊含义的符号。

```python
import re

print(re.findall(r'\.', 'a.b.c'))   # 输出: ['.', '.']
```

## 12.3 实战：匹配手机号

**手机号正则的思路是把号段和后续位数拼起来**。手机号按号段编写正则。以常见号段为例（不一定是最新的）：

- 13 开头：130~139 都有 → `13[0-9]`
- 14 开头：145~149 → `14[5-9]`
- 15 开头：150~153、155~159 → `15[0-35-9]`
- 其他号段同理。

号段后面还有 8 位数字，写 `\d{8}`；几个号段之间用 `|`（或）连接，外面套一层括号：

```text
(13[0-9]|14[5-9]|15[0-35-9])\d{8}
```

这样还有两个问题：

1. 字母开头的也匹配到了 → 前面加 `^`，严格要求必须以这些号段开头；
2. 超过 11 位的长串也匹配到了 → 后面加 `$`，要求 11 位数字后就结束。

```text
^(13[0-9]|14[5-9]|15[0-35-9])\d{8}$
```

用户注册时输入手机号，就可以用这种方式限制输入格式。

### `^` 只匹配行首带来的坑

**`^` 只认行首，想匹配任意位置就得换成 `\b`**。如果一行里有多个手机号想全部匹配，把 `$` 换成 `\b`（单词边界）：11 位号码后面必须是空白或边界，超长串就不会匹配。但**行中间**的号码仍然匹配不到，问题出在前面的 `^`：


:::warning[注意]
`^` 匹配的是**行首**。要匹配的内容不在一行的最前面，就匹配不到。很多教程说 `^` 是"匹配开头"，结果自己一用什么都匹配不到，原因就在这里。要匹配任意位置的号码，把 `^` 也换成 `\b`。
:::


```text
\b(13[0-9]|14[5-9]|15[0-35-9])\d{8}\b
```

也可以偷懒写成 `\b1\d{10}\b`，但不够严谨。

### 不必自己写所有正则

**现成正则可以直接搜，但看懂和改的能力不能省**。要匹配网址、邮箱、身份证号等，直接搜"身份证号正则表达式"就能找到现成的。但这不代表可以不掌握正则：

- 拿到别人写的正则，你得能看懂；
- 需要定制时（比如爬虫里在特定上下文提取数据）还得自己写。

掌握本章这些知识点就够用了。

## 12.4 re 模块：findall 与 flags 参数

### findall 与点号的行为

**Python 用内置的 `re` 模块做正则匹配**，其中最常用的入口是 `re.findall(正则, 字符串)`，它返回所有匹配结果组成的列表。

**点号默认匹配不到换行符**，所以 `.` 再贪婪也会被 `\n` 切断。

```python
import re

print(re.findall(r'.+', 'abc\ndef\ng'))                    # 输出: ['abc', 'def', 'g']
print(re.findall(r'.+', 'abc\ndef\ng', flags=re.DOTALL))   # 输出: ['abc\ndef\ng']
```

`.` 不匹配换行符，所以即使 `+` 再贪婪，也被 `\n` 隔开，被迫切成三段。传 `flags=re.DOTALL` 让 `.` 也能匹配换行符后，整个字符串就成了一个结果。

### flags 参数

**flags 控制匹配的行为方式**，不了解它会踩很多坑。不用背，用时查文档即可（搜 `python re flags` 进 docs.python.org 的 re 文档，左侧点 `Flags`）。常用的三个：

| 标志 | 全称 | 作用 |
|---|---|---|
| `re.I` | `re.IGNORECASE` | 不区分大小写 |
| `re.M` | `re.MULTILINE` | 让 `^`/`$` 匹配**每一行**的开头和结尾 |
| `re.S` | `re.DOTALL` | 让 `.` 匹配所有字符，包括换行符 |

此外 `re.A`（`re.ASCII`）只考虑 ASCII 字符，不常用。简写和全称作用完全一样，掌握 `re.I`、`re.M`、`re.S` 即可。

```python
import re

print(re.findall(r'python', 'Python PYTHON python', flags=re.I))
# 输出: ['Python', 'PYTHON', 'python']

s = 'xg\nxyg\nxyyg'
print(re.findall(r'^x', s))               # 只匹配第一行开头的 x，输出: ['x']
print(re.findall(r'^x', s, flags=re.M))   # 每一行的开头，输出: ['x', 'x', 'x']
```


:::warning[注意]
在编辑器里演示时，`^` 好像能匹配每一行开头；但在 Python 里 `^` **默认只匹配整个字符串的开头**。要达到编辑器里的效果，必须显式传 `flags=re.M`。这是编辑器默认开了多行模式造成的错觉。
:::


## 12.5 re 模块：分组、search 与 finditer

### 坑：小括号就是分组

**在 Python 里，正则中的小括号一律会被当作分组**，这是从编辑器搬代码过来最常踩的坑。用 Python 实现手机号匹配：

```python
import re

phone_number = '13812345678 14712345678 15512345678 15412345678'

print(re.findall(r'\b(13[0-9]|14[5-9]|15[0-35-9])\d{8}\b', phone_number))
# 输出: ['138', '147', '155']  —— 只匹配出前三位，而不是完整手机号
```

正则本身没问题，问题在于：**在编程语言里，正则中的小括号会被视为匹配边界**，括号里的内容是一个**分组（group）**，`findall` 只返回分组里的内容。

解决办法是在小括号内的最前面加 `?:`，声明这个括号**只用于归类、不作为分组**：

```python
import re

phone_number = '13812345678 14712345678 15512345678 15412345678'
print(re.findall(r'\b(?:13[0-9]|14[5-9]|15[0-35-9])\d{8}\b', phone_number))
# 输出: ['13812345678', '14712345678', '15512345678']   （154 号段未开通，不匹配）
```

### re.search

**search 只返回第一个匹配，且结果是 Match 对象而不是字符串列表**。用法和 `findall` 一样，区别在返回值：只匹配符合规则的**第一个**值，返回一个 **Match 对象（匹配对象）**；匹配不到返回 `None`。

以座机号为例：区号 3 或 4 位，电话号 7 或 8 位，正则为 `\d{3,4}-\d{7,8}`。

```python
import re

s = '座机号码010-1234567，欢迎来电'
res = re.search(r'\d{3,4}-\d{7,8}', s)
print(res)           # 输出: <re.Match object; span=(4, 15), match='010-1234567'>
print(res.span())    # 数据所在位置：从索引 4 到索引 15，输出: (4, 15)
print(res.group())   # 正则匹配到的内容，输出: 010-1234567
```

把区号和号码分别用小括号括起来，匹配结果不变，但可以给 `group()` 传参取出**某一组**的内容：

```python
import re

s = '座机号码010-1234567，欢迎来电'
res = re.search(r'(\d{3,4})-(\d{7,8})', s)
print(res.group())    # 整体，输出: 010-1234567
print(res.group(1))   # 第 1 组（区号），输出: 010
print(res.group(2))   # 第 2 组（号码），输出: 1234567
```


:::warning[注意]
匹配不到时 `search` 返回 `None`，直接 `.group()` 会抛 `AttributeError`。用之前先判断 `if res:`。
:::


### re.finditer

**finditer 返回迭代器，每一项都是能取分组的 Match 对象**。看名字就知道它返回一个**迭代器**：匹配**所有**符合规则的项，迭代到的每一项同样是 Match 对象，所以也有 `group` 方法。

```python
import re

s = '座机号码010-1234567，备用0755-87654321'
res = re.finditer(r'(\d{3,4})-(\d{7,8})', s)
for m in res:
    print(m.group(), m.group(1), m.group(2))
# 输出:
# 010-1234567 010 1234567
# 0755-87654321 0755 87654321
```

用 `finditer` 也可以在循环里同时看到每项的分组，比 `findall` 返回纯列表更灵活。

## 12.6 re 模块：match 与 fullmatch

### 用分组把请求头转成字典

回到 12.1 节 PyCharm 里的例子：一组小括号 `(.*)`，接冒号加空格，再一组小括号 `(.*)`。用 `finditer` 实现：

```python
import re

s = """Host: www.baidu.com
Connection: keep-alive
Accept-Language: zh-CN"""

dic = {}
for m in re.finditer(r'(.*): (.*)', s):
    dic[m.group(1)] = m.group(2)     # 冒号左边是第 1 组，右边是第 2 组
print(dic)
# 输出: {'Host': 'www.baidu.com', 'Connection': 'keep-alive', 'Accept-Language': 'zh-CN'}
```

这里的 `group(1)`、`group(2)` 就相当于 PyCharm 替换框里的 `$1`、`$2`：编辑器给的是 `$1`，Python 给的是 `group()`。

### re.match 与 re.fullmatch

**re.match：只从字符串开头匹配**

和 `search` 一样，只匹配第一个值、返回 Match 对象、匹配不到返回 `None`。差别是它**只能从字符串开头匹配**——注意是**字符串**的开头，不是每一行的开头；即使加 `flags=re.M` 也只匹配第一行开头。

**re.fullmatch：整串都必须符合**

**从头匹配到尾**：整个字符串都要符合规则。成功返回 Match 对象，失败返回 `None`，非常适合做格式校验。

```python
import re

s = 'abc\n123'
print(re.match(r'\d+', s))                 # 字符串开头不是数字，输出: None
print(re.match(r'\d+', s, flags=re.M))     # 加了 re.M 也只看字符串开头，输出: None
print(re.match(r'[a-z]+', s).group())      # 输出: abc

print(re.fullmatch(r'1[3-9]\d{9}', '13812345678'))    # 整体符合，输出 Match 对象
print(re.fullmatch(r'1[3-9]\d{9}', '13812345678a'))   # 多一个字符，输出: None
```

### 命名分组 (?P<name>...)

**分组多了以后，靠 `group(1)`、`group(2)` 记顺序容易混，可以给分组起名字**：`(?P<name>...)`，然后用 `group('name')` 或多个一起用 `groupdict()` 取出。

```python
import re

m = re.match(r'(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})', '2026-10-10')
print(m.group('y'), m.group('m'), m.group('d'))   # 输出: 2026 10 10
print(m.groupdict())                              # 输出: {'y': '2026', 'm': '10', 'd': '10'}
```

结论：**命名分组特别适合从结构化文本里提字段**，代码可读性比数字下标高很多。

## 12.7 re 模块：sub、subn、split 与 compile

### re.sub：替换

**`re.sub(正则, 替换成什么, 字符串)` 把匹配到的内容替换掉**，第二个参数传字符串或函数都行。

```python
import re

s = '座机号码010-1234567，备用0755-7654321'
print(re.sub(r'(\d{3,4})-(\d{7,8})', '***', s))
# 输出: 座机号码***，备用***
```

第二个参数除了传字符串，还可以传一个**函数**。`sub` 每匹配到一处就构造一个 Match 对象并调用这个函数，**函数的返回值用来替换原内容**。

典型应用是**脱敏**：把电话号码中间几位用星号遮住（外卖单、网约车上的号码就是脱敏过的）。

```python
import re


def hide(m):                          # m 接收 sub 传进来的 Match 对象
    area = m.group(1)                 # 第 1 组：区号
    tel = m.group(2)                  # 第 2 组：电话号码
    return area + '-' + tel[:2] + '***' + tel[-2:]


s = '座机号码010-1234567，备用0755-7654321'
print(re.sub(r'(\d{3,4})-(\d{7,8})', hide, s))   # 传函数名，不加括号
# 输出: 座机号码010-12***67，备用0755-76***21
```

也可以在替换字符串里用 `\1`、`\2` 反向引用分组，例如把 `2026-10-10` 改成 `10/10/2026`：

```python
import re

print(re.sub(r'(\d{4})-(\d{2})-(\d{2})', r'\2/\3/\1', '2026-10-10'))
# 输出: 10/10/2026
```


:::warning[注意]
替换串里用 `\1` 时，一定要写成原始字符串 `r'\2/\3/\1'`，否则 `\1` 会被 Python 当成八进制转义字符处理，结果是错的。
:::


### re.subn

**它和 sub 的用法完全一样，只是多返回一个替换次数**。

```python
import re

print(re.subn(r'\d', '#', 'a1b2c3'))    # 输出: ('a#b#c#', 3)
```

### re.split：按正则拆分

**字符串自带的 split 只能按固定分隔符拆，正则可以按"任意非单词字符"这类规则拆**。遇到脏数据时 `s.split` 就没办法了，用正则可以轻松处理。

```python
import re

s = 'hello, world -- python>>> regex!'
print(s.split(','))           # 输出: ['hello', ' world -- python>>> regex!']  还是很乱
print(re.split(r'\W', s))     # 每个非单词字符都当分隔符，产生大量空串
print(re.split(r'\W+', s))    # 连续的非单词字符整体当一个分隔符
# 输出: ['hello', 'world', 'python', 'regex', '']
```

### re.compile：编译正则对象

**compile 把正则编译成 Pattern 对象，之后调用方法不用再传正则**，适合同一个正则被多次使用的场景。给 `compile` 传一个正则，返回一个**正则表达式对象（Pattern）**，之后直接调用它的 `findall`、`finditer` 等方法。

```python
import re

pat = re.compile(r'(\d{3,4})-(\d{7,8})')
print(pat.findall('010-1234567 0755-87654321'))
# 输出: [('010', '1234567'), ('0755', '87654321')]
for m in pat.finditer('010-1234567 0755-87654321'):
    print(m.group())
# 输出:
# 010-1234567
# 0755-87654321
```


:::tip[技巧]
`re` 下的所有函数都能传 `flags`；`compile` 时也可以直接把 flags 一起带上，例如 `re.compile(r'abc', re.I)`。
:::


## 12.8 实战：校验邮箱、日期与提取数据

### 校验数据格式

**结论：用 `fullmatch` 做校验最省心**，因为它要求整串符合规则，不用自己补 `^` 和 `$`。

```python
import re

# 邮箱：用户名@域名.后缀，这里用简化规则，够应付大多数校验场景
print(bool(re.fullmatch(r'\w+@\w+\.\w+', 'abc@qq.com')))   # 输出: True
print(bool(re.fullmatch(r'\w+@\w+\.\w+', 'abc@qq')))       # 输出: False

# 日期：2026-10-10 这类
print(bool(re.fullmatch(r'\d{4}-\d{2}-\d{2}', '2026-10-10')))   # 输出: True
```


:::note[补充]
严格校验邮箱的正则非常长且难懂，实际项目里通常只做"大致格式"校验，真正的可用性靠发送验证邮件确认。日期同理，正只能校验形状，要判断 2 月有没有 30 号还得用 `datetime`。
:::


### 从文本里提取数据

**提取数据主要靠 findall 配合 `\b` 这类边界**，把散落在文本里的手机号、邮箱捞出来。

```python
import re

text = '张三 13812345678，李四 15900001111，客服邮箱 help@shop.com'

phones = re.findall(r'\b1[3-9]\d{9}\b', text)
print(phones)      # 输出: ['13812345678', '15900001111']

mails = re.findall(r'\w+@\w+\.\w+', text)
print(mails)       # 输出: ['help@shop.com']
```

### 提取带标签/固定格式的字段

**带命名分组的正则特别适合爬虫里解析数据**，字段名可以直接写在规则里。

```python
import re

html = '<a href="https://a.com">链接A</a><a href="https://b.com">链接B</a>'
for m in re.finditer(r'<a href="(?P<url>.+?)">(?P<text>.+?)</a>', html):
    print(m.group('text'), '->', m.group('url'))
# 输出:
# 链接A -> https://a.com
# 链接B -> https://b.com
```


:::warning[注意]
用正则解析 HTML 只适合结构简单、固定的场景；页面结构复杂时应该用解析库（如 BeautifulSoup），否则正则维护起来很痛苦。
:::


## 12.9 为什么需要 logging

### 为什么需要日志

**print 调试和多级需求都撑不住，才需要专门的标准日志工具**。调试时用 `print` 打印变量看执行状态，项目写完又得一条条注释掉，项目大、模块多时非常麻烦。自己写"打开文件写日志"的函数，也只能打印或只能写文件，级别、格式、是否输出都得自己判断。

**需要一个标准的、可配置的日志工具**，`logging` 就是 Python 内置的这个模块，`import logging` 即可。

### 五个日志级别

**日志按重要性分五级，级别越高越严重，数值就是过滤的门槛**：

| 级别 | 数值 | 用途 |
|---|---|---|
| `DEBUG` | 10 | 调试日志：调试代码时输出的信息 |
| `INFO` | 20 | 消息日志：正常日志，如某用户何时登录、充值了多少 |
| `WARNING` | 30 | 警告日志：磁盘空间不足了，程序还能跑，但不处理就可能出错 |
| `ERROR` | 40 | 错误日志：某部分功能已经出错，但这个错误**是被捕获的**，不是程序直接崩溃 |
| `CRITICAL` | 50 | 严重错误：程序已经不能正常执行、面临崩溃 |

**ERROR 与 CRITICAL 的区别在程序还能不能用**：ERROR 对应那种"软件还能用，但点某个功能弹提示"文件丢失""网络原因""的错误，要捕获下来记成日志，绝不能让程序直接崩掉；CRITICAL 则对应"QQ、迅雷打不开，弹窗让你上传日志信息"这类，日志输出完程序可能就崩了。

### 用日志代替 print 调试

**结论：用 `logging.debug(...)` 代替 `print`，靠配置级别控制输出，不用改代码。**

结论 → 原因 → 例子：

- **结论**：调试时配成 `DEBUG` 级别，所有级别都输出；上线后配成 `INFO`，比它低的 `DEBUG` 就自动不输出了；
- **原因**：日志比 `print` 多了级别、格式、输出目标（控制台/文件）三样可配置的东西。

```python
import logging

logging.debug('调试日志')
logging.info('消息日志')
logging.warning('硬盘空间不足')
logging.error('错误日志')
logging.critical('严重错误')
# 输出:
# WARNING:root:硬盘空间不足
# ERROR:root:错误日志
# CRITICAL:root:严重错误
```

运行后只打印了 `warning` 及以上，因为**默认的日志输出级别是 WARNING**。输出格式 `WARNING:root:硬盘空间不足` 中：**第一部分是级别**，`root` 是日志的名字（后面可以改），最后是日志内容。

## 12.10 logging 基本配置 basicConfig

改输出级别限制要用 `logging.basicConfig`。这段配置不用背，用时复制再改即可。

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,        # 级别：DEBUG 时所有日志都输出（默认 WARNING=30，DEBUG=10）
    format='%(asctime)s - %(name)s - %(pathname)s[line:%(lineno)d] - %(levelname)s - %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S',  # 设置后 asctime 不再带毫秒
    # filename='access.log',      # 指定后日志写入文件，不再打印到控制台
)

logging.debug('调试日志')
logging.warning('硬盘空间不足')
# 输出类似:
# 2026-10-10 12:00:00 - root - D:\demo\run.py[line:16] - DEBUG - 调试日志
# 2026-10-10 12:00:00 - root - D:\demo\run.py[line:17] - WARNING - 硬盘空间不足
```

`format` 里常见字段：

| 占位符 | 含义 |
|---|---|
| `%(asctime)s` | 当前时间 |
| `%(name)s` | 当前日志的名字 |
| `%(pathname)s` | 哪个文件产生的这条日志 |
| `%(filename)s` | 文件名（不含路径） |
| `%(lineno)d` | 第几行代码产生的 |
| `%(levelname)s` | 日志等级 |
| `%(message)s` | 日志具体内容 |

有了这些信息，就能清楚地知道在哪个时间、哪个文件的哪一行产生了什么日志。

- 不设 `datefmt` 时时间后面会多出**毫秒**，用 `datefmt` 改掉，里面的符号就是时间格式化那套写法；
- 格式可以随意定制，想换成小括号直接改 `format` 字符串即可。

### 写入文件与中文乱码

**指定 `filename` 就写文件，不指定就打到控制台**。指定路径后不再打印到控制台，转而写入文件；写相对路径会在执行文件同级目录生成日志文件。

**Windows 上写文件容易中文乱码**，原因是写日志时没指定字符编码：Windows 下按系统默认 GBK 写入，而编辑器默认用 UTF-8 打开，两边对不上。这个问题只在 Windows 上出现，Linux/Mac 默认就是 UTF-8。


:::note[补充]
Python 3.9 起 `basicConfig` 新增了 `encoding` 参数，可以写 `logging.basicConfig(filename='access.log', encoding='utf-8')` 解决乱码。但 `basicConfig` **仍然无法同时输出到文件又输出到终端**，所以下一节的配置字典才是项目里的标准做法。
:::


## 12.11 日志配置字典：formatters、handlers、loggers

除了编码问题，若想把日志**同时写入文件和输出到终端**，`basicConfig` 也做不到。这就需要**日志配置字典**：把 `logging` 各方面的配置写在一个字典里，再让 `logging` 加载使用。

这个字典不用自己写，复制模板再改即可；要学的是**看懂**里面的配置项，用到项目里时知道怎么改。既然是配置，就应放到 `settings.py`（写项目时按目录规范放到 `conf/settings.py`）。字典很长别慌，在 PyCharm 里按 `Ctrl + Shift + 减号` 全部折叠再逐项展开看。

```python
# settings.py 中配置字典的第一部分
standard_format = '[%(asctime)s][%(threadName)s:%(thread)d][task_id:%(name)s][%(filename)s:%(lineno)d]' \
                  '[%(levelname)s][%(message)s]'
simple_format = '[%(levelname)s][%(asctime)s][%(filename)s:%(lineno)d]%(message)s'
test_format = '%(asctime)s] %(message)s'

LOGGING_DIC = {
    'version': 1,                         # 版本号，可自行标注第几版，一般不用管
    'disable_existing_loggers': False,    # 默认即可，不用管
    'formatters': {                       # 日志格式，复数：可定义多种格式
        'standard': {'format': standard_format},   # key 是格式名，用的时候按名字取
        'simple': {'format': simple_format},
        'test': {'format': test_format},
    },
    'filters': {},                        # 过滤器，默认即可
    'handlers': {},                       # 日志处理器，12.12 节讲
    'loggers': {},                        # 日志记录器，12.13 节讲
}
```

- `formatters` 里每个键值对就是一种日志格式，key 即格式名。`standard` 内容最全，`simple` 简单一些，`test` 只有时间和日志内容。三种都是自己定制的，不喜欢可以复制一份改名再改格式。
- `filters` 是过滤器，一般用不到。
- 只需重点掌握 **`formatters`、`handlers`、`loggers`** 三部分。


:::note[补充]
每种格式里还能加 `'datefmt'` 配置 `asctime` 的时间格式，例如 `'standard': {'format': standard_format, 'datefmt': '%Y-%m-%d %H:%M:%S'}`。
:::


## 12.12 日志处理器 handlers

**Python 的日志采用 logger 生产、handler 处理的分工模型**。**handler（处理器）** 与 **logger（记录器）** 是一对概念：

- **logger 负责生产**不同级别的日志，再把日志交给 handler；
- **handler 负责处理**这些日志：输出到控制台还是写文件？写文件 A 还是文件 B？都由 handler 决定。

**一个配置里可以挂多个 handler 各干各的**：handler1 往终端打印，handler2 写文件 A，handler3 写文件 B 的同时也往终端输出。

```text
# 配置字典中 handlers 部分
'handlers': {
    # 输出到终端（console），级别是 debug。名字要见名知意
    'console_debug_handler': {
        'level': 'DEBUG',                    # 级别限制，也可以写数字 10（10~50）
        'class': 'logging.StreamHandler',    # StreamHandler：输出到终端
        'formatter': 'simple',               # 用 formatters 里的 simple
    },
    # 写入文件的 handler
    'file_debug_handler': {
        'level': 'DEBUG',
        'class': 'logging.FileHandler',      # FileHandler：往文件写日志
        'filename': 'test.log',              # 文件路径，演示用相对路径
        'encoding': 'utf-8',                 # 写文件编码，解决上一节的乱码问题
        'formatter': 'test'},
},
```

**handler 的名字可以随便取，但要见名知意**（写 `AA` 也行，但要像 `console_debug_handler` 这样见名知意）；**`formatter` 只写格式名**，logging 后台会自己去 `formatters` 里找；写项目时文件路径要**动态获取**，例如写到项目根目录 `log` 文件夹下；`encoding` 是 handler 级别的配置，这也是它能解决 `basicConfig` 乱码问题的原因。

**最后一步是产生日志的 logger，handler 只负责处理**。

## 12.13 日志记录器 loggers 与两层过滤

```text
# 配置字典中 loggers 部分
'loggers': {
    'logger1': {
        'handlers': ['console_debug_handler'],   # 产生的日志交给哪些 handler
        'level': 'DEBUG',                        # logger 自己的级别
        'propagate': False,                      # 不往父级 logger 传递
    },
    'logger2': {
        'handlers': ['console_debug_handler', 'file_debug_handler'],
        'level': 'INFO',
        'propagate': False,
    },
},
```

**handlers 决定日志的去向**：值是一个列表，指定这个 logger 产生的日志交给哪些 handler。`logger1` 只交给 `console_debug_handler`，日志就只输出到终端；`logger2` 交给两个，日志既到终端也存文件。

**level 和 handler 级别是两层筛选，互不冲突**：logger 自己也有级别，与 handler 的级别**不冲突，是两层筛选**。logger 级别为 debug 时，它会记录所有级别并传给 handler；到了 handler，若 handler 级别是 warning，就会丢弃 warning 以下的日志。

**propagate 设为 False 才不会重复输出**：涉及 logger 的父子关系，默认 `True`，即默认会把日志继续传给更高一级的 logger。正常应设为 `False`——自己产生的日志交给自己的 handler 就够了，否则会重复输出。

### 加载配置字典：`logging.config` 的导入问题

**logging 是包，config 是包里的子模块，所以 `logging.config` 不能直接用**。配置写好后要让 `logging` 加载这个字典，但直接写 `logging.config` 会报错：

```python
import logging

logging.config   # 会报错: AttributeError: module 'logging' has no attribute 'config'
```

**原因是 `import logging` 只导入了 `logging/__init__.py`**，而 `config` 这个名字没有被放进 `__init__.py`。两种正确的导入方式：

```python
from logging import config     # from 方式能找包文件夹里的子模块

print(config.dictConfig)       # 能用，但用不了 logging.getLogger
```

```python
import logging.config          # 会连 logging 一起导入

logging.config   # 能用，且 logging.getLogger 等也能用
```

### `from 包 import 名字` 会执行 `__init__.py`

**用 `from logging import config` 时，`__init__.py` 一定会被执行，但 `logging` 这个名字不可用**。`from logging import config` 后，当前文件里**不能用 `logging` 下的其他功能**，因为只导入了 `config` 这个名字。不过 `logging/__init__.py` **确实被执行过**：`from logging import config` 会先检查 `logging/__init__.py` 里有没有 `config`——要检查就一定会执行一遍 `__init__.py`；没有才去 logging 文件夹里找同名子模块。

用自己写的包验证。包 `mm` 下有模块 `module.py`：

```text
mm/
├── __init__.py
└── module.py
```

```python
# 28-模块.py
from mm import module

print(module)    # __init__.py 为空时：拿到 mm/module.py 这个模块
                 # 在 mm/__init__.py 里写 module = 10 后：输出 10
```

结论：**`from mm import module` 优先取 `__init__.py` 里的名字，`__init__.py` 里没有才找文件夹下的子模块。** `import logging.config` 同理，但它会连同包本身一起导入。

### 完整可用示例

**把 formatters、handlers、loggers 拼在一起，就是一个能直接用的配置**，再用 `dictConfig` 加载。

```python
# settings.py
standard_format = '[%(asctime)s][%(threadName)s:%(thread)d][task_id:%(name)s][%(filename)s:%(lineno)d]' \
                  '[%(levelname)s][%(message)s]'
simple_format = '[%(levelname)s][%(asctime)s][%(filename)s:%(lineno)d]%(message)s'
test_format = '%(asctime)s] %(message)s'

LOGGING_DIC = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'standard': {'format': standard_format},
        'simple': {'format': simple_format},
        'test': {'format': test_format},
    },
    'filters': {},
    'handlers': {
        'console_debug_handler': {
            'level': 'DEBUG',
            'class': 'logging.StreamHandler',
            'formatter': 'simple',
        },
        'file_debug_handler': {
            'level': 'DEBUG',
            'class': 'logging.FileHandler',
            'filename': 'test.log',
            'encoding': 'utf-8',
            'formatter': 'test',
        },
    },
    'loggers': {
        'logger1': {
            'handlers': ['console_debug_handler'],
            'level': 'DEBUG',
            'propagate': False,
        },
        'logger2': {
            'handlers': ['console_debug_handler', 'file_debug_handler'],
            'level': 'INFO',
            'propagate': False,
        },
    },
}
```

```python
# run.py
import logging.config         # 会导入 logging，logging 下的功能都能用

import settings

logging.config.dictConfig(settings.LOGGING_DIC)    # 加载配置字典
logger1 = logging.getLogger('logger1')             # 按名字获取记录器
logger1.info('某某某充值了5毛钱')
# 终端输出类似（simple 格式）:
# [INFO][2026-10-10 12:00:00,123][run.py:7]某某某充值了5毛钱
```

### 两层过滤的效果

**logger 级别先放行、handler 级别再拦一次，这就是两层过滤**。把 `run.py` 里的 `logger1` 改成 `logger2`：它把日志交给两个 handler，终端打印一份，同时写入 `test.log` 一份，且两边格式不同（终端用 `simple`，文件用 `test`）。

此时 `logger2` 级别是 info、两个 handler 都是 debug，两边都有数据。把 `console_debug_handler` 的 `level` 改成 `'WARNING'` 再运行：info 日志在 `logger2` 处放行、在 `file_debug_handler` 处放行，但在 `console_debug_handler` 处被拦下——**终端不打印，`test.log` 里照常多一条**。这就是两层过滤。

## 12.14 日志分类与命名

### 按业务把日志写入不同文件

**想按业务分文件，就多加几个 handler 和 logger**。日志目前都写进同一个 `test.log`，想细分的话，**用户交易**一个文件、**用户操作**另一个文件，加两个 handler 和两个 logger 即可：

```text
# settings.py 的 handlers 中新增
'file_deal_handler': {                 # 用户交易日志
    'level': 'INFO',
    'class': 'logging.FileHandler',
    'filename': 'deal.log',
    'encoding': 'utf-8',
    'formatter': 'standard',
},
'file_operate_handler': {              # 用户操作日志
    'level': 'INFO',
    'class': 'logging.FileHandler',
    'filename': 'operate.log',
    'encoding': 'utf-8',
    'formatter': 'standard',
},

# settings.py 的 loggers 中新增
'logger3': {                           # 记录用户交易
    'handlers': ['console_debug_handler', 'file_deal_handler'],
    'level': 'DEBUG',
    'propagate': False,
},
'logger4': {                           # 记录用户操作
    'handlers': ['file_operate_handler'],
    'level': 'DEBUG',
    'propagate': False,
},
```

```python
# run.py
import logging.config

import settings

logging.config.dictConfig(settings.LOGGING_DIC)
logger3 = logging.getLogger('logger3')
logger4 = logging.getLogger('logger4')
logger3.info('某某某充值了5毛钱')     # 用户充值 -> deal.log
logger4.info('某某某登录了')          # 用户操作 -> operate.log
```

运行几次后打开两个文件，`deal.log` 里都是交易相关日志，`operate.log` 里都是操作相关日志。

### 给 logger 起有意义的名字

**logger 名要见名知意，别用 logger3、logger4 这种编号**。日志文件里记录的名字如果只是 `logger3`、`logger4`，看不出含义。用户交易日志以后还会分得更细（充值、转账、提现……），所以名字应当有意义，方便日后查日志。

```text
# settings.py 的 loggers
'用户充值': {
    'handlers': ['console_debug_handler', 'file_deal_handler'],
    'level': 'DEBUG',
    'propagate': False,
},
'用户操作': {
    'handlers': ['file_operate_handler'],
    'level': 'DEBUG',
    'propagate': False,
},
```

```python
# run.py 中
logging.getLogger('用户充值').info('某某某充值了5毛钱')
logging.getLogger('用户操作').info('某某某登录了')
```

### 无名 logger：多种日志写入同一个文件

**想让多种日志写进同一个文件，只配一个无名 logger 就够了**。如果用户转账、用户提现也要写进 `deal.log` 并分类，难道再建两个配置完全一样的 logger？它们的配置和"用户充值"**一模一样，只是名字不同**，复制三份就是冗余（"用户操作"写的是另一个文件、handler 不同，单独写一个可以接受）。

这时只写一个**名字为空字符串**的 logger：

```text
# settings.py 的 loggers
'': {                                   # 没有名字的 logger
    'handlers': ['console_debug_handler', 'file_deal_handler'],
    'level': 'DEBUG',
    'propagate': False,
},
```

```python
# run.py 中
logging.getLogger('用户充值').info('某某某充值了5毛钱')
logging.getLogger('用户转账').info('某某某给某某某转了5毛钱')
logging.getLogger('用户提现').info('某某某提现了5毛钱')
```

`getLogger` 在配置里找不到对应名字时，就会使用这个无名 logger。运行不报错，`deal.log` 里三个业务的日志都在，而日志里记录的名字仍是传给 `getLogger` 的那个名字。结论：**想把多种类型的日志写入同一个文件，就用无名 logger。**


:::note[补充]
**空字符串 `''` 配置的其实是根记录器 root**。`getLogger('用户转账')` 得到一个没有单独配置、也没有 handler 的 logger，它默认把日志 **propagate 给父级 root**，由 root 的 handler 输出；`%(name)s` 记录的是最初产生日志的 logger 名字，所以仍显示"用户转账"。这也正是前面要把具体 logger 的 `propagate` 设为 `False` 的原因：否则同一条日志会被自己和 root 各输出一次。
:::


## 12.15 日志轮转

### 为什么要轮转

**日志不能随意删，但也不能一直往同一个文件里写，所以需要轮转**。日志记录的是程序运行的关键信息，**不能随意删除**：可能很多年用不上，但你不知道哪天哪个用户出问题，前脚删日志后脚用户就找上门。

但软件生命周期一长，日志文件可能涨到几 GB、几十 GB。既不能删、又不能一直往同一个文件写，唯一的办法是：**文件涨到一定量时，把旧内容挪到另一个文件（或把原文件重命名），下次再生成新文件**。这就叫**日志轮转（log rotation）**。

**logging 已经实现好了轮转功能，直接用 `RotatingFileHandler` 即可**。除 `filename`、`encoding`、`formatter` 外，重点看三个参数：

```text
# settings.py 的 handlers 中
'file_info_handler': {
    'level': 'INFO',
    'class': 'logging.handlers.RotatingFileHandler',   # 1. 按文件大小轮转
    'filename': 'deal.log',
    'maxBytes': 1024 * 1024 * 10,   # 2. 达到多大时轮转，单位字节：这里是 10MB
    'backupCount': 3,               # 3. 保留的旧文件数量
    'encoding': 'utf-8',
    'formatter': 'standard',
},
```

- `maxBytes`：单位字节，1KB = 1024 字节，1MB = 1024KB，故 `1024 * 1024 * 10` 即 10MB。演示时可改小（如 800 字节）；
- `backupCount`：保留的日志文件数量。项目里应**尽量设大**，因为文件数达到这个值后，最前面的日志文件会被**直接删掉**。

实操验证（用一个独一无二的文件名，见 12.16 节）：

```python
import os
import logging.config

LOGGING_DIC = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'standard': {'format': '[%(asctime)s][%(name)s][%(levelname)s][%(message)s]'},
    },
    'handlers': {
        'file_info_handler': {
            'level': 'INFO',
            'class': 'logging.handlers.RotatingFileHandler',
            'filename': 'abc.log',      # 轮转的文件独一无二，不与其他 handler 共用
            'maxBytes': 800,            # 演示：超过 800 字节就轮转
            'backupCount': 3,           # 演示：只保留 3 个旧文件
            'encoding': 'utf-8',
            'formatter': 'standard',
        },
    },
    'loggers': {
        '': {'handlers': ['file_info_handler'], 'level': 'DEBUG', 'propagate': False},
    },
}
logging.config.dictConfig(LOGGING_DIC)

for i in range(60):                     # 相当于多运行几遍程序
    logging.getLogger('用户充值').info(f'某某某充值了5毛钱，第{i}次')

print(sorted(name for name in os.listdir('.') if name.startswith('abc.log')))
# 输出: ['abc.log', 'abc.log.1', 'abc.log.2', 'abc.log.3']
```

`abc.log` 超过 800 字节后被重命名为 `abc.log.1`，新日志继续写新的 `abc.log`；继续运行，旧文件依次后挪，无论跑多少次都**只保留 3 个旧文件**，最前面的被删掉。

### 按时间轮转：TimedRotatingFileHandler

**RotatingFileHandler 按大小轮转，按时间轮转要用 TimedRotatingFileHandler**。如果希望"每天生成一个文件"，就用它。

| 参数 | 含义 |
|---|---|
| `when` | 轮转单位：`'S'` 秒、`'M'` 分、`'H'` 小时、`'D'` 天、`'midnight'` 每天凌晨 |
| `interval` | 结合 `when` 的间隔，如 `when='H', interval=6` 表示每 6 小时 |
| `backupCount` | 保留的旧文件数量 |
| `atTime` | 配合 `'midnight'` 指定具体时刻，如 `datetime.time(0, 0)` |

```python
import os
import logging.config

LOGGING_DIC = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'standard': {'format': '[%(asctime)s][%(name)s][%(levelname)s][%(message)s]'},
    },
    'handlers': {
        'time_handler': {
            'level': 'DEBUG',
            'class': 'logging.handlers.TimedRotatingFileHandler',
            'filename': 'time.log',
            'when': 'midnight',      # 每天凌晨轮转一次
            'interval': 1,
            'backupCount': 7,        # 保留最近 7 天
            'encoding': 'utf-8',
            'formatter': 'standard',
        },
    },
    'loggers': {'': {'handlers': ['time_handler'], 'level': 'DEBUG', 'propagate': False}},
}
logging.config.dictConfig(LOGGING_DIC)
logging.getLogger('access').info('程序启动')
```

轮转后的旧文件名会带上时间后缀（如 `time.log.2026-10-13`）。


:::tip[技巧]
大小轮转和时间轮转可以同时用：配两个 handler 指向不同文件，一个 `RotatingFileHandler` 防单日暴涨，一个 `TimedRotatingFileHandler` 按天归档。
:::


## 12.16 轮转的坑与配置文件 fileConfig

### 轮转的文件必须独一无二

**配了轮转的文件不能和其他 handler 共用**，否则会报 `PermissionError`：**另一个程序正在使用此文件，进程无法访问**。

原因：程序要把 `deal.log` 重命名为 `deal.log.1` 时，`deal.log` 正被另一个 handler 占用。看配置就明白——`file_info_handler` 处理 `deal.log`，而 `file_deal_handler` 也处理 `deal.log`；**即使没有任何 logger 调用 `file_deal_handler`，它也会把这个文件一直打开占用着**，被占用的文件无法重命名。


:::warning[注意]
结论：**参与轮转的文件必须独一无二**，不能和其他 handler 共用。把 `file_info_handler` 的 `filename` 改成 `abc.log` 即可解决（12.15 节的示例已经这样做了）。这个坑新手很容易踩。
:::


### 用配置文件代替配置字典

**除了配置字典，还可以用 .cfg/.ini 配置文件，但项目里一般仍以配置字典为主**。新建 `.cfg` 或 `.ini`，配置项内容和配置字典一样，只是换成配置文件的书写格式。区别：

- 读取不用 `dictConfig`，而用 `logging.config.fileConfig(配置文件路径)`，其余用法相同；
- 配置文件里写在配置项**后面的注释**，使用时必须删掉或挪到单独一行，否则读取会出问题；
- **读取配置文件时不能指定字符编码**：Windows 上默认以 GBK 读，若配置文件用 UTF-8 写（含中文）就会报错，Mac/Linux 没这个问题。

Windows 上的老办法是改源码：`Ctrl` 点进 `fileConfig` 源码，找到 `cp.read(fname)`，再点进 `read` 看到它有 `encoding` 参数，Windows 下默认 GBK，改成 `utf-8`。但**不到万不得已不要改源码**。


:::note[补充]
Python 3.10 起 `fileConfig` 新增了 `encoding` 参数，可以直接写 `logging.config.fileConfig('logging.ini', encoding='utf-8')`，不必再改源码。配置文件基本格式：
```ini
[loggers]
keys=root

[handlers]
keys=console

[formatters]
keys=simple

[logger_root]
level=DEBUG
handlers=console

[handler_console]
class=StreamHandler
level=DEBUG
formatter=simple
args=(sys.stdout,)

[formatter_simple]
format=[%(levelname)s] %(name)s: %(message)s
```
:::


**结论：配置文件了解即可，项目里一般还是用配置字典。**

## 12.17 项目中的实用配置模板

把前面知识串起来，给出一个可落地的日志方案。

### 目录与路径动态获取

**日志目录要在项目根目录下动态算出来，不能写死相对路径**。按目录规范，路径由 `__file__` 反推。

```python
# conf/settings.py（节选）
import os

BASE_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))   # 项目根目录
LOG_DIR = os.path.join(BASE_DIR, 'log')
os.makedirs(LOG_DIR, exist_ok=True)                # 目录不存在就创建
LOG_PATH = os.path.join(LOG_DIR, 'access.log')     # handler 的 filename 用这个变量
```

### 按日志级别分文件

**一种常见做法是让不同级别的日志写进不同的文件**：正常的业务日志进一个文件，错误单独的进另一个文件，方便排障时只看错误文件。

```python
# conf/settings.py（节选）
LOGGING_DIC = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'standard': {'format': '[%(asctime)s][%(levelname)s][%(name)s][%(filename)s:%(lineno)d] %(message)s',
                     'datefmt': '%Y-%m-%d %H:%M:%S'},
    },
    'filters': {},
    'handlers': {
        # 所有级别 -> 全量日志文件
        'all_file_handler': {
            'level': 'DEBUG',
            'class': 'logging.handlers.RotatingFileHandler',
            'filename': LOG_PATH,
            'maxBytes': 1024 * 1024 * 10,     # 10MB
            'backupCount': 10,
            'encoding': 'utf-8',
            'formatter': 'standard',
        },
        # 只有 ERROR 及以上 -> 错误日志文件
        'error_file_handler': {
            'level': 'ERROR',
            'class': 'logging.handlers.RotatingFileHandler',
            'filename': os.path.join(LOG_DIR, 'error.log'),
            'maxBytes': 1024 * 1024 * 10,
            'backupCount': 10,
            'encoding': 'utf-8',
            'formatter': 'standard',
        },
    },
    'loggers': {
        '': {
            'handlers': ['all_file_handler', 'error_file_handler'],
            'level': 'DEBUG',
            'propagate': False,
        },
    },
}
```

`error_file_handler` 的 `level` 设为 `ERROR`，就会有级别过滤的效果：同一条日志，DEBUG/INFO 只进 `access.log`，ERROR 及以上两个文件都进。

### main 与 access 双日志

**另一种常见分类是业务日志（main）和访问/调试日志（access）分开写**，两者用不同的 logger 名，绑定不同的 handler。

```text
# conf/settings.py（节选）
'handlers': {
    'main_file_handler': {
        'level': 'INFO',
        'class': 'logging.handlers.RotatingFileHandler',
        'filename': os.path.join(LOG_DIR, 'main.log'),
        'maxBytes': 1024 * 1024 * 10,
        'backupCount': 10,
        'encoding': 'utf-8',
        'formatter': 'standard',
    },
    'access_file_handler': {
        'level': 'DEBUG',
        'class': 'logging.handlers.TimedRotatingFileHandler',
        'filename': os.path.join(LOG_DIR, 'access.log'),
        'when': 'midnight',
        'interval': 1,
        'backupCount': 30,
        'encoding': 'utf-8',
        'formatter': 'standard',
    },
},
'loggers': {
    'main': {'handlers': ['main_file_handler'], 'level': 'INFO', 'propagate': False},
    'access': {'handlers': ['access_file_handler'], 'level': 'DEBUG', 'propagate': False},
},
```

### 封装获取 logger 的工具函数

**把加载配置和取 logger 封装成一个函数，业务代码里只写一行**。加载配置只需一次，业务代码里按名字拿 logger，通常在 `lib/common.py` 里封装：

```python
# lib/common.py
import logging.config

from conf import settings


def get_logger(name):
    logging.config.dictConfig(settings.LOGGING_DIC)   # 加载配置字典
    return logging.getLogger(name)


# 业务代码中：get_logger('main').info('某某某充值了5毛钱')
```


:::tip[技巧]
`dictConfig` 重复调用是安全的（会重置配置），但更规范的做法是模块级只调一次或加个标志位判断，避免每次取 logger 都重新加载。
:::


## 本章小结

- 正则是一种跨语言的**查找规则**。编辑器里 `Ctrl + R` 并点亮 `.*` 即可用正则替换，`$1`、`$2` 引用分组。
- 限定符只管前一个字符：`*`（0+）、`+`（1+）、`?`（0 或 1）、`{n}`、`{n,m}`、`{n,}`；`()` 让多个字符整体重复，`|` 表示或。
- 字符组 `[]` 任取其一，`[^...]` 取反；元字符 `\d \w \s`（大写取反）、`\b` 单词边界、`.` 除换行外任意字符、`^` 行首、`$` 行尾；特殊符号用 `\` 转义。
- 量词默认贪婪，后面加 `?` 变懒惰。`^` 匹配的是**行首**（Python 默认是整串开头，需 `re.M` 才是每行），匹配任意位置用 `\b`。
- Python 里小括号就是分组，`findall` 只返回组内容，用 `(?:...)` 取消分组；Match 对象用 `group()`、`group(n)`、`span()`；命名分组 `(?P<name>...)` + `groupdict()`。
- `findall` 全部（列表）、`search` 第一个、`finditer` 全部（迭代器）、`match` 字符串开头、`fullmatch` 整体匹配、`sub/subn` 替换（可传函数）、`split` 拆分、`compile` 复用；flags 常用 `re.I`、`re.M`、`re.S`。
- 日志五个级别：DEBUG(10) < INFO(20) < WARNING(30) < ERROR(40) < CRITICAL(50)，默认 WARNING。用日志代替 `print`，靠配级别控制输出。
- `basicConfig` 可设 `level`、`format`、`datefmt`、`filename`（3.9+ 有 `encoding`），但**不能同时输出到文件和终端**。
- 配置字典重点掌握 `formatters`（格式）、`handlers`（输出目标/格式/编码）、`loggers`（交给哪些 handler、级别、`propagate`）。logger 生产、handler 处理，**两层级别过滤**。
- `import logging` 不能直接用 `logging.config`；`from logging import config` 只导入 config，`import logging.config` 连 logging 一起导入；两者都会先执行 `__init__.py`。
- 不同 logger 绑不同文件的 handler 实现日志分类；名字要有意义；找不到名字时用无名 logger `''`（实为 root），日志里显示传入的名字。
- `RotatingFileHandler` 按大小轮转（`maxBytes`、`backupCount`），`TimedRotatingFileHandler` 按时间轮转（`when`、`interval`）；**轮转文件不能与其他 handler 共用**，否则 Windows 上 `PermissionError`。`fileConfig` 读配置文件，Windows 有编码坑（3.10+ 可传 `encoding`），一般仍用配置字典。
