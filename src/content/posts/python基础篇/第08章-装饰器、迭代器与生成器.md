## 8.1 装饰器的本质

### 什么是装饰器

**装饰器**(Decorator):定义一个函数,用来给其他函数添加额外功能。

- **器**:工具。写一个函数就相当于造一个工具,如遥控器是遥控的工具。
- **装饰**:为其他事物添加额外的功能。

它要遵守**开放封闭原则**(Open-Closed Principle):

- **开放**:对**扩展功能**开放(增加功能)
- **封闭**:对**修改源代码**封闭(不改原代码)

结论:**程序应该可扩展,而不是可修改。**

### 开放封闭原则的由来

软件写完要放到线上环境运行,和真实用户接触。改代码就要先把程序停掉,这就是**停服维护**。

类比:玩游戏时官方不能毫无预告就关服,即使要停服也会提前通知(比如提前一个月)几点到几点维护。而且改代码有风险——用户会以各种意想不到的方式操作软件,测试时发现不了的问题上线后可能暴露。


:::warning[注意]
**修改形参(增加或减少)也属于修改源代码**。一个函数可能在几十个地方被调用,改了形参,几十个调用处都要跟着改。所以不仅不能改源代码,连调用方式也不能改。
:::


于是装饰器的目标就是:

> 在**不修改被装饰对象的源代码**、也**不修改其调用方式**的前提下,给被装饰对象增加新的功能。

## 8.2 从需求到方案:统计运行时间

### 明确需求与时间戳

需求:统计函数运行时间。先明确时间戳。

`time.time()` 返回**时间戳**(timestamp):从 1970 年 1 月 1 日 0 时 0 分 0 秒开始,到此刻经过的秒数。1970 年被称为 **UNIX 元年**(UNIX 是很有影响力的操作系统,Linux 由它演变而来)。

```python
import time

start = time.time()
time.sleep(1)
end = time.time()
print(round(end - start, 1))  # 输出: 1.0(中间经过的秒数,约1.0)
```


:::note[补充]
在中国,时间戳的起点是 1970 年 1 月 1 日早上 8 点,因为我们位于**东八区**(比默认时间加 8 小时)。
:::


被装饰的函数:用 `print` 模拟王者荣耀开局。

```python
import time

def inside(group, s):
    print('欢迎来到王者荣耀')
    print(f'你出生在{group}方阵营')
    print(f'敌军还有{s}秒到达战场')
    time.sleep(s)
    print('全军出击')

inside('红色', 5)
```

### 方案 1~4:从改源码到参数写活

现在要给它加"统计运行时间"的功能,且不改源码、不改调用方式。逐步推导。

**方案 1:修改源代码。** 在函数体前后各记一次时间。→ 修改了源代码,违反原则。

**方案 2:在调用处加代码。** 在 `inside(...)` 前后记时间。→ 没改源码和调用方式,但重复代码太多(`inside` 在 100 个地方被调用,就要加 100 遍)。

**方案 3:把重复代码封装成函数。**

```python
def wrapper():
    start = time.time()
    inside('蓝色', 3)
    end = time.time()
    print(end - start)

wrapper()
```

→ 解决了冗余,但**调用方式变了**:原来调 `inside`,现在调 `wrapper`。

**方案 4:参数写活。** `inside` 的参数不能写死,用 `*args, **kwargs` 原封不动转交:

```python
def wrapper(*args, **kwargs):
    start = time.time()
    inside(*args, **kwargs)   # 原样接收,原样转交
    end = time.time()
    print(end - start)

wrapper('蓝色', 3, '炮车')    # 参照inside的形参规则传参
```

### 方案 5:闭包传入被装饰对象

`wrapper` 里把 `inside` 写死了,换成变量 `func`。怎么传?

- 方案一:通过参数传?不行。`wrapper` 的参数要原封不动转交给被装饰对象,不能随便加实参。
- **方案二:用闭包传**(这正是闭包的应用场景)。

在 `wrapper` 外套一层 `outer`,把 `func` 包给它:

```python
def outer(func):              # func写活了:传谁就装饰谁
    def wrapper(*args, **kwargs):
        start = time.time()
        func(*args, **kwargs)
        end = time.time()
        print(end - start)
    return wrapper            # 返回wrapper的内存地址(不加括号)

res = outer(inside)           # res指向wrapper的内存地址
res('蓝色', s=3, z='炮车')
```

→ 成功装饰,但调用方式还是变了(原来调 `inside`,现在调 `res`)。怎么办?**偷梁换柱**。

```python
import time

def outer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        func(*args, **kwargs)
        end = time.time()
        print(round(end - start, 2))
    return wrapper

def inside(group, s):
    print('欢迎来到王者荣耀')
    print(f'你出生在{group}方阵营')
    print(f'敌军还有{s}秒到达战场')
    time.sleep(s)
    print('全军出击')

print(inside.__name__)      # 输出: inside
inside = outer(inside)      # 右边的inside传给outer,返回的wrapper赋给名字inside
print(inside.__name__)      # 输出: wrapper(名字被换掉了)
inside('蓝色', 3)           # 调用方式和原来一样
# 输出:
# 欢迎来到王者荣耀
# 你出生在蓝色方阵营
# 敌军还有3秒到达战场
# 全军出击
# 3.0(approx)
```

对调用者来说浑然不知,名字没变,但 `inside` 早已被偷梁换柱,实际调用的是 `wrapper`。


:::warning[注意]
全局不可能同时存在两个同名名字,`inside = outer(inside)` 之后,后者覆盖前者。原来的 `inside` 的内存地址已经传给了 `outer` 局部的 `func`,现在只有 `func` 指向它。
:::


### 方案 6~7:通用性与返回值

**方案 6:应用到其他函数。** 同一个装饰器可装饰任意函数,例如模拟手机充电:

```python
import time

def outer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        func(*args, **kwargs)
        end = time.time()
        print(round(end - start, 2))
    return wrapper

def recharge(num):
    for i in range(num, 101):          # 从当前电量充到100
        time.sleep(0.05)
        print(f'\r当前电量:{"■" * i} {i}%', end='')
    print('\n电量已充满')

recharge = outer(recharge)
recharge(20)
```

要点:

- `\r` 回到行首,`end=''` 去掉默认换行符,实现**同行刷新**
- 字符串乘法 `"■" * i` 做进度条(电量越多,方块越多)

**方案 7:处理返回值。** 被装饰对象有返回值时,`wrapper` 也要返回:

```python
def outer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)    # 接住原函数的返回值
        end = time.time()
        print(round(end - start, 2))
        return res                     # 原函数返回什么,wrapper就返回什么
    return wrapper

def recharge(num):
    for i in range(num, 101):
        time.sleep(0.05)
        print(f'\r当前电量:{"■" * i} {i}%', end='')
    print('\n电量已充满')
    return 100

recharge = outer(recharge)
res = recharge(20)
print(res)   # 输出: 100
```

原函数没有返回值时默认返回 `None`,`wrapper` 也随之返回 `None`。参数、调用方式、返回值都一致,装饰器已能以假乱真。


:::warning[注意]
**`return wrapper` 不能写成 `return wrapper()`**。加括号会立刻调用 `wrapper`,返回值变成了 `wrapper` 的返回值,而不是函数本身;并且 `wrapper` 没返回值时,装饰后的名字将变成 `None`。
:::


### 方案演进对照

| 方案 | 是否改源码 | 是否改调用方式 | 遗留问题 |
|---|---|---|---|
| 1 改函数体 | 是 | 否 | 违反开放封闭原则 |
| 2 调用处加代码 | 否 | 否 | 重复代码太多 |
| 3 封装成函数 | 否 | 是 | 调名字变成了 wrapper |
| 4 `*args, **kwargs` | 否 | 是 | 被装饰对象仍写死 |
| 5 闭包 + 偷梁换柱 | 否 | 否 | 返回值没接住 |
| 6 通用装饰任意函数 | 否 | 否 | 有返回值时丢失 |
| 7 接住并返回 res | 否 | 否 | 属性仍是 wrapper 的 |

## 8.3 无参装饰器模板

### 基础模板

去掉计时逻辑,得到**无参装饰器**的通用模板,以后写装饰器往里"填空":

```python
def outer(func):
    def wrapper(*args, **kwargs):
        # 调用原函数之前添加的新功能
        res = func(*args, **kwargs)
        # 调用原函数之后添加的新功能
        return res
    return wrapper
```

**三句话记模板**:

1. `wrapper` 的参数用 `*args, **kwargs` 原样接收、原样交出
2. 在 `func(*args, **kwargs)` 前后加功能
3. `return res` 把原函数返回值交出去

### 语法糖 `@`

每装饰一个函数都要写一遍 `func = outer(func)`,很麻烦。**语法糖**(syntactic sugar)让代码更简洁。

写法:在被装饰函数的**正上方**写 `@装饰器名`(**不加括号**),等价于 `func = outer(func)`。

```python
import time

def count_time(func):              # 改个见名知意的名字
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        end = time.time()
        print('运行时间: %.2f 秒' % (end - start))
        return res
    return wrapper

@count_time      # 等价于 index = count_time(index)
def index(x, y):
    time.sleep(0.5)
    print('index: %s %s' % (x, y))

@count_time      # 等价于 recharge = count_time(recharge)
def recharge(money):
    time.sleep(0.3)
    print('充值 %s 元' % money)
    return 'ok'

index(1, 2)
print(recharge(100))
# 输出:
# index: 1 2
# 运行时间: 0.50 秒
# 充值 100 元
# 运行时间: 0.30 秒
# ok
```

**注意**:

- 执行到 `@` 这行就会**立刻调用**装饰器,所以**装饰器必须定义在被装饰函数前面**(否则报 `NameError`)
- 装饰器名字要**见名知意**:`outer` 只能看出它是个装饰器,`count_time` 一眼就知道是计时


:::note[补充]
`@count_time` 是在**定义函数时**就执行,不是等到调用函数时。可以在 `count_time` 函数体第一行加一句 `print('装饰器被调用')` 验证:即使后面一次都不调用 `index`,运行脚本也会打印这句话。
:::


### 认证装饰器

需求:运行 `home` 之前先让用户输入账号密码,正确才运行,否则提示错误。

```python
def auth(func):
    def wrapper(*args, **kwargs):
        name = input('请输入账号: ').strip()
        pwd = input('请输入密码: ').strip()
        # 实际应从文件中读取账号密码,这里为了演示直接写死
        if name == 'jake' and pwd == '123':
            res = func(*args, **kwargs)      # 账号密码正确才执行原功能
            return res
        else:
            print('账号或密码错误')
    return wrapper

@auth
def home():
    print('welcome')

home()
# 输入 jake/123,输出: welcome
# 输入错误,输出: 账号或密码错误(home根本没执行)
```

以后哪个功能需要登录才能用,就在它的头顶加一个 `@auth`。

## 8.4 完美伪装:`__name__`、`__doc__` 与 wraps

### 装饰后被换掉的属性

装饰后还有破绽:函数名、文档注释等属性都变成了 `wrapper` 的。

```python
def outer(func):
    def wrapper(*args, **kwargs):
        res = func(*args, **kwargs)
        return res
    return wrapper

@outer
def home():
    """这是主页"""
    print('welcome')

print(home)            # 输出: <function outer.<locals>.wrapper at 0x...>
print(home.__name__)   # 输出: wrapper
print(home.__doc__)    # 输出: None
```

- `print(home)`(不加括号)打印的是函数的内存地址,名字显示为 `wrapper`
- `__name__` 属性是函数名,装饰后 `home.__name__` 变成了 `wrapper`
- `__doc__` 属性是函数的文档注释(函数体第一行的三引号字符串),装饰后拿到的是 `wrapper` 的文档注释(这里是 `None`)

调用者一看就知道这个函数被换过了。**手动复制**这些属性可行,但函数有一大堆双下划线属性,一个个写太啰嗦:

```python
def outer(func):
    def wrapper(*args, **kwargs):
        res = func(*args, **kwargs)
        return res
    wrapper.__name__ = func.__name__   # 写在wrapper定义之后、return之前
    wrapper.__doc__ = func.__doc__
    return wrapper

@outer
def home():
    """这是主页"""
    print('welcome')

print(home.__name__)   # 输出: home
print(home.__doc__)    # 输出: 这是主页
```


:::warning[注意]
属性复制要写在 **`wrapper` 定义完成之后、`return wrapper` 之前**,不要写进 `wrapper` 的函数体里——函数体只有调用时才执行,那就晚了。
:::


### 用 wraps 一键复制属性

用 Python 现成的工具 **`wraps`**:`from functools import wraps`。它本身也是一个装饰器,把原函数的所有属性复制给 `wrapper`。用法要**加括号**并把 `func` 传进去:

```python
from functools import wraps

def outer(func):
    @wraps(func)               # 把func的__name__、__doc__等属性复制给wrapper
    def wrapper(*args, **kwargs):
        res = func(*args, **kwargs)
        return res
    return wrapper

@outer
def home():
    """这是主页"""
    print('welcome')

print(home)            # 输出: <function home at 0x...>  名字显示成home,地址仍是wrapper的
print(home.__name__)   # 输出: home
print(home.__doc__)    # 输出: 这是主页
```

怎么理解"装饰器里又加了一个装饰器"?加不加 `@wraps(func)`,调用方式和结果都没有区别,区别只在 `wrapper` 的属性是否和原函数一样。

最关键的伪装(参数、调用方式、返回值)前面已经做好了,`wraps` 只是**锦上添花**。


:::tip[技巧]
建议把 `@wraps(func)` 加进装饰器模板。`wraps` 还会给 `wrapper` 加一个 `__wrapped__` 属性,指向原函数,即 `home.__wrapped__` 就是没被装饰的 `home`。
:::


`@wraps(func)` 这种**加括号传参**的写法,就是下面的**有参装饰器**。

## 8.5 有参装饰器

### 为什么需要有参装饰器

先看现有约束:

- `wrapper` 的参数要原封不动转交给被装饰对象,**不能动**
- `outer` 的参数受语法糖限制,**只能有一个**,且只能用来接收被装饰对象的内存地址

如果 `wrapper` 需要一个外部的值 `name`,怎么传?

**方案一:加到 `outer` 的参数上?不行。**

```python
def outer(func, name):
    def wrapper(*args, **kwargs):
        print(name)
        res = func(*args, **kwargs)
        return res
    return wrapper

# @outer          # 一运行就报错: TypeError: outer() missing 1 required positional argument: 'name'
# def home():
#     print('welcome')
```

不用调用 `home`,直接运行就报错。因为执行到语法糖时会立刻调用 `outer`,并且**只传一个参数**(下面函数的内存地址)。把 `name` 设成默认参数虽然不报错,但等于把值写死了,失去意义。

### 方案:再包一层

**方案二:再包一层。** 在 `outer` 外面再包一层函数,把 `name` 包给它:

```python
def g_outer(name):                 # 最外层接收参数
    def outer(func):               # 原来的outer原封不动缩进进来
        def wrapper(*args, **kwargs):
            print(name)
            res = func(*args, **kwargs)
            return res
        return wrapper
    return outer                   # 把outer返回出去

@g_outer('梦泪')   # ①先调用g_outer('梦泪'),返回outer
def home():          # ②相当于@outer: home = outer(home)
    print('welcome')

@g_outer('李白')
def index():
    pass

home()   # 输出: 梦泪 / welcome
index()  # 输出: 李白
```

**这就是有参装饰器:先调用一个函数得到一个装饰器地址,再与 `@` 结合构成语法糖。**

为什么套两层?

- `wrapper` 需要 `func`,又不能动 `wrapper` 的参数 → 套一层 `outer`
- `wrapper` 还需要 `name`,而 `outer` 的参数受语法糖限制也不能动 → 再套一层 `g_outer`

`g_outer` 是正常调用,参数可以随便定义,所以**到 `g_outer` 这层就足够了,没必要套第三层**。

### 有参装饰器模板

去掉 `print` 行,参数改名为 `x`,就是**有参装饰器模板**:

```python
def g_outer(x):                    # 可以接收任意多个参数
    def outer(func):
        def wrapper(*args, **kwargs):
            res = func(*args, **kwargs)
            return res
        return wrapper
    return outer
```


:::tip[技巧]
分析装饰器代码不要想一眼看出结果,而要**按执行顺序**看:执行到哪个函数就看哪个函数的函数体,还没执行的函数体先"收起来"不看。
:::


### 应用:多种认证来源

账号来源可能多种多样:文件、数据库(MySQL、Oracle)、LDAP(一种集中式的账号管理服务)。比如 `home` 的账号来源是文件,`index` 是 MySQL,`default` 是 LDAP。

如果都用无参的 `@auth`,三个来源就都变成文件了。

解决:让 `source` 在使用装饰器时传入——这正是有参装饰器。

```python
def auth(source):                   # 最外层接收认证来源
    def outer(func):
        def wrapper(*args, **kwargs):
            name = input('请输入账号: ').strip()
            pwd = input('请输入密码: ').strip()
            if source == 'file':
                print('基于文件的登录验证')
                if name == 'jake' and pwd == '123':
                    res = func(*args, **kwargs)
                    return res
                else:
                    print('账号或密码错误')
            elif source == 'mysql':
                print('基于mysql的登录验证')
            elif source == 'ldap':
                print('基于ldap的登录验证')
            else:
                print('不支持的验证')
        return wrapper
    return outer

@auth('file')    # home的账号来源是文件
def home():
    print('welcome')

@auth('mysql')   # index的账号来源是MySQL
def index():
    pass

@auth('ldap')    # default的账号来源是LDAP
def default():
    pass

home()
index()
default()
# 每次都输入 jake/123,输出:
# 基于文件的登录验证
# welcome
# 基于mysql的登录验证
# 基于ldap的登录验证
```

**使用场景**:用同一个装饰器装饰不同函数时,内部需要的参数可能不一样。

## 8.6 装饰器叠加

### 加载顺序:自下而上

一个函数头顶可以同时加多个装饰器,叫**装饰器叠加**。

```python
@outer3          # ③ home = outer3(home),此时home是outer2.wrapper
@outer2(10)      # ② home = outer2(home),此时home是outer1.wrapper
@outer1          # ① home = outer1(home),传入原home
def home(z):
    ...
```

紧贴被装饰对象的装饰器先加载。不管套了多少层,每个装饰器的最终目的都是把全局的 `home` 替换成自己的 `wrapper`。

### 执行顺序:自上而下进入,自下而上退出

写三个装饰器(两个无参、中间一个有参)验证:

```python
def outer1(func1):                  # func1 = 原home
    def wrapper1(*args, **kwargs):
        print('开始执行 outer1.wrapper1')
        res1 = func1(*args, **kwargs)
        print('outer1.wrapper1 执行完毕')
        return res1
    return wrapper1

def outer2(x):                      # 有参装饰器,x这里没用到
    def outer(func2):               # func2 = outer1.wrapper1
        def wrapper2(*args, **kwargs):
            print('开始执行 outer2.wrapper2')
            res2 = func2(*args, **kwargs)
            print('outer2.wrapper2 执行完毕')
            return res2
        return wrapper2
    return outer

def outer3(func3):                  # func3 = outer2.wrapper2
    def wrapper3(*args, **kwargs):
        print('开始执行 outer3.wrapper3')
        res3 = func3(*args, **kwargs)
        print('outer3.wrapper3 执行完毕')
        return res3
    return wrapper3

@outer3
@outer2(10)
@outer1
def home(z):
    print('执行 home 功能', z)
    return '梦泪'

res = home(0)        # 全局的home实际是wrapper3
print(res)
# 输出:
# 开始执行 outer3.wrapper3
# 开始执行 outer2.wrapper2
# 开始执行 outer1.wrapper1
# 执行 home 功能 0
# outer1.wrapper1 执行完毕
# outer2.wrapper2 执行完毕
# outer3.wrapper3 执行完毕
# 梦泪
```

**执行过程**:

1. 全局调用 `home`,实际是 `wrapper3`,打印"开始执行 outer3.wrapper3"
2. `wrapper3` 调用 `func3`(即 `wrapper2`),打印"开始执行 outer2.wrapper2"
3. `wrapper2` 调用 `func2`(即 `wrapper1`),打印"开始执行 outer1.wrapper1"
4. `wrapper1` 调用 `func1`(即原 `home`),打印"执行 home 功能 0"
5. 原 `home` 执行完,回到 `wrapper1` 继续往下,打印"outer1.wrapper1 执行完毕"
6. 依次退出 `wrapper2`、`wrapper3`
7. `res1`、`res2`、`res3` 都在传递原 `home` 的返回值,最后全局拿到 `'梦泪'`

规律:**像堆栈(后进先出)**。执行时从上往下依次进入,结束时从下往上依次退出。


:::warning[注意]
叠加顺序会影响结果。例如同时加计时和认证:`@auth` 在上、`@count_time` 在下时,计时会把用户输入账号密码的等待时间也算进去,结果就不准了。想让某功能只作用于原函数本身,就把它放在**离原函数最近的位置**。
:::


## 8.7 迭代的概念

### 什么是迭代

**迭代**(iteration)是重复执行,但每次重复都基于上一次的结果。

```python
# 单纯重复——不是迭代
# while True:
#     print(1)

# 迭代——每次基于上一次的结果
i = 0
while i < 3:
    print(i)
    i += 1
# 输出:
# 0
# 1
# 2
```

**为什么需要迭代器?** 列表、元组、字符串可以用索引取值,但字典、集合、文件对象没有索引。Python 要提供一种**不依赖索引**的、统一的迭代取值机制,这就是**迭代器**(iterator)。

## 8.8 可迭代对象与迭代器对象

### 可迭代对象

**可迭代对象**(iterable):内置有 `__iter__` 方法的对象。调用 `__iter__` 会返回一个迭代器对象。

```python
d = {'k1': 1, 'k2': 2, 'k3': 3}
print(hasattr(d, '__iter__'))    # 输出: True

d_iterator = d.__iter__()        # 得到迭代器
print(d_iterator)                # 输出: <dict_keyiterator object at 0x...>
```

列表、字符串、元组、字典、集合、文件对象都是可迭代对象。


:::note[补充]
整数、浮点数没有 `__iter__` 方法,不是可迭代对象,所以 `for i in 123` 会报错。以前说"能被 `for` 遍历的就是可迭代对象"不够准确,准确说法是"有 `__iter__` 方法"。
:::


### 迭代器对象

**迭代器对象**(iterator):同时具有 `__iter__` 和 `__next__` 方法的对象。

- `__next__` 方法:每调用一次返回一个值,取完抛出 `StopIteration` 异常
- `__iter__` 方法:返回迭代器自身

```python
d = {'k1': 1, 'k2': 2, 'k3': 3}
d_iterator = d.__iter__()

print(d_iterator.__next__())       # 输出: k1
print(d_iterator.__next__())       # 输出: k2
print(d_iterator.__next__())       # 输出: k3
# print(d_iterator.__next__())     # 第4次:值取完了,抛出 StopIteration
```

类比:迭代器像一只**老母鸡**,每次调用 `__next__` 生一个蛋,生完就"死"了——再让它生就抛 `StopIteration`。它肚子里并不是一开始就存着所有蛋,而是一个一个来的。

**迭代器很节省内存**:同一时刻只保存当前值,不会把所有值同时放在内存里。

### 用 while 不依赖索引取值

配合 `try...except` 捕获 `StopIteration` 异常:

```python
d = {'k1': 1, 'k2': 2, 'k3': 3}
d_iterator = d.__iter__()

while True:
    try:                            # 尝试执行可能抛异常的代码
        print(d_iterator.__next__())
    except StopIteration:           # 捕获"值取完了"的异常
        break                       # 结束循环
# 输出:
# k1
# k2
# k3
```


:::warning[注意]
同一个迭代器取完后就空了,再次遍历什么都取不到。想重新遍历需要**重新调用 `__iter__`** 生成新迭代器(像"再造一只新的老母鸡")。
:::


### 概念对照

| 名称 | 具备的方法 | 能否被 for | 能否被 next | 能否复用 |
|---|---|---|---|---|
| 可迭代对象 | `__iter__` | 能 | 不能 | 能(每次重新 `__iter__`) |
| 迭代器对象 | `__iter__` + `__next__` | 能 | 能 | 不能(取完即空) |
| 生成器 | `__iter__` + `__next__` | 能 | 能 | 不能(取完即空) |

## 8.9 for 循环的原理

### for 做的是 while 做的事

迭代器对象也有 `__iter__` 方法,且返回**自身**——这保证了 for 循环对可迭代对象和迭代器对象都能统一处理。

```python
s = {1, 2, 3}
print(hasattr(s, '__next__'))           # 输出: False:可迭代对象,不是迭代器

res = s.__iter__()
print(hasattr(res, '__next__'))         # 输出: True:迭代器
print(res.__iter__() is res)            # 输出: True:__iter__返回自身
```

**for 循环的工作原理**:

1. 调用 `in` 后面对象的 `__iter__` 方法,得到迭代器
2. 反复调用迭代器的 `__next__` 方法,拿到返回值赋给循环变量,执行循环体
3. 捕获 `StopIteration` 异常并结束循环

```python
d = {'k1': 1, 'k2': 2, 'k3': 3}
for key in d:
    print(key)
# 输出:
# k1
# k2
# k3
```

本质等价于:

```python
d_iterator = d.__iter__()
while True:
    try:
        key = d_iterator.__next__()
        print(key)
    except StopIteration:
        break
```

### for 与 while 的定位

**结论**:`for` 做的事就是上面这段 `while` 代码做的事。所以 `for` 循环称为**迭代循环**,`while` 循环称为**条件循环**。

`for` 能做的 `while` 都能做,但在循环取值这件事上 `for` 更简洁。


:::note[补充]
这解释了为什么对同一个列表 `for` 两次都能取到全部值(每次都重新 `__iter__` 出新迭代器),而对同一个迭代器 `for` 两次,第二次什么也取不到(`__iter__` 返回的还是那个已经取空的自己)。
:::


## 8.10 迭代器补充

### 文件对象与容器转换

**1. 迭代器一定是可迭代对象,反之不成立。** 可迭代对象只有 `__iter__`(列表、字典、集合都不是迭代器);迭代器同时有 `__iter__` 和 `__next__`。**文件对象是迭代器**:

```python
with open('test.txt', 'w', encoding='utf-8') as f:
    f.write('line1\nline2\n')

with open('test.txt', 'rt', encoding='utf-8') as f:
    print(hasattr(f, '__next__'))   # 输出: True:文件对象是迭代器
    print(list(f))                  # 输出: ['line1\n', 'line2\n']
```

**2. `list()`、`tuple()` 的原理与 for 一样。** 接收可迭代对象,内部调用 `__iter__` 和 `__next__` 把值收集起来。

```python
print(list('梦泪'))    # 输出: ['张', '大', '仙']
print(tuple('梦泪'))   # 输出: ('张', '大', '仙')
```

### range 与 dict 视图

**3. `dict.values()`、`range()` 是可迭代对象,不是迭代器。**

```python
v = {'k1': 1}.values()
print(hasattr(v, '__iter__'), hasattr(v, '__next__'))   # 输出: True False

r = range(10)
print(hasattr(r, '__iter__'), hasattr(r, '__next__'))   # 输出: True False
```


:::note[补充]
Python 3 把 `range()`、`dict.keys()/values()/items()` 都做成了可迭代对象(惰性),而在 Python 2 里它们返回的是列表。可以说列表是可迭代对象,但不能反过来说可迭代对象就是列表这种具体类型。
:::


### 便捷函数 iter 与 next

**4. 便捷函数 `iter()` 和 `next()`。** 与 `len(obj)` 本质调用 `obj.__len__()` 同理:

- `iter(对象)` 等价于 `对象.__iter__()`
- `next(对象)` 等价于 `对象.__next__()`

```python
l = [1, 2, 3]
it = iter(l)              # 等价于 l.__iter__()
print(next(it))           # 等价于 it.__next__()   输出: 1
print(next(it))           # 输出: 2
```


:::note[补充]
迭代器优点:①统一的不依赖索引的取值方式;②省内存(惰性计算)。缺点:①只能往后取,不能回退,也不能按位置取值;②一次性的,取完要重新生成;③不能用 `len()` 预知长度。
:::


## 8.11 生成器与 yield

### 为什么需要生成器

目前得到迭代器的方法只有"先创建数据容器再调 `__iter__`"。要一个能产生一亿个值的迭代器,难道先造一个一亿个值的列表?

想做"产生一亿个字符串的迭代器",`range` 也办不到(它只能产生整数)。

所以需要一种**不依赖容器、直接自定义迭代器**的方法,这就是**生成器**(generator)。

### yield 与生成器对象

用 `return` 不行:既不能一次返回多个值,也不能写多个 `return`(写完函数就结束了)。这时用新关键字 **`yield`**:用法类似 `return`,区别是**可以返回多次值**。

```python
def func():
    print('第一次执行')
    yield 1
    print('第二次执行')
    yield 2
    print('第三次执行')
    yield 3

res = func()        # 函数体一行都没执行!
print(res)          # 输出: <generator object func at 0x...>
print(hasattr(res, '__iter__'), hasattr(res, '__next__'))   # 输出: True True
```

调用生成器对象的 `__next__` 才触发函数体执行,遇到 `yield` 暂停并返回值:

```python
def func():
    print('第一次执行')
    yield 1
    print('第二次执行')
    yield 2
    print('第三次执行')
    yield 3

res = func()
print(next(res))   # 输出: 第一次执行 / 1
print(next(res))   # 输出: 第二次执行 / 2
print(next(res))   # 输出: 第三次执行 / 3
try:
    next(res)      # 打印"第三次执行"后没有yield了,抛出 StopIteration
except StopIteration:
    print('StopIteration')   # 输出: StopIteration
```


:::warning[注意]
不能说"函数里写了 `yield`,这个函数就是生成器"。准确说法是:函数体内有 `yield` 时,**调用这个函数不会执行函数体代码,而是返回一个生成器对象**,这个生成器对象才是自定义的迭代器。生成器就是迭代器,有 `__iter__` 和 `__next__`。
:::


### 自定义 range

```python
def my_range(start, stop, step=1):
    while start < stop:
        yield start      # 产出当前值,然后暂停
        start += step

for n in my_range(1, 10, 2):
    print(n, end=' ')    # 输出: 1 3 5 7 9
```

## 8.12 yield 表达式与 send

### yield 作为表达式

`yield` 可以作为**表达式**赋值给变量:`y = yield 值`。这样 `yield` 有两个功能:

1. 暂停并返回一个值(原有功能)
2. 接收通过 `send()` 传入的值

```python
def func(x):
    print(x, '开始执行')
    while True:
        y = yield None      # 暂停并返回None
        print(x, y)

g = func(1)                 # 得到生成器,函数体没执行
res = next(g)               # 打印"1 开始执行",停在yield,返回None
print(res)                  # 输出: None

next(g)                     # 从yield继续:y=None,打印"1 None"
next(g)                     # 再打印"1 None"
```

### send 方法

**`send()` 方法**:给 yield 传值并继续执行。`g.send(10)` 把 10 传给 `yield`,`yield` 赋给 `y`,然后继续运行到下一个 `yield` 暂停。相当于在 `next` 的基础上多了一个传值功能。

但对刚创建的生成器直接 `send(10)` 会报错:

```python
def func(x):
    print(x, '开始执行')
    while True:
        y = yield None
        print(x, y)

g = func(1)
try:
    g.send(10)              # 会报错
except TypeError as e:
    print(e)                # 输出: can't send non-None value to a just-started generator
```

意思是"不能给刚开始的生成器发送非 `None` 的值"——刚创建的生成器还停在函数开头,没遇到 `yield`,没人接收值。所以**第一次只能 `send(None)`**(等价于 `next(g)`),让函数运行到 `yield` 处停下:

```python
def func(x):
    print(x, '开始执行')
    while True:
        y = yield None
        print(x, y)

g = func(1)
res = g.send(None)   # 等价于next(g):打印"1 开始执行",停在yield,返回None
print(res)           # 输出: None

g.send(10)           # 10传给yield,赋给y,打印"1 10",回到yield暂停
g.send(20)           # 输出: 1 20
```

可以把 `y = yield None` 拆成两部分看:

- `y = yield`:在**本次执行开始时**起作用,接收 `send` 传进来的值
- `yield None`:在**本次执行结束时**起作用,把值返回出去(即 `send(...)` 的返回值)


:::note[补充]
`send` 一次只能传一个值,想传多个值就用列表或字典包起来。生成器可以控制多段程序自由切换执行,是**协程**(coroutine)的雏形,在并发编程中用于实现异步 IO(Python 的 `async/await` 就源于这一思想)。
:::


## 8.13 三元表达式

### 写法与用法

**三元表达式**(conditional expression):把简单的 `if...else` 写成一行。"三元"指三个元素:**条件**、条件成立时返回的值、条件不成立时返回的值。

```python
x = 6
y = 9
# 格式:条件成立时的值 if 条件 else 条件不成立时的值
res = x if x > y else y    # 条件成立返回x,否则返回y
print(res)   # 输出: 9
```

### 左右两边与条件

左右两边不一定非得是变量,想返回什么都可以,甚至可以是函数调用;中间的条件也可以随便写。

```python
print('ok' if 1 > 2 else 'no')     # 输出: no

def f1():
    return '条件成立'

def f2():
    return '条件不成立'

print(f1() if 10 > 3 else f2())    # 输出: 条件成立
```


:::warning[注意]
三元表达式只适合**简单的二选一**。多个分支(`if...elif...else`)硬写成嵌套三元表达式会非常难读,这时还是写普通的 `if` 语句。
:::


## 8.14 列表生成式

### 从普通循环到一行代码

**列表生成式**(list comprehension,也叫列表推导式):用一行代码从可迭代对象生成列表。

```python
l = ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜', '白象']

# 普通写法
new_l = []
for name in l:
    if name.endswith('老坛酸菜'):    # 以"老坛酸菜"结尾
        new_l.append(name)
print(new_l)   # 输出: ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜']

# 列表生成式
new_l = [name for name in l if name.endswith('老坛酸菜')]
print(new_l)   # 输出: ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜']
```

### 语法结构与结果表达式

`[结果表达式 for 变量 in 可迭代对象 if 条件]`

- 结果表达式可以是:变量、一个值、函数(方法)调用、三元表达式、另一个生成式
- `if` 条件**可省略**(不写默认条件成立,原列表所有值都加进来)

```python
l = ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜', '白象']

# 左边写方法调用:把"老坛酸菜"都换成"小鸡炖蘑菇"
print([name.replace('老坛酸菜', '小鸡炖蘑菇') for name in l])
# 输出: ['康师傅小鸡炖蘑菇', '统一小鸡炖蘑菇', '大今野小鸡炖蘑菇', '白象']

# 左边写三元表达式
print([name if name.endswith('老坛酸菜') else '其他' for name in l])
# 输出: ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜', '其他']

# 嵌套生成式:外层每循环一次,里面的生成式就生成一个列表加进外层
print([[i for i in range(10) if i > 6] for name in l])
# 输出: [[7, 8, 9], [7, 8, 9], [7, 8, 9], [7, 8, 9]]
```


:::note[补充]
两种 `if` 位置的区别:
- `[x for x in l if 条件]`:`if` 在后面是**筛选**,不满足的元素被丢掉
- `[a if 条件 else b for x in l]`:`if...else` 在前面是**三元表达式**,每个元素都保留,只是取值不同

列表生成式可以写多个 `for`(相当于循环嵌套),但超过两层可读性差,不建议。
:::


## 8.15 字典与集合生成式

### 字典生成式

**字典生成式**(dict comprehension):大括号 + `key: value` 格式。

```python
l = ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜', '白象']
res = {name: 5 for name in l}
print(res)
# 输出: {'康师傅老坛酸菜': 5, '统一老坛酸菜': 5, '大今野老坛酸菜': 5, '白象': 5}
```

配合**解压赋值**更简洁:

```python
l = [('康师傅老坛酸菜', 5), ('统一老坛酸菜', 6), ('大今野老坛酸菜', 7), ('白象', 8)]

# 写法一:索引取值(要取好几次,有点麻烦)
res = {item[0]: item[1] for item in l if not item[0].startswith('康师傅')}

# 写法二:解压赋值
res = {k: v for k, v in l if not k.startswith('康师傅')}
print(res)   # 输出: {'统一老坛酸菜': 6, '大今野老坛酸菜': 7, '白象': 8}
```

### 集合生成式与拆解妙招

**集合生成式**(set comprehension):大括号但只有值,没有冒号。

```python
l = ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜', '白象']
res = {name for name in l}
print(type(res))   # 输出: <class 'set'>
```


:::tip[技巧]
不管生成式看起来多复杂,**拆成三块看**就清晰了:中间是 `for` 循环,右边是条件判断,左边是要添加进去的值。
:::


## 8.16 生成器表达式

### 没有元组生成式

**没有"元组生成式"**:生成式的操作本质是往容器里添加值,而元组是不可变的,不能往里加值。小括号的生成式语法返回的是**生成器表达式**(generator expression),不是元组。

```python
l = ['康师傅老坛酸菜', '统一老坛酸菜', '大今野老坛酸菜', '白象']
res = (name for name in l)
print(res)                  # 输出: <generator object <genexpr> at 0x...>

print(next(res))            # 输出: 康师傅老坛酸菜
print(res.send(None))       # 输出: 统一老坛酸菜  send(None)相当于next
print(next(res))            # 输出: 大今野老坛酸菜
try:
    next(res)               # 已经没有值了
except StopIteration:
    print('StopIteration')  # 输出: StopIteration
```

**关键区别**:

- 列表生成式**一次性**把所有元素存进内存,可反复遍历、可按索引取值
- 生成器表达式同一时刻**只产生一个元素**,省内存,但只能往后取一次

要强调的是:**生成器造出来的时候本身没有任何值**。只有调用 `next` 时,才执行一次 `for` 循环得到一个值然后停住;下一次 `next` 才执行第二次循环得到第二个值。

不要看它写得像列表生成式,就以为里面已经放好了所有值。

### 应用:统计文件字符数

先准备测试文件:

```python
import os
os.makedirs('data', exist_ok=True)
with open('data/user.log', 'w', encoding='utf-8') as f:
    f.write('hello world\n')      # 12
    f.write('你好,Python\n')       # 10
    f.write('egon\n')             # 5
```

**方案一:逐行累加。** 不能用 `f.read()`(文件太大内存会被撑爆),要一行一行读,同一时刻内存里只有一行:

```python
with open('data/user.log', mode='rt', encoding='utf-8') as f:
    size = 0
    for line in f:
        size += len(line)
    print(size)   # 输出: 27
```

**方案二:`sum()` + 列表生成式(占内存)。**

```python
print(sum([1, 2, 3]))   # 输出: 6

with open('data/user.log', mode='rt', encoding='utf-8') as f:
    size = sum([len(line) for line in f])
    print(size)   # 输出: 27
```

**存在的问题**:

1. 列表生成式会把每一行的字符数都放进列表,文件有几百万行,列表里就有几百万个值,对内存不友好
2. 文件对象是**迭代器**,取完一遍就空了,再取值得到 0:

```python
with open('data/user.log', mode='rt', encoding='utf-8') as f:
    print([len(line) for line in f])   # 输出: [12, 10, 5]
    size = sum([len(line) for line in f])
    print(size)                        # 输出: 0:文件迭代器已被取空
```

**方案三(最优):`sum()` + 生成器表达式。** 生成器本身没有任何值,不管文件多少行都一样,只有 `next` 时才产生一个值;生成器是可迭代对象,可以作为 `sum()` 的参数。

```python
with open('data/user.log', mode='rt', encoding='utf-8') as f:
    size = sum((len(line) for line in f))
    print(size)   # 输出: 27
```

生成器表达式作为**函数唯一参数**时,外面那层括号可以省略:

```python
with open('data/user.log', mode='rt', encoding='utf-8') as f:
    size = sum(len(line) for line in f)   # 效率最高、最省内存
    print(size)   # 输出: 27
```


:::tip[技巧]
这里统计的是**字符数**(一个汉字、一个字母、一个换行符都算 1)。若要统计**字节数**,用 `rb` 模式打开,`len(line)` 得到每行的字节数(UTF-8 下一个汉字占 3 字节)。统计行数:`sum(1 for line in f)`。
:::


### 四种写法对照

| 写法 | 语法 | 生成什么 |
|---|---|---|
| 三元表达式 | `a if 条件 else b` | 一个值 |
| 列表生成式 | `[x for x in 可迭代对象 if 条件]` | 列表(一次性存好) |
| 字典生成式 | `{k: v for k, v in 可迭代对象}` | 字典 |
| 集合生成式 | `{x for x in 可迭代对象}` | 集合 |
| 生成器表达式 | `(x for x in 可迭代对象)` | 生成器(用时才产生值) |

## 本章小结

- **装饰器**:给其他函数添加额外功能;开放封闭原则——不改源代码(包括形参)、不改调用方式
- **推导路线**:方案1改源代码(违反原则)→方案2调用处加代码(冗余)→方案3封装(调用方式变了)→方案4 `*args, **kwargs` 写活参数→方案5闭包+偷梁换柱→方案7处理返回值
- **无参装饰器模板**:外层 `outer(func)` 包住 `wrapper(*args, **kwargs)`,调用前后加功能,`return res`(`return wrapper` 不加括号)
- **语法糖 `@outer`** 等价于 `func = outer(func)`,写在被装饰函数正上方、不加括号,装饰器要先定义、名字见名知意
- `@wraps(func)` 把原函数的属性复制给 `wrapper`,伪装更完美;属性复制写在 `wrapper` 定义之后、`return` 之前
- **有参装饰器**:再包一层 `g_outer(x)`,语法糖写成 `@g_outer(x)`,先调用得到 `outer` 再装饰;三层足够
- **装饰器叠加**:加载自下而上,执行自上而下进入、自下而上退出(像堆栈);叠加顺序会影响结果
- **迭代/迭代器**:可迭代对象有 `__iter__`;迭代器有 `__iter__` 和 `__next__`,取完抛 `StopIteration`,省内存
- **for 循环**原理:先 `__iter__` 得到迭代器,再反复 `__next__`,自动捕获 `StopIteration`;`list()`、`tuple()` 同理
- 文件对象是**迭代器**;`range()`、`dict.values()` 在 Python 3 里是**可迭代对象**;`iter()`/`next()` 是 `__iter__`/`__next__` 的便捷函数
- **生成器**:函数体有 `yield`,调用函数返回生成器(自定义迭代器);`yield` 暂停并返回值,可多次返回
- `yield` 表达式接收 `send()` 传入的值,第一次必须 `send(None)`;生成器可切换、可记录状态,是协程的雏形
- **三元表达式**:`值1 if 条件 else 值2`,适合简单二选一
- **生成式**:列表 `[结果 for x in 可迭代对象 if 条件]`;字典 `{k: v for ...}`;集合 `{x for ...}`;**没有元组生成式**
- **生成器表达式** `(结果 for x in ...)` 返回生成器,本身不存值,一次产生一个,省内存;`sum(len(line) for line in f)` 统计文件字符数
